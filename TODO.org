* DONE org table formatting
There's a bug in org table formatting, where, links dont get properly formatted. May be related to precedence when formatting org tables between link formatting and column formatting (w auto page wrapping).  Investigate and fix.
  - It was exactly the precedence you guessed: column formatting ran
    first. The over-wide-table wrap (`Editor::OrgTableWrapScan` ->
    `PlanOrgTableWrap`) measured, re-budgeted and wrapped each cell as
    its *raw markup*, so a cell holding `[[file:docs/lua-api.org][Lua
    API]]` was billed fifty columns for the seven it draws as. Two
    visible symptoms, both on this repo's own README: the Documentation
    table (155 raw columns, 78 rendered) was wrapped although it fits,
    and once wrapped its cells were hard-split mid-URL
    (`[[file:docs/architecture.org][Architectu` / `re]]`) and drawn as
    plain unstyled text, because a wrapped row's own decorations are
    skipped -- its stored columns aren't the drawn ones.
  - Link formatting now runs first. `OrgTableCellDisplayText` (org_doc.h)
    renders a cell the way the row itself is rendered -- each
    `[[target][desc]]` stood down to `desc` while concealment is on, a
    bare URL left alone either way -- and the planner lays the columns
    out around *that*, so the widths and the wrap points are the ones the
    reader sees. The README table stops wrapping entirely; one that
    genuinely is too wide now wraps on word boundaries in the
    description instead of through the middle of a URL.
  - The links survive the wrap rather than being flattened into it: the
    plan carries each one through as an `OrgTableWrapLink` in the
    rendered line's own columns (one span per line a description spans,
    with the word-break pieces merged back), so DrawPane paints the same
    Blue underline every other org link gets and registers a click
    region for it. Clicking a link inside a wrapped table follows it now
    -- by target, via `Editor::OrgFollowLinkTargetOn`, since there is no
    stored column to hand `OrgFollowLinkAt`. `<leader>otm` re-plans the
    table on the spot, because concealment is what decides a link cell's
    width.
  - The other half, once the wrapped case was right: a link table that
    *fits* still drew badly. The file pads such a table to its markup's
    width and the renderer holds every `|` at the column the raw text
    puts it (the cell-local conceal collapse), so the README's own
    Documentation table rendered as a 24-column description followed by
    31 columns of dead gutter before the pipe. `OrgTableWrapScan` now
    draws a table from its layout whenever that layout is genuinely
    narrower than the stored rows, not only when the table overflows
    `:set textwidth` -- so the columns close up to what they draw as.
    A table already as tight as its layout, and an unaligned one whose
    layout comes out *wider*, are both left alone, so nothing about a
    link-free table changes.
  - Concealed links draw with the Blue face and no underline, which is
    what `OrgLinkScan`'s concealing overlay does; raw markup and bare
    URLs keep the underline. The layout carries the distinction as
    `OrgTableWrapLink::concealed` so the two renderers can't drift.
  - `:MepOrgTableAlign` is deliberately untouched: it pads the *file*,
    which the raw-column renderer needs, so raw widths stay the right
    thing to write -- the tightening is display-only, and `<leader>otw`
    turns it off along with the rest of the layout. The row the cursor
    is on still steps aside to its stored columns (the caret has to land
    on the character it is editing), so that one row shows its markup
    and its own wider pipes -- the same trade-off over-wide tables
    already made. Covered by new
    `PlanOrgTableWrap`/`OrgTableCellDisplayText` cases in
    org_doc_test.cpp, including the link-free table that must not move.

    formatter. It includes `<string>`, `<vector>`, `<algorithm>` and
    `<cctype>` and nothing else, spawns nothing, links no LLVM and needs no
    `.clang-format`, so `gf` on a C++ buffer works in a fresh checkout with

    `mep.format_languages.cpp = {builtin = 'format_cpp', name = ..., width = 100}`
    (kBuiltinFormat, src/main.cpp), the same `spec.builtin` dispatch the
    Python and R formatters use; `.cc/.cxx/.h/.hpp/.hh/.hxx/.ipp/.inl/.cu/.cuh`
    alias onto it, and `#+begin_src cpp` org blocks get it for free.
    `mep.format_cpp(text[, width])` is the Lua binding. `c` itself is still on
    clang-format -- the C formatter entry above is its own task, and this
    engine handles C already, so that one is mostly a wiring decision.
  - Style target is clang-format in the dialect mep's own source is written
    in: 4-space indents, `Type *name`, `if (x)` spaced and `foo(x)` not,
    namespace bodies unindented, access specifiers flush with the class,
    `case` labels a level inside the switch, continuations aligned under the
    open bracket and bin-packed, runs of trailing `//` comments lined up in
    one column with two spaces in front of them, a braced initializer with a
    trailing comma left exploded, 100 columns. Calibrated against
    clang-format run with the matching style: **89% of output lines over
    mep's own 217 C++ sources are byte-identical** to it, 82% over 300 real
    files from the nix store, and the remainder are the deliberate
    differences cpp_format.h lists.
  - It reformats the *token stream* rather than parsing to a tree: lex, group
    into unwrapped lines at `;`/`{`/`}`/labels, re-render each under a
    spacing table, split the too-long ones greedily at their member-init
    colon, assignment, lowest-precedence top-level operator or brackets.
    cpp_format.h lists the known gaps (no macro-body formatting, no comment
    reflow, no `#include` sorting, no `}  // namespace foo` fixups, greedy
    rather than optimal breaking, and short forms preserved rather than
    imposed -- `if (c) return;` stays on one line if that is how it was
    written, and nothing is ever *joined* that the input had apart).
  - Safety is exact here in a way it could not be for Python: the formatter
    only moves whitespace, so the output is re-lexed and compared to the
    input token for token with *no* tolerance beyond trailing whitespace
    inside comments. That makes every C++ ambiguity a token stream cannot
    settle -- `<` template vs less-than, `*` pointer vs multiply, `{` block
    vs braced-init -- cosmetic by construction: a wrong guess moves a space
    and the check proves it moved nothing else. The one place whitespace is
    genuinely semantic, `#define X(a)` vs `#define X (a)`, is carried over
    from the source rather than re-derived, because no re-lexing can see it.
  - Covered by `mep-cpp-format-test` (src/cpp_format_test.cpp, in
    `just test`): the spacing table, templates/operators/braces, indentation,
    braceless bodies, the splitter, the preprocessor, comments, blank lines,
    lexer corners, refusals, the 20k-nested-paren guard, a token-shape
    property test over 40 awkward snippets at three widths, and idempotency
    asserted on every expectation. Beyond that it was run over **25k real C++
    files** from the nix store (plus every one of mep's own), checking three
    things per file: clang's own raw lexer (`clang -cc1 -dump-raw-tokens`)
    agrees the token streams of input and output are identical, formatting
    twice is a fixed point, and anything it cannot prove is a refusal rather
    than a rewrite. The only refusals left in that corpus are two bison `.cc`
    m4 skeletons, which are not C++.

like it to run without previously exisiting linters (i.e. entirely inhouse).
  - Done: `src/python_format.{h,cpp}`, a dependency-free black-shaped
    formatter. It includes `<string>`/`<vector>` and nothing else, spawns
    nothing, and needs no `black`/`ruff`/Python on PATH -- `gf` in a .py
    buffer now works in a fresh checkout. Wired as
    `mep.format_languages.py = {builtin = 'format_python', name = ..., width = 88}`
    (kBuiltinFormat, src/main.cpp), the same `spec.builtin` dispatch the R
    formatter uses, so `#+begin_src python` org blocks get it for free.
    `mep.format_python(text[, width])` is the Lua binding.
  - It reformats the *token stream* rather than parsing to a tree the way
    black does: tokenize, group into logical lines, re-render under a
    spacing table, split the too-long ones at their brackets. That covers
    4-space indents, double quotes, 88 columns, kwarg/annotation/slice/`**`
    spacing, `;` and one-line-suite splitting, blank-line rules, the magic
    trailing comma and black's two-stage bracket split. python_format.h
    lists what it deliberately does not do -- no invented parentheses, no
    `match` statement handling (soft keywords need a real parser), comments
    normalized but not relocated.
  - Safety is the design point, since `gf` overwrites a live buffer: every
    result is re-tokenized and compared against the input before it is
    returned (`VerifyEquivalent`), tolerating only the changes the formatter
    is entitled to make -- and only *inert* added trailing commas, so a
    comma that would turn `(a + b)` into a tuple or `case (A | B):` into a
    sequence pattern is caught rather than waved through. Any mismatch, or
    any syntax error, refuses with a message and leaves the buffer alone.
  - Verified against a real corpus: 51k .py files
    from the nix store, each checked for ast.parse equality (with the `u`
    prefix normalized, since dropping it is intended) and byte-identical
    idempotency, plus `mep-python-format-test`. Bugs it found and that are
    fixed: `;` splitting across a one-line suite header (moved a statement
    out of its `if`), comments stranded between implicitly concatenated
    strings (swallowed the rest of the line, and were emitted twice), the
    soft-keyword `case (...)` pattern bug above, PEP 701 nested f-strings,
    t-strings, and raw-string `\'`. Per the recipe's in-process rule there
    is a `kMaxNest` cap: 20k nested parens segfaulted the editor before it.

* DONE r formatter

I'd like an inhouse version of a formatter for R. Can you implement one? I'd
like it to run without previously exisiting linters (i.e. entirely inhouse).
  - Landed as src/r_format.{h,cpp}: a complete R formatter of mep's own --
    lexer, recursive-descent parser over R's real precedence table
    (?Syntax), and a width-driven printer -- with no dependency on `air`,
    `styler` or an R installation. `gf` on an R buffer now runs it
    in-process: mep.format_languages.R is `{builtin = 'format_r', width =
    80}`, a third entry shape alongside the existing filter/`mode = 'file'`
    ones, dispatched at the top of mep_format_run (kBuiltinFormat,
    main.cpp) and exposed to Lua as mep.format_r(text[, width]). Org
    `#+begin_src R` blocks get it through the same table.
  - The style is tidyverse/air's: two-space indent, spaces around binary
    operators except the tight ones (^ : :: ::: $ @), statement `=` to
    `<-`, single- to double-quoted strings, `#comment` to `# comment`
    (roxygen `#'` and shebangs untouched), and an 80-column margin that
    argument lists, operator chains and pipelines break to respect -- with
    the "hug" rule that keeps a trailing block on the call's own line
    (`test_that("x", {`). On the samples checked against real `air`, the
    only layout difference is a mixed `&&`/`||` condition, which air breaks
    at every operator and this breaks only where it has to.
  - Deliberately *not* done: it never adds braces to a brace-less if/for
    body (air does) and never rewrites `%>%` to `|>`. Both change the code
    rather than its layout.
  - Comments survive wherever they were written -- above a statement,
    trailing it, after the operator they follow (`x <- a + # why`), or
    alone before a closing delimiter -- as do single blank lines between
    statements (runs of them collapse to one).
  - Two safety properties, because this rewrites the buffer in place and
    runs inside the editor: Format() re-tokenizes its own output and
    compares it token-for-token against the input (Signature), returning
    the input untouched if anything but its own intended rewrites moved;
    and nesting deeper than kMaxNest is refused rather than recursed into,
    so a pathological file is an error message instead of a stack
    overflow. A file that does not parse comes back byte-identical with
    the failing line reported.
  - Covered by mep-r-format-test (src/r_format_test.cpp, in `just test`),
    every case asserted for both output and idempotency. Beyond that, the
    formatter was run over 153 real R files (base R's own demos/scripts
    plus package sources) and each result fed to R itself: `parse()` of the
    input and of the output are `identical` for all 153, and formatting
    twice is a no-op for all 153.

* DONE python lsp engine
I'd like an inhouse LSP engine for python. Can you implement one? I'd like it to run without previously exisiting linters (i.e. entirely inhouse)
  - `mep-python-lsp` (src/python_lsp_server.cpp), built and installed
    beside `mep` and registered as `mep.lsp_servers.python_ls` for `py`
    and `pyi`. Same three-file shape as the org server: a JSON-RPC wire
    half, a pure analysis half (src/python_lsp.cpp) and a windowless
    CHECK() suite (src/python_lsp_test.cpp, `mep-python-lsp-test`, in
    `just test`). Nothing external: no pyright, no pyflakes, no `pip`,
    no node -- and no Python interpreter either, at build time or at run
    time.
  - Unlike org_lsp.cpp, which deliberately stays a line scanner, this one
    has a real front end (src/python_ast.h/.cpp): a Python 3.12+
    tokenizer -- significant indentation, implicit and explicit line
    joining, every string prefix, PEP 701 nested f-strings, PEP 750
    `t""` -- and a recursive-descent parser over it. It has to: "this
    name is never defined", "this import is unused", "this local is never
    read" are questions about *scopes*, and a scope is exactly what a
    line-oriented scan cannot see. f-string `{...}` fields are parsed as
    real expressions and positioned back inside the literal, so a typo in
    one is found like any other.
  - Verified against a corpus rather than by inspection: 3,399 real
    files (CPython 3.13's stdlib plus numpy/pandas/matplotlib/fontTools
    out of the nix store, every one of which CPython itself compiles) --
    zero false syntax errors, and 367 of 367 mutants (one `:` deleted
    per file, each confirmed a SyntaxError by CPython) caught. Five
    genuine parser gaps turned up that way and are fixed: nested
    same-quote f-strings, `t""` template strings, `case x if guard:`,
    PEP 617 parenthesized `with (a as b,):` item lists, and PEP 758
    `except A, B:` (which is spelled exactly like Python 2's
    `except E, err:`, so the two are told apart by whether the last item
    reads as a capture name).
  - Diagnostics: syntax (with Python 2 constructs named as such rather
    than reported as "invalid syntax"), scope (undefined name, unused
    import, unused local, redefinition), the statements Python itself
    would refuse (`return`/`yield`/`break`/`await`/`nonlocal` out of
    place, duplicate parameter), and the mistakes that compile and still
    bite (mutable default argument, `is` against a literal,
    `assert (cond, msg)`, bare `except:`, duplicate dict key, `return`
    inside `finally`, `raise NotImplemented`, `__init__` returning a
    value, a method with no `self`, dead code after `return`). There is
    no type checking and there will not be one here: a single file cannot
    see the modules it imports.
  - The false-positive work was the bulk of it, and each suppression is
    tested as deliberately as the findings: the same corpus run took
    undefined-name from 596 reports to 60 (the survivors are mostly
    ssl.py/calendar.py's own runtime namespace injection, which pyflakes
    reports too) and unused-variable from 49,383 to 313. The five that
    mattered: a read marks *every* binding of that name in the scope it
    resolved to (not just the last, or `if/else: colno = ...` reports the
    first branch); a comprehension's outermost iterable is evaluated in
    the enclosing scope (which is the only way one in a class body can
    see a class variable); a string annotation counts as a *use* but
    never as a claim that the name exists (`Literal["w"]` must not invent
    one); a file with a syntax error gets no scope diagnostics at all,
    since mid-edit is when invented errors are least welcome; and
    `with pytest.raises(...): a + b` is a test, not a dead expression.
  - Everything the server knows about the standard library is a table
    compiled into it (src/python_lsp_vocab.cpp, 4,417 entries: builtins,
    exceptions, dunders, the members of ~80 modules and of every builtin
    type, each with its signature and a one-line doc). Generated once by
    introspecting CPython 3.13 and committed, which is what lets Python
    support work on a machine with no Python on it.
  - Features beyond diagnostics: context-aware completion (scope names,
    `os.`, `self.` including inherited members, `text.` for a local
    assigned a literal, `import`, `from x import`, `raise`, `def` in a
    class body, `@`; nothing at all inside a comment or a string, but an
    f-string field is code), hover, signature help (with `self` dropped
    for a method called through an instance, and live while typing a
    string argument), document symbols, folding (suites, comment runs,
    the import block, multi-line strings), definition (including
    `self.field` and an import of a sibling module, resolved to the
    *definition* line in that file), references, document highlight and
    rename -- the last two scoped to the binding under the cursor, so a
    local `value` and a module-level `value` stay separate.
  - Two things outside the server itself: the tokenizer re-runs in a
    recovery mode when a file ends with a bracket still open, so one
    unfinished `f(` while typing no longer swallows every symbol, fold
    and diagnostic below it into one logical line; and the LSP client now
    passes a registry entry's `init_options` as `initializationOptions`
    (mep.lsp_servers.python_ls.init_options = {maxLineLength = 100}
    turns on the one style check, which is off by default).
  - pyright keeps its registry entry but no longer claims `py`; handing
    it back is one line in init.lua, documented on the new
    help/python-lsp.org page.

    and roxygen2 =@param= that names an argument the function does not
    have.

    it refuses to say, so: a =library()= of anything outside base R (or
