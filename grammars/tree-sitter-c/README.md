# tree-sitter-c

A [tree-sitter](https://tree-sitter.github.io/) grammar for **C**, written
for mep and compiled into it. It follows the C23 grammar (ISO/IEC
9899:2024 Annex A, draft N3096) plus the GNU extensions real code uses
(statement expressions, `asm`, `__attribute__`, `__extension__`, `?:`,
designator and case ranges) and the Microsoft ones (`__declspec`, calling
conventions, pointer modifiers, `__try`/`__except`).

Its node names, fields and tree shapes are the ones
[tree-sitter/tree-sitter-c](https://github.com/tree-sitter/tree-sitter-c)
0.24 established -- the grammar mep vendored before this one -- so queries
and tools written for that grammar work unchanged: the same 125 node types
and 39 fields.

## How it compares

C has no oracle (a file's validity depends on its include path), so the
comparison with the old grammar is `just grammar-diff c --old-clean`, on
SQLite, Lua's C sources, CPython's `Objects/`, `Python/`, `Modules/` and
`Include/`, and the C in this repository (874 files, 2.4M lines):

* 49,606 top-level items (functions, declarations, directives) parse
  without errors in the old grammar; every one that parses without errors
  in this one too is the identical subtree, except in 3 files listed in
  `test/known-differences.txt`, where the old grammar was wrong (below).
* Both grammars fail on the same files (this one on 3 fewer), and inside
  their error regions the two recover differently -- code neither can
  parse, mostly statement macros with no `;` (`Py_BEGIN_ALLOW_THREADS`)
  and `#if`s splitting an expression. Overall this grammar leaves 2.7%
  fewer bytes inside ERROR nodes (better in 57 files, worse in 9).

**One deliberate difference: preprocessor-split `else` chains.**

```c
if (a) { ... }
#ifdef X
else if (b) { ... }
#endif
else { ... }
```

No C grammar can parse this as written -- an `else` cannot start a
statement -- and it is common. The old grammar either failed, or (in 3
corpus files, without an error) read `else if (b) {...}` as a function
named `if` with return type `else`. Here an `else_clause` may stand on its
own as a block item, so each arm is an `else_clause` holding its
`if_statement`; right after an `if`, an `else` still belongs to it, so
ordinary C parses exactly as before.

Known shared limitation: SQLite's amalgamation (`sqlite3.c`) opens one
`#ifndef` near its top that closes near its end, and something inside it
neither grammar parses takes the whole 9 MB file to a single ERROR root.

| File | What it is |
|---|---|
| `grammar.js` | the grammar; operator precedence follows C's |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `just c-grammar` (mep-ts-generate) -- commit them, don't edit them |
| `queries/highlights.scm` | highlight captures (nvim-treesitter naming) |
| `queries/folds.scm` | fold ranges |
| `queries/structure.scm` | the structure sidebar's outline: structs, unions, enums, typedefs of them, functions |
| `test/corpus/*.txt` | corpus cases, run by `mep-ts-corpus-test` |
| `test/known-differences.txt` | the reviewed differences from the old grammar, for `just grammar-diff` |

No external scanner: everything C needs is in the grammar. What makes it
large is that C cannot be parsed without knowing which names are types:
`a * b;` is a declaration or a multiplication. Those readings are left to
the GLR parser (`conflicts`) and settled by dynamic precedence --
declarations win, as they do in real code; a bare `NAME;` is an expression
(a macro call); and where `f(b) {}` could be K&R or modern, modern wins.
The preprocessor is parsed where it appears, so each `#if` form exists once
per context (top level and blocks, struct fields, enumerators) and is
aliased back to one set of node names.

## Working on it

```sh
just c-grammar                    # regenerate src/parser.c and run the corpus tests
just grammar-corpus c             # once
just grammar-diff c --old-clean   # must report 0 items parsed cleanly by both but differently
just grammar-fuzz c
```

The C++ grammar (`../tree-sitter-cpp`) is built on this one, so a change
here changes it too: regenerate it as well (`just cpp-grammar`) and run
`just grammar-diff cpp --old-clean`.

Then rebuild mep, which compiles `src/` directly (`ts_c` in CMakeLists.txt)
and embeds the queries into a generated header at configure time.
`mep-treesitter-test` checks highlights, folds, the outline and
incremental reparsing.
