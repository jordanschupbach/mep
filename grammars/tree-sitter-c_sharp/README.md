# tree-sitter-c_sharp

A [tree-sitter](https://tree-sitter.github.io/) grammar for **C#** (through
C# 13), written for mep and compiled into it, so `.cs` files are
highlighted, folded and outlined without a grammar `.so` on the machine. It
follows the C# language specification (ECMA-334 and the C# 8+ drafts at
dotnet/csharpstandard, plus the feature specifications since: records,
patterns, raw strings, collection expressions, function pointers) and
Roslyn's hand-written parser and lexer (`LanguageParser.cs`, `Lexer.cs`)
where the specification leaves a choice to prose.

Its node names, fields, supertypes and tree shapes are the ones
[tree-sitter/tree-sitter-c-sharp](https://github.com/tree-sitter/tree-sitter-c-sharp)
0.23.5 established -- the grammar mep loaded dynamically before this one
(MIT, (c) Max Brunsfeld, Damien Guard, Amaan Qureshi and contributors) --
so queries and tools written for that grammar work unchanged: the same
node types and fields, the same supertypes (`declaration`, `expression`,
`statement`, `type`, `pattern`, ...), and the same rule order (where two
readings survive to the same point, tree-sitter keeps the lower-numbered
one, so order matters: rules this grammar adds come after all of the old
ones).

| File | What it is |
|---|---|
| `grammar.js` | the grammar |
| `src/scanner.c` | the external scanner: interpolated and raw strings |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `just c_sharp-grammar` (mep-ts-generate) -- commit them, don't edit them |
| `queries/highlights.scm` | highlight captures (nvim-treesitter naming) |
| `queries/folds.scm` | fold ranges: namespaces, types, members, blocks, initializers, `#if`, comments, multi-line strings |
| `queries/structure.scm` | the structure sidebar's outline: namespaces, classes, records, structs, interfaces, enums (and their members), delegates, methods, constructors, operators, local functions, properties, indexers, events, fields |
| `test/corpus/*.txt` | corpus cases, run by `mep-ts-corpus-test` |
| `test/known-differences.txt` | the reviewed corpus files whose trees differ from the old grammar's |

## Why there is a scanner

C#'s tokens are context-free except for strings whose end depends on how
they began: a raw string (`"""..."""`) closes with as many quotes as opened
it, and an interpolated string (`$"..{x}.."`, `$@"..."`, `$$"""..{{x}}.."""`)
opens an interpolation with as many braces as it has `$`s, nests (an
interpolation may hold another interpolated string), and escapes braces and
quotes differently in each kind. `src/scanner.c` keeps a stack of the open
interpolated strings. The preprocessor needs no scanner: `#if` blocks are
parsed where they usually appear (between members, statements, enum
members, attribute lists, inside an expression) and the other directives
are extras, allowed on any line.

## How it compares

`just grammar-corpus c_sharp` collects 17,828 files: Roslyn's compilers and
analyzers with their tests (every corner of the syntax), jellyfin, osu!,
OpenRA, Pinta, ILSpy, BTCPay Server, Wasabi Wallet, ArchiSteamFarm,
OmniSharp and the other C# applications nixpkgs packages. Against
tree-sitter-c-sharp 0.23.5 (`just grammar-diff c_sharp --old <its src>`):

* 17,752 files parse to identical trees; the other 76 differ where the old
  grammar was wrong, each reviewed and listed in `test/known-differences.txt`
  (`--old-clean`: no top-level item the old grammar parsed without an error
  reads differently except those). Without the corrections below, all
  17,828 were identical: the old grammar's productions are kept as they
  were.
* Files with parse errors: 156 -> 106, none new; bytes inside ERROR nodes
  -18.6%, worse in no file.
* Error recovery on 3,000 damaged copies: the same (-0.0% bytes in ERROR
  nodes; better in 14 files, worse in 5).
* The parser is clean under ASan + UBSan on the corpus and the damaged
  copies (`just grammar-fuzz c_sharp`).

The oracle (`--oracle`) is Roslyn's own parser, the copy the .NET SDK ships
(`tools/csharp_oracle`, `just csharp-oracle`). It accepts 17,821 of the
17,828 files; since every difference above is a file Roslyn accepts, the
gate is `--old-clean` plus the known differences.

## Where it differs

Corrections over tree-sitter-c-sharp 0.23.5, each a Roslyn-accepted
construct the old grammar misread:

* Interpolated strings (the scanner): `{{{x}}}` -- an escaped brace, then an
  interpolation -- was read as plain text; a verbatim string ending in an
  escaped quote (`$@"...""{x}"""`) ran on past its end; `$""` was an error;
  an escape sequence in a format (`{d:HH \"h\"}`) was an error.
* List patterns: a leading slice (`[.., last]`, `[..]`) was read as a
  collection expression of a range; a slice with a pattern (`.. var rest`)
  was an error.
* Pointer indirection took only a name: `*(p + i) = x`, `*(int*)p` and
  `*p++ = x` were errors, and `*p++` read as `(*p)++`.
* Contextual words as names: an attribute target in a collection
  expression (`[type]`, `[property]`) and `with` (`var with = ...`).
* `delegate*<ref readonly T, R>` and `unsafe ~C()`.

## Known limits

* `#if` blocks whose branches split a construct (half a statement, an
  argument list's items, a member's header with two bodies) are errors:
  the grammar parses every branch, where the compiler sees one. Most of the
  101 corpus files Roslyn accepts that still have errors are these. A
  highlighter should not stop at them; mep's C# language server reports the
  real syntax errors.
* `async` and `await` as names (`if (async)`, `await.X`), and an assignment
  to a call returning by reference (`F() = x`): telling these apart needs
  the context Roslyn has (an async method, a ref return). The latter was
  tried and dropped: its extra parse states tipped an unrelated GLR tie
  (`await a.F<B<C>>(x).G()` read as comparisons).
* `(a) - b` and `(a) * b` read as casts, as in the old grammar; Roslyn reads
  them as arithmetic (a cast needs a type, which a parser cannot tell from
  a name).
