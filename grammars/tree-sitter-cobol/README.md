# tree-sitter-cobol

A [tree-sitter](https://tree-sitter.github.io/) grammar for **COBOL**, fixed
and free reference format, compiled into mep, so `.cob` `.cbl` `.cobol` `.cpy`
files (either case) are highlighted, folded and outlined without a grammar
`.so` on the machine. It replaced the hand-written highlighter mep had in
`src/cobol_syntax.cpp` (which now only carries the line structure the COBOL
language server and formatter share).

It started from [yutaro-sakamoto/tree-sitter-cobol](https://github.com/yutaro-sakamoto/tree-sitter-cobol)
(0.1.1-14, commit 550020d) by Yutaro Sakamoto, released under the MIT licence
(kept here as `LICENSE`); its `grammar.js`, scanner and test corpus are the
base here, with thanks. What changed:

* **Reference format.** The external scanner tells fixed from free format the
  way GnuCOBOL and mep-cobol-lsp do: `>>SOURCE [FORMAT] [IS] FREE|FIXED` and
  `$SET SOURCEFORMAT` switch it, and without a directive a line is fixed unless
  code sits where the sequence area would be (six characters of anything
  followed by an indicator are still a sequence area, as in NIST's
  alphabetic sequence fields). Fixed format gets `sequence_area` (columns
  1-6), `indicator` (`-`, `D`), `*` / `/` comment lines and
  `identification_area` (column 73 on) as extras; free format reads the whole
  line as code. Upstream read only fixed format, and every free-format file
  was one big error.
* **Comments and directives** are external tokens: `*>` anywhere (up to column
  72 in fixed format), `>>...` and `$SET`/`$IF`... directive lines
  (`compiler_directive`).
* **COPY and REPLACE** are extras (`copy_statement`, `replace_statement`, with
  `REPLACING` pairs and `==pseudo-text==`), so they parse wherever they stand.
* **Copybooks** parse: `start` also takes a bare list of data entries.
* Smaller fixes: `_` in words, exponents in numbers, `LINE SEQUENTIAL`,
  optional LOCAL-STORAGE/LINKAGE bodies, numeric paragraph names, a guard so
  a comment entry (`AUTHOR.` ...) cannot swallow lines during error recovery,
  and every keyword token aliased to one `keyword` node.

| File | What it is |
|---|---|
| `grammar.js` | the grammar |
| `src/scanner.c` | the external scanner: reference format, sequence/indicator/identification areas, comments, comment entries, directives, continued literals |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `just cobol-grammar` (mep-ts-generate) -- commit them, don't edit them |
| `queries/highlights.scm` | highlight captures (nvim-treesitter naming) |
| `queries/folds.scm` | fold ranges: programs, divisions, sections, SELECT entries, file descriptions |
| `queries/structure.scm` | the structure sidebar's outline: programs, sections, paragraphs, 01/77 entries, file descriptions |
| `test/corpus/*.txt` | corpus cases, run by `mep-ts-corpus-test`: upstream's (expectations regenerated for the changes above) plus `reference_format.txt` |

## How it is checked

* `mep-ts-corpus-test` runs the corpus (91 cases, all passing).
* `mep-treesitter-test`'s TestCobol checks captures, folds and the outline on
  fixed, free and directive-switched programs.
* The datamunge COBOL examples and copybooks parse with no ERROR node; of
  NIST's COBOL85 suite (382 programs), 7 files still have an ERROR node
  (upstream: 11).

## Limitations

* The tree is flat below paragraphs: statements are not nested into IF /
  EVALUATE / PERFORM nodes, so folds stop at divisions and sections.
* EXEC SQL / EXEC CICS blocks are not parsed; REPORT and SCREEN sections are
  placeholders.
* The scanner decides free format line by line (latching it once seen);
  mep-cobol-lsp decides for the whole file. They agree on real files.
* A tab counts as one column.
