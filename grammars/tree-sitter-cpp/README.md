# tree-sitter-cpp

A [tree-sitter](https://tree-sitter.github.io/) grammar for **C++**,
written for mep and compiled into it. It follows the C++23 grammar
(ISO/IEC 14882:2024, draft N4950, Annex A) and is built on mep's C grammar
(`../tree-sitter-c`): `grammar.js` requires C's and extends it the way C++
extends C, so the declarators, statements and expressions the two share
are C's rules, and C++'s own (classes, templates, namespaces, references,
lambdas, concepts, coroutines, ...) are added or override them.

Its node names, fields and tree shapes are the ones
[tree-sitter/tree-sitter-cpp](https://github.com/tree-sitter/tree-sitter-cpp)
0.23 established -- the grammar mep vendored before this one -- so queries
and tools written for that grammar work unchanged: the same 206 node types
and 50 fields, and the same rules in the same order (which is
load-bearing; see below).

## How it compares

C++ has no oracle (a file's validity depends on its include path and on
which names are types and templates), so the comparison with the old
grammar is `just grammar-diff cpp --old-clean`, on fmt, abseil,
nlohmann_json and the C++ in this repository (1,622 files, 1.48M lines):

* 38,871 top-level items parse without errors in the old grammar; every
  one that parses without errors in this one too is the identical subtree.
  1,587 files are identical throughout.
* Both grammars fail on the same 817 files -- macro-heavy code mostly
  (`ABSL_*` and gtest's macros, `#define` bodies a comment cuts short) --
  and recover differently inside those errors: overall this grammar leaves
  0.4% fewer bytes inside ERROR nodes there.

**Where this grammar parses what the old one could not** (the trees differ
only where the old grammar had an error):

* `p->*pm`: the old grammar had `.*` but no `->*` ([expr.mptr.oper]).
* `p->Base::~Base()`: a qualified destructor name as a member.
* `template class vector<int>;`: an explicit class instantiation has no
  declarator ([temp.explicit]); the old grammar reported one missing.

**Number literals** follow [lex.icon] and [lex.fcon], not C's looser
rule: an integer takes `u` with `l`/`ll`/`z` in either order, a floating
literal `f`, `l`, `f16`..`f128` or `bf16`, and anything else is a
`literal_suffix` of a `user_defined_literal` (`1f`, `1.5d`, `12_km`). A
leading `0` means octal, and a hexadecimal floating literal needs its `p`
exponent. These match the old grammar's tokens exactly.

**Error recovery** (`just grammar-recovery cpp`): on 3,000 damaged copies of the
corpus, 0.4% fewer bytes end up inside ERROR nodes than with the old
grammar overall, though it is worse in more files (87) than better (45):
mostly small differences, and two large ones where damage inside a
50-deep parenthesized expression in generated code (a `#` starting a
directive mid-line) leaves this grammar's error open to the end of the
file and the old one's not. Recovery has not been tuned beyond matching
the old grammar.

The raw-string scanner is clean under ASan + UBSan on the corpus plus
3,000 damaged copies (`just grammar-fuzz cpp`).

## Files

| File | What it is |
|---|---|
| `grammar.js` | the grammar, extending `../tree-sitter-c/grammar.js` |
| `src/scanner.c` | the external scanner: raw string delimiters and content |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `just cpp-grammar` (mep-ts-generate) -- commit them, don't edit them |
| `queries/highlights.scm` | highlight captures (nvim-treesitter naming): C's, plus C++'s |
| `queries/folds.scm` | fold ranges |
| `queries/structure.scm` | the structure sidebar's outline: namespaces, classes, structs, unions, enums, aliases, concepts, functions and methods (in or out of their class), constructors and operators |
| `test/corpus/*.txt` | corpus cases, run by `mep-ts-corpus-test` |

C++ cannot be parsed without knowing which names are types and which are
templates: `a < b > c;`, `T(x);` and `f(g<h>(i))` each have two readings.
They are left to the GLR parser (`conflicts`) and settled by dynamic
precedence: a declaration wins over an expression, a type over an
expression inside `<...>`, and a plain field over a template call when
`a.b < c` could be either.

Rules are declared in the old grammar's order. When two readings survive
to the same point, tree-sitter keeps the one whose node types are
numbered lower, and node types are numbered in declaration order. So
`grammar.js` reorders C's rules (`BASE_ORDER`) and drops the ones C++ has
no use for (K&R definitions, macro type specifiers: `DROPPED`) before
extending them.

The scanner reads raw strings: the delimiter between `R"` and `(` (up to
16 characters), the content up to `)delimiter"`, and the closing
delimiter. The open string's delimiter is its state, saved with every
token so an incremental reparse resumes inside a raw string exactly.

### Size

`src/parser.c` is 16.2 MB (the old grammar's was 17.3 MB): about 2 s to
compile at `-O2`, a 3.3 MB object. Most of it (10 MB) is the dense table
tree-sitter writes for "large" states, those with more than 64 actions.
In C++ that is most states that just finished an expression: C++ has
many more tokens that may follow one than C (`<=>`, `.*`, `->*`, `...`,
`and`/`or`/`bitand`/... and `and_eq`/...), and every context an expression
can end in whose lookaheads clash with another's (a template's `>`, a
fold's `...`, the preprocessor's `#else` in an enumerator list) is its
own state: about 530 such contexts here, against C's 160. Measured one at
a time, no single construct costs more than a few percent; `->*` as a
real operator saved 5%. The plan's original budget (well under half the old size)
was relaxed for that reason: a grammar change should not make `parser.c`
larger, and is worth measuring against it.

## Working on it

```sh
just cpp-grammar                    # regenerate src/parser.c and run the corpus tests
just grammar-corpus cpp             # once
just grammar-diff cpp --old-clean   # must report 0 items parsed cleanly by both but differently
just grammar-recovery cpp           # the error-bytes total should not grow
just grammar-fuzz cpp
```

A change to the C grammar changes this one too: regenerate both
(`just c-grammar cpp-grammar`) and run both diffs.

Then rebuild mep, which compiles `src/` directly (`ts_cpp` in
CMakeLists.txt) and embeds the queries into a generated header at
configure time. `mep-treesitter-test` checks highlights, folds, the
outline and incremental reparsing (raw strings opened and closed by
edits).
