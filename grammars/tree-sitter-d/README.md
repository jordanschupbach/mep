# tree-sitter-d

A [tree-sitter](https://tree-sitter.github.io/) grammar for **D**, compiled
into mep. It is [gdamore/tree-sitter-d](https://github.com/gdamore/tree-sitter-d)
0.8.2 (`fb028c8`, MIT, Copyright 2024 Garrett D'Amore; the notice is kept in
`grammar.js`'s and `src/scanner.c`'s headers) -- the grammar mep loaded from
nixpkgs before this one -- taken in-house and checked against the D
compiler's own parser, so its node names, fields and tree shapes are that
grammar's: the same 285 node types and 13 fields, and queries or tools
written for it work unchanged. Its corpus tests (`test/corpus/`, copied from
it) pass, plus `mep.txt` for the changes below.

## What changed

Places where the compiler's parser (LDC 1.41, the dmd 2.111 front end)
reads code the old grammar could not, or read wrongly:

* **object.d's aliases are names.** `string`, `size_t`, `ptrdiff_t`,
  `noreturn`, `cstring`, `dstring` and `wstring` are not keywords to D:
  they can be declared (object.d itself does `alias string = ...;`, dmd's
  `auto string = ...`) and used as expressions (`return string;`,
  `string[0 .. len]`, `T == string`). Their node types stay, and a builtin
  type may now stand alone as an expression (`@(int)`, `"" == int`).
* **Nested `/+ +/` comments** to any depth, in the external scanner (the old
  regex stopped at five levels and failed on runs of `+`, `/+++++/`). The
  scanner is told when it is inside a string, so `"/+ x +/"` stays a string.
* **`body`** before a function body (the obsolete spelling of `do`, read as
  a `do` node), and `body` as an ordinary identifier elsewhere: a bare
  function literal can no longer start with `do`/`body`.
* **A `{ }` block statement** followed by `*p = 1;`, `.f();` or `(x)` is a
  block, as dmd reads it; the old grammar read the block as a function
  literal applied to what followed.
* `q{...}c` (a token string's suffix), `\&sup2;` (HTML entities with
  digits), `switch (auto x = f())` and `ref` in `if`/`while`/`switch`
  declarations, `catch` with no parameter, `enum E {}`, `enum uint x;`,
  `private version = X;`, literal UDAs (`@"name"`, `@1`, `@__LINE__`) and
  placement `new (buf) T`.

The two `:error` cases in the upstream corpus (`Invalid Hex String`,
`Shebang starts in column 0`) were dropped: mep-ts-corpus-test has no
`:error` attribute.

## How it was checked

The corpus (`just grammar-corpus d`) is LDC 1.41's source tree -- Phobos,
druntime, the dmd front end and dmd's test suite (whose `fail_compilation`
files are deliberately invalid) -- plus dub, D-Scanner and serve-d from
nixpkgs and DCD, libdparse, dfmt and vibe.d from GitHub: 6,778 files (194
duplicates dropped), 1.27M lines. The oracle is the compiler's own parser
(`tools/ts_grammar_diff/d_check.sh`: `ldc2 -o- -v -unittest`; a syntax error
is one reported before `importall`; `just d-check` links the pinned LDC).

* `just grammar-symbols d`: identical, 285 node types, 13 fields.
* `just grammar-diff d --oracle`: 6,624 of 6,778 files identical; 142
  reviewed known differences (`test/known-differences.txt`, all files the
  compiler accepts and the old grammar misread), 12 differ in files the
  compiler rejects, 0 unexplained. Files with parse errors: old 411, new
  282 (0 only in the new grammar). Of the 282, 252 are files the compiler
  rejects; the other 30 are dmd test inputs written to exercise corners
  the node API has no shape for: `#line` in the middle of a line, UTF-16/32
  source, C11 identifier characters, comma expressions in conditions
  (rejected by design upstream: dmd errors on them in semantic analysis),
  `case 1,:`, a template parameter named `string`, old `alias this x;` and
  a handful of semantic-error tests.
* `just grammar-fuzz d`: FUZZ_RESULT
* `just grammar-recovery d`: RECOVERY_RESULT

| File | What it is |
|---|---|
| `grammar.js` | the grammar |
| `src/scanner.c` | numbers, the q-strings, `!in`/`!is`, directives, nesting comments |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `just d-grammar` (mep-ts-generate) -- commit them, don't edit them |
| `queries/highlights.scm` | highlight captures (upstream's, plus declaration names) |
| `queries/folds.scm` | fold ranges |
| `queries/structure.scm` | the structure sidebar's outline: module, aggregates, enums and members, templates, functions, constructors, unittests, fields, constants, aliases |
| `test/corpus/*.txt` | corpus cases, run by `mep-ts-corpus-test` |
| `test/known-differences.txt` | the reviewed differences from the old grammar, for `just grammar-diff` |

## Working on it

```sh
just d-grammar                      # regenerate src/ and run the corpus tests
just grammar-corpus d               # once
just d-check                        # once: the LDC oracle
just grammar-diff d --oracle        # must report 0 unexplained differences
just grammar-fuzz d
just grammar-recovery d
```

Then rebuild mep, which compiles `src/` directly (`ts_d` in
CMakeLists.txt) and embeds the queries into a generated header at
configure time. `mep-treesitter-test` checks highlights, folds and the
outline.
