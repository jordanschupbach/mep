# tree-sitter-fish

A [tree-sitter](https://tree-sitter.github.io/) grammar for the **fish**
shell, compiled into mep, so `.fish` files are highlighted, folded and
outlined without a grammar `.so` on the machine.

It started from [ram02z/tree-sitter-fish](https://github.com/ram02z/tree-sitter-fish)
3.7.0 -- the grammar mep loaded from nixpkgs before -- which is released into
the public domain (the Unlicense); its `grammar.js`, scanner and test corpus
are the base here, with thanks. Its node types and fields are kept exactly
(`just grammar-symbols fish`: 38 node types, 9 fields, none added or lost), so
queries written for it carry over. What changed was measured against fish
4.8's own tokenizer and parser (`src/tokenizer.rs`, `src/ast.rs`, and
`fish --no-execute` as the oracle):

* `(` inside double quotes is text: only `$(` substitutes there. The old
  grammar opened a command substitution at every `(`, so `"("` misread the
  rest of the file.
* `{` where a command may start opens a block whatever follows it
  (`{echo a}`, `{{echo inner}`), as fish 4.1's tokenizer has it; a `}` always
  ends a word.
* `&` followed by a word character is part of the word (`a&b`, fish 3.4's
  default); `^` is an ordinary character.
* Blanks after a brace expansion's comma are not part of the element (fish
  trims them), and an element may concatenate a command substitution.
* Newlines after `&&`, `||` and `|` are skipped, as fish does.
* A line continuation (`\` + newline) is still an `escape_sequence` argument
  where an argument may stand (the old shape), but where a command starts
  (`a | \` then `b`) it is invisible rather than the command's name; and
  comment lines a continuation carries over keep the command going -- fish
  skips them together with their newline (the scanner remembers that state).
* The last statement of a file needs no newline after it; `for x in` may
  have no values, and its variable is any word to the parser.

| File | What it is |
|---|---|
| `grammar.js` | the grammar |
| `src/scanner.c` | the external scanner: zero-width concatenation markers, the `{` that opens a block, line continuations and the comments they carry over |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `just fish-grammar` (mep-ts-generate) -- commit them, don't edit them |
| `queries/highlights.scm` | highlight captures (nvim-treesitter naming) |
| `queries/folds.scm` | fold ranges |
| `queries/structure.scm` | the structure sidebar's outline: functions, exported/global/universal `set`s at the top level, `abbr -a` and `alias` |
| `test/corpus/*.txt` | corpus cases, run by `mep-ts-corpus-test` (upstream's, with the brace-expansion cases moved into argument position, plus `mep_additions.txt`) |
| `test/known-differences.txt` | the reviewed corpus files whose trees differ from the old grammar's |

## How it is checked

`just grammar-corpus fish` gathers 1,956 files: fish's own functions,
completions and test scripts (fish's source) and 28 fish plugins packaged in
nixpkgs (`fishPlugins.*`: tide, pure, hydro, fzf-fish, bobthefish ...).

* `just grammar-diff fish --oracle`: 1,890 files identical to the old
  grammar's trees; the other 66 are reviewed known differences, each a place
  the old grammar was wrong (fish accepts all 66). Files with parse errors:
  old 42, new 3 (`break -h`, `"$foo[d]"`, `"$abc["`, all three in fish's own
  test suite).
* `just grammar-fuzz fish`: the corpus and 3,000 damaged copies, clean under
  ASan + UBSan.
* `just grammar-recovery fish`: 59.5% fewer bytes left in ERROR nodes on the
  damaged copies; better in 1,002 files, worse in 49.
