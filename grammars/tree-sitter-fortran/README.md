# tree-sitter-fortran

A [tree-sitter](https://tree-sitter.github.io/) grammar for **Fortran**, free
and fixed form, compiled into mep, so `.f90` `.f95` `.f03` `.f08` `.f` `.for`
`.F90` files are highlighted, folded and outlined without a grammar `.so` on
the machine.

It started from [stadelmanma/tree-sitter-fortran](https://github.com/stadelmanma/tree-sitter-fortran)
(0.4.0, commit 022b032) by Matthew Stadelman, Peter Hill and contributors -- the grammar mep
loaded from nixpkgs before -- which is released under the MIT licence (kept
here as `LICENSE`); its `grammar.js` and test corpus are
the base here, with thanks. Its node types and fields are kept exactly
(`just grammar-symbols fortran`: 218 node types, 30 fields, none added or
lost), so queries written for it carry over. What changed was measured
against gfortran 14.3 (`gfortran -fsyntax-only` as the oracle):

* **Fixed form.** The old grammar read every file as free form. The external
  scanner now recognises fixed form from the text (a `C`/`c`/`*` comment in
  column 1, a mark in column 6, a label in columns 1-5) and latches it:
  column-1 `C c * D d` comment lines, column-6 continuation lines (a
  zero-width `line_continuation` at the end of the continued line, so the
  tree shape is the free-form one), comment lines between continuations, and
  character constants that run across continuation lines.
* **Free form.** A character constant continued with `'abc&` / `&def'` is one
  `string_literal`; `q`/`Q` exponents read as reals.
* **Comments** are an external token, so a `!` in fixed form's column 6 is a
  continuation mark rather than a comment, and a comment keeps its `\r`.
* **The preprocessor.** The newline that ends a `#define`, `#include` or a
  directive line is an external token: a directive ends at its own line
  instead of swallowing the blank lines after it, and a function-like macro
  call line (`PUSH_SUB(x)`) ends at its newline.

| File | What it is |
|---|---|
| `grammar.js` | the grammar |
| `src/scanner.c` | the external scanner: numbers, BOZ and string literals (kinds, continuation), end of statement, free and fixed line continuations, comments, preprocessor newlines |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `just fortran-grammar` (mep-ts-generate) -- commit them, don't edit them |
| `queries/highlights.scm` | highlight captures (nvim-treesitter naming) |
| `queries/folds.scm` | fold ranges: program units, interfaces, derived types, every block construct |
| `queries/structure.scm` | the structure sidebar's outline: programs, modules, submodules, subroutines, functions, module procedures, derived types, named interfaces |
| `test/corpus/*.txt` | corpus cases, run by `mep-ts-corpus-test` (upstream's 121, all passing) |
| `test/known-differences.txt` | the reviewed corpus files whose trees differ from the old grammar's |

## How it is checked

`just grammar-corpus fortran` gathers 16,409 files: LAPACK and BLAS
(lapack-reference), scipy's Fortran sources, ARPACK, Wannier90, Quantum
ESPRESSO, netCDF-Fortran, HDF5's Fortran API, SIESTA, Octopus, and gcc
14.3's gfortran testsuite.

`tools/ts_grammar_diff/fortran_check.py` is the oracle. gfortran has no
parse-only mode, so it compiles each file with `-fsyntax-only` against `.mod`
files built from the corpus itself (`--build-mods`), stubs a module or
include it cannot find, and sorts gfortran's messages into syntax errors and
semantic ones (a type mismatch is not the grammar's business). Of the
corpus, 15,324 files are accepted and 1,085 have a syntax error.

* `just grammar-diff fortran --oracle`: 11,344 files identical to the old
  grammar's trees. Files with parse errors: old 5,853, new 1,210 (none new).
  Of the 5,065 that differ, 193 are rejected by gfortran and 4,872 accepted;
  all 4,872 are known differences: 4,784 fixed-form files (`.f`, `.F`) the
  old grammar read as free form, 6 free-form files where only the new tree is
  right (continued strings), and 82 free-form files where both grammars fail
  on macros from unseen headers or DEC extensions and only the error recovery
  differs.
* `just grammar-fuzz fortran`: the corpus and 3,000 damaged copies, clean
  under ASan + UBSan.
* `just grammar-recovery fortran`: 71.3% fewer bytes left in ERROR nodes on
  the damaged copies; better in 1,011 files, worse in 212.
