# tree-sitter-gap

A [tree-sitter](https://tree-sitter.github.io/) grammar for **GAP** (4.15),
compiled into mep. It is
[gap-system/tree-sitter-gap](https://github.com/gap-system/tree-sitter-gap)
at commit 96fe2e4 (MIT, Copyright (c) 2019 Max Horn; the license is
reproduced in `grammar.js`'s header) -- the grammar mep built from GitHub
before this one -- taken in-house and checked against GAP's own reader, so
its node names, fields and tree shapes are that grammar's: the same 59 node
types and 23 fields, and queries or tools written for it work unchanged.
Its corpus tests (`test/corpus/`, copied from it) pass, plus `mep.txt` for
the change below.

## What changed

* **A file may open with `local`**, as GAP's reader allows for a file it
  `Read`s (and as `ReadAsFunction` reads one): `local a, b;` before the
  first statement is `source_file`'s `locals` field, the same `locals` node
  a function body has. The old grammar read the line as an error, or
  `local` as a name. Package data files use it (rcwa, atlasrep).
* **`scanner.c`**: `tree_sitter_gap_external_scanner_create(void)` -- it was
  declared `create()`, an unprototyped function the runtime calls through
  `void *(*)(void)`, which UBSan reports on every parse.

## How it was checked

The corpus (`just grammar-corpus gap`) is GAP 4.15.1's library (`lib/`,
`grp/`, `hpcgap/`, `tst/`) and the ~160 packages it ships with, plus the
input lines of every `.tst` test transcript: 8,950 files after dropping
duplicates, 3.25M lines. The oracle is GAP's own reader
(`tools/ts_grammar_diff/gap_check.py`: `ReadAsFunction`, which parses
without running, with the file's top-level expression statements and
`quit;`/`?` lines located by `mep-gap-lsp --gap-toplevel`).

* `just grammar-symbols gap`: identical, 59 node types, 23 fields.
* `just grammar-diff gap --oracle`: 8,931 of 8,950 files identical; 19
  reviewed known differences (`test/known-differences.txt`, all a leading
  `local` the old grammar could not read), 0 unexplained. Files with parse
  errors: old 79, new 60 (0 only in the new grammar). Of the 60, 59 are
  files GAP rejects too (its syntax-error tests, damaged examples); the
  other is `tst/testinstall/linecontinuation.tst`, which tests GAP's
  backslash-newline continuation inside a token (`m\`+newline+`od` reads
  as `mod`) -- a scanner-level splice no tree-sitter lexer rule can express.
* `just grammar-fuzz gap`: 11,950 files (3,000 damaged) clean under ASan +
  UBSan (after the scanner fix above).
* `just grammar-recovery gap`: 0.1% fewer bytes in ERROR nodes than the old
  grammar on the 3,000 damaged copies (better in 9 files, worse in 2).

| File | What it is |
|---|---|
| `grammar.js` | the grammar |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `just gap-grammar` (mep-ts-generate) -- commit them, don't edit them |
| `src/scanner.c` | the external scanner (string contents, plain and triple-quoted, and a float's trailing `.`), from the original |
| `queries/highlights.scm` | highlight captures (nvim-treesitter naming) |
| `queries/folds.scm` | fold ranges |
| `queries/structure.scm` | the structure sidebar's outline: function assignments, top-level globals, `Declare*` declarations, `Install*` methods |
| `test/corpus/*.txt` | corpus cases, run by `mep-ts-corpus-test` |
| `test/known-differences.txt` | the reviewed differences from the old grammar, for `just grammar-diff` |

## Working on it

```sh
just gap-grammar                     # regenerate src/ and run the corpus tests
just grammar-corpus gap              # once
just grammar-diff gap --oracle       # must report 0 unexplained differences (needs `gap` on PATH)
just grammar-fuzz gap
just grammar-recovery gap
```

Then rebuild mep, which compiles `src/` directly (`ts_gap` in
CMakeLists.txt) and embeds the queries into a generated header at
configure time. `mep-treesitter-test` checks highlights, folds and the
outline.
