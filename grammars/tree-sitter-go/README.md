# tree-sitter-go

A [tree-sitter](https://tree-sitter.github.io/) grammar for **Go** (1.26),
compiled into mep. It is
[tree-sitter/tree-sitter-go](https://github.com/tree-sitter/tree-sitter-go)
0.25.0 (MIT, Copyright (c) 2014 Max Brunsfeld; the license is reproduced in
`grammar.js`'s header) -- the grammar mep loaded from nixpkgs before this
one -- taken in-house and checked against Go's own parser, so its node
names, fields and tree shapes are that grammar's: the same 107 node types
and 35 fields, and queries or tools written for it work unchanged. Its
corpus tests (`test/corpus/`, copied from it) pass, plus `mep.txt` for the
changes below.

## What changed

Three places where go/parser (the parser behind gofmt) accepts code the
old grammar could not read:

* **`new(expr)`**, new in Go 1.26 (`new(int64(300))`), and `new`/`make`
  called with an expression in general -- a local function named `make`,
  or `make(1)`, which the type checker rather than the parser rejects. A
  bare type still reads as a type (`new(T)`, `make([]int, n)`).
* **`const x T`** with no value: a parse, then a type error.
* **A label on a label** at the end of a block (`L1: L2:` before `}`).

## How it was checked

The corpus (`just grammar-corpus go`) is Go 1.26.5's own `src/` tree --
the compiler, linker, go command, standard library, their tests and
testdata -- plus gh, hugo, fzf, delve, caddy and go-tools (staticcheck)
from nixpkgs, vendored modules included: 11,486 files (after dropping 401
duplicates), 3.74M lines. The oracle is go/parser itself
(`tools/ts_grammar_diff/go_check.go`, built by `just go-check`: parse with
`AllErrors`, nothing type-checked).

* `just grammar-symbols go`: identical, 107 node types, 35 fields.
* `just grammar-diff go --oracle`: 11,477 of 11,486 files identical; 7
  reviewed known differences (`test/known-differences.txt`, all old parse
  errors or `new(nil)` read as a type), 2 differ in files go/parser
  rejects, 0 unexplained. Files with parse errors: old 52, new 46 (0 only
  in the new grammar). Of the 46, 39 are files go/parser rejects too
  (the type checker's and parser's own error tests); the other 7 are type
  checker test inputs that use a type where an expression goes
  (`struct{ A }.m`, `(*struct{ J }).method`, a type as a builtin's later
  argument), `[...]T` outside a composite literal, `~x` as an expression or
  `x.(type)` outside a type switch -- shapes the node API has no node for,
  all of which the type checker rejects.
* `just grammar-fuzz go`: 14,486 files (3,000 damaged) clean under ASan +
  UBSan.
* `just grammar-recovery go`: 0.9% more bytes in ERROR nodes than the old
  grammar on the 3,000 damaged copies (better in 59 files, worse in 50;
  seed 11: +0.7%). All of it comes from `new(expr)`: letting an
  expression into `new(...)`/`make(...)` gives error recovery more ways to
  read a damaged call. Reading valid Go 1.26 was judged worth that.

| File | What it is |
|---|---|
| `grammar.js` | the grammar |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `just go-grammar` (mep-ts-generate) -- commit them, don't edit them |
| `queries/highlights.scm` | highlight captures (nvim-treesitter naming) |
| `queries/folds.scm` | fold ranges |
| `queries/structure.scm` | the structure sidebar's outline: types (struct, interface, alias), functions, methods, interface methods, package-level consts and vars |
| `test/corpus/*.txt` | corpus cases, run by `mep-ts-corpus-test` |
| `test/known-differences.txt` | the reviewed differences from the old grammar, for `just grammar-diff` |

## Working on it

```sh
just go-grammar                      # regenerate src/ and run the corpus tests
just grammar-corpus go               # once
just go-check                        # once: the go/parser oracle
just grammar-diff go --oracle        # must report 0 unexplained differences
just grammar-fuzz go
just grammar-recovery go
```

Then rebuild mep, which compiles `src/` directly (`ts_go` in
CMakeLists.txt) and embeds the queries into a generated header at
configure time. `mep-treesitter-test` checks highlights, folds and the
outline.
