# tree-sitter-julia

A [tree-sitter](https://tree-sitter.github.io/) grammar for **Julia**,
compiled into mep. It is
[tree-sitter/tree-sitter-julia](https://github.com/tree-sitter/tree-sitter-julia)
0.25.0 (MIT, Copyright (c) 2018 Max Brunsfeld, GitHub; see `LICENSE`) -- the
grammar mep loaded before this one -- taken in-house and checked against
JuliaSyntax, Julia's own parser. Its node names, fields and tree shapes are
that grammar's: the same 86 node types and 6 fields, so queries and tools
written for it work unchanged. Its 63 corpus cases (`test/corpus/`) pass.

## What changed

* **`isa` and `in` as names**, and never the right side of a juxtaposition:
  `function in end`, `for isa in ...`, `1 isa T` and `A' in B` now parse as
  Julia reads them. A newline is allowed after infix `in`/`isa` and after
  `public`; `for outer in xs` works.
* **`begin` as an index**: `a[begin+1:end]`. A new external scanner token
  (`_begin_index`) treats `begin` as a name when an operator, closing
  bracket or comma follows it; `[:begin, :end]` and `@testset begin ... end`
  are unaffected.
* **`;` after a comma list inside `[...]`** (JuMP's `x[i = 1:2, j = 1:2; cond]`).
* **`where` in a struct's type head**: `struct S{N} <: T where {N} end`.
* **`scanner.c`**: `tree_sitter_julia_external_scanner_create(void)` -- it
  was unprototyped, which UBSan reports on every parse.

## How it was checked

The corpus (`just grammar-corpus julia`) is 8,216 files: Julia's `base/` and
standard libraries plus a set of large packages. The oracle is JuliaSyntax
(`tools/ts_grammar_diff/julia_check.jl`, `Meta.parseall`), which accepts
every corpus file.

* `just grammar-symbols julia`: identical, 86 node types, 6 fields.
* `just grammar-diff julia --old-clean`: 214,303 clean items, 0
  unexplained. 7,353 of 8,216 files identical; 536 reviewed known
  differences (`test/known-differences.txt`: `isa`/`in` as names,
  spaced-colon ranges, trailing `;` in arguments, `~` at assignment
  precedence, juxtaposition after `)`/adjoint and in comparison chains,
  keyword symbols, suffixed operators like `==ₜ`, `::(...)` types, char
  literals, the old grammar's root-ERROR recoveries). The per-file reasons
  were assigned by category, with each class reviewed on samples.
* Files with parse errors: old 446, new 79 (none only in the new grammar);
  bytes in ERROR nodes -46.9%.
* `just grammar-fuzz julia`: 11,216 files clean under ASan + UBSan.
* `just grammar-recovery julia`: 3.3% fewer bytes in ERROR nodes than the
  old grammar on damaged copies (better in 544 files, worse in 487).
