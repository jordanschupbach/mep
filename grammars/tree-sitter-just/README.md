# tree-sitter-just

A [tree-sitter](https://tree-sitter.github.io/) grammar for
[justfiles](https://just.systems), written for mep and compiled into it, so
`justfile`, `Justfile`, `.justfile` and `*.just` files are highlighted and
folded without a grammar `.so` on the machine. It follows just's own
grammar (`GRAMMAR.md` in the just repository) and its lexer's rules for
indentation and recipe bodies.

| File | What it is |
|---|---|
| `grammar.js` | the grammar |
| `src/scanner.c` | the hand-written external scanner: newlines, recipe bodies |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `just just-grammar` (mep-ts-generate) -- commit them, don't edit them |
| `queries/highlights.scm` | highlight captures (nvim-treesitter naming) |
| `queries/folds.scm` | fold ranges |
| `queries/structure.scm` | the structure sidebar's outline: recipes, modules and variables |
| `queries/injections.scm` | recipe bodies and backticks as bash |
| `test/corpus/*.txt` | corpus cases, run by `mep-ts-corpus-test` |

## Why a scanner

A justfile is line-oriented, and a recipe's body is only known by its
indentation:

* **Newlines** end items, except inside `(...)`, `[...]` and `{...}`. The
  scanner gives a newline only where the grammar asks for one, so inside
  brackets it is whitespace.
* **Recipe bodies** run until the next line with content that is not
  indented. The scanner looks past blank lines to decide, and puts the
  zero-width dedent at the first line after the body, so blank lines after
  a recipe are not part of it (or of its fold).
* **Body text** is the shell's, apart from `{{...}}`: `{{{{` is a literal
  `{{`, a line ending in `\` continues (so the next line's `-` is text,
  not the ignore-failure prefix), and `@`/`-` are prefixes only at the
  start of a line.

just's keywords are only keywords where they start an item, so `set`,
`mod`, `alias` and the rest can also name a variable or a recipe; where
both readings parse, the item wins (`prec.dynamic`).

## Working on it

```sh
just just-grammar      # regenerate src/parser.c and run the corpus tests
```

Then rebuild mep, which compiles `src/` directly (`ts_just` in
CMakeLists.txt) and embeds `queries/highlights.scm` / `folds.scm` into a
generated header at configure time (`structure.scm` too). `mep-treesitter-test` checks the
highlights mep paints from them.

A good regression check after changing the grammar is just's own test
suite: the justfiles in its `tests/*.rs` that `just --dump` accepts should
all parse without errors, and with the recipes, assignments and aliases
`just --dump --dump-format json` reports.
