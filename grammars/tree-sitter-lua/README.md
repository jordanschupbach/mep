# tree-sitter-lua

A [tree-sitter](https://tree-sitter.github.io/) grammar for **Lua** 5.4
(plus Lua 5.5's `global` declarations), written for mep and compiled into
it. It follows the Lua reference manual (§3, and the complete syntax in §9)
and Lua's lexer (`llex.c`).

Its node names, fields and tree shapes are the ones
[tree-sitter-grammars/tree-sitter-lua](https://github.com/tree-sitter-grammars/tree-sitter-lua)
0.5 established -- the grammar mep vendored before this one -- so queries
and tools written for that grammar work unchanged: the same 47 node types
and 23 fields. On a corpus of luarocks, awesome, lua-language-server,
three neovim plugins and mep's own Lua (3,214 files, 633k lines), 3,192
files parse to the same tree as the vendored parser, node for node and
byte for byte. The other 22 are listed, with why, in
`test/known-differences.txt` -- all places where this grammar follows Lua
and the old one did not:

* **`global` as a name** (18 files). Before Lua 5.5 `global` is an
  ordinary name (`global.x = 1`, `if not global then`), and in 5.5 it is a
  keyword only where it starts a declaration. The old grammar made it an
  anonymous keyword token wherever it appeared.
* **`--[[` inside a quoted string** (2): `' --[['` opened a block comment
  in the old scanner, and one string node swallowed the code after it.
* **Comments of only dashes** (2): the old grammar nested the next line's
  comment inside a bare `--` and split `----` in two.

Both grammars fail on the same 5 files, and `luac -p` rejects all of them.

| File | What it is |
|---|---|
| `grammar.js` | the grammar; operator precedence follows §3.4.8 |
| `src/scanner.c` | the hand-written external scanner: long brackets, comment content |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `just lua-grammar` (mep-ts-generate) -- commit them, don't edit them |
| `queries/highlights.scm` | highlight captures (nvim-treesitter naming) |
| `queries/folds.scm` | fold ranges |
| `queries/structure.scm` | the structure sidebar's outline: functions, methods, function-valued assignments and table fields |
| `test/corpus/*.txt` | corpus cases, run by `mep-ts-corpus-test` |
| `test/known-differences.txt` | the reviewed differences from the old grammar, for `just grammar-diff` |

## Why a scanner

* **Long brackets.** `[==[ ... ]==]` strings and `--[==[ ... ]==]`
  comments close only at the same level, so the scanner keeps the level as
  state (serialized, so an incremental reparse resumes inside one).
* **What follows `--`.** A long bracket right after it opens a block
  comment; anything else (including nothing) is the rest of the line. A
  comment is an `extra`, and extras need an unambiguous end, so the
  scanner makes the call.

Two places where Lua's grammar is ambiguous are settled the way Lua settles
them: a `(` after a value always calls it, even on the next line
(`f\n(g)()`), and a function's name is only ever `a.b.c` or `a.b:c`.

## Working on it

```sh
just lua-grammar                # regenerate src/parser.c and run the corpus tests
just grammar-corpus lua         # once
just grammar-diff lua --oracle  # must report 0 unexplained differences
just grammar-fuzz lua
```

Then rebuild mep, which compiles `src/` directly (`ts_lua` in
CMakeLists.txt) and embeds the queries into a generated header at
configure time. `mep-treesitter-test` checks highlights, folds, the
outline and incremental reparsing.
