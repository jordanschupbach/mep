# tree-sitter-maxima

A [tree-sitter](https://tree-sitter.github.io/) grammar for **Maxima**, the
computer algebra system, written for mep and compiled into it, so `.mac`
and `.max` files are highlighted, folded and outlined without a grammar
`.so` on the machine. Its node names are those of stewsat/tree-sitter-maxima,
the grammar mep loaded before (it has no license, so nothing of it is copied
here) -- queries written for that one carry over -- but its shapes are
Maxima's: it was written from Maxima's own reader (`src/nparse.lisp`), whose
Pratt binding powers mep's Maxima reader (`src/maxima_ast.cpp`) already
reads out of a live image. `-x^2` is `-(x^2)`, `a+b:c+d` is `a+(b:(c+d))`,
`if a then if b then c else d` gives the `else` to the inner `if`.

| File | What it is |
|---|---|
| `grammar.js` | the grammar: one rule per operator, its lbp on the left operand and its rbp on the right (see the comment at the top for why that encodes a Pratt parser) |
| `src/scanner.c` | the external scanner: comments, which nest in Maxima |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `just maxima-grammar` (mep-ts-generate) -- commit them, don't edit them |
| `queries/highlights.scm` | highlight captures (nvim-treesitter naming) |
| `queries/folds.scm` | fold ranges |
| `queries/structure.scm` | the structure sidebar's outline: `f(x) := ...`, `m(x) ::= ...`, `f[n] := ...` and top-level assignments |
| `test/corpus/*.txt` | corpus cases, run by `mep-ts-corpus-test` |

## How it is checked

The grammar the old one would be compared with gets Maxima's precedences
wrong, so the oracle is Maxima's reader instead:
`just maxima-grammar-check` (`tools/ts_grammar_diff/maxima_check.py`) parses
each of the 799 `.mac` files of Maxima's source tree with this grammar and
with `src/maxima_ast.cpp` -- which agrees with Maxima's own `mread-raw` on all
of them -- and compares the trees statement by statement, every leaf with its
byte range.

* 758 of the 774 files the reader accepts give identical trees.
* 15 use an operator declared at run time by a word (`infix("cross")`,
  `a cross b`): a context-free grammar cannot learn a declaration. The
  punctuation spellings Maxima's packages declare (`=>`, `~`, `&`, `|`, `@@`,
  `` ` `` ...) are read as infix operators at the power a declaration without
  numbers gets, so ezunits and the vector packages still parse.
* 1 splits a number across lines with `\`+newline (Maxima deletes that pair
  in its character reader, below the tokenizer).

`just grammar-fuzz maxima`: the corpus and 3,000 damaged copies, clean under
ASan + UBSan. `just grammar-recovery maxima --old <upstream src>`: better
than the old grammar in 1,478 damaged files and worse in 478, +4.8% error
bytes in total, from a few files where an unbalanced `block(` now reads
`block` as a name -- which it has to be able to be: `integrate(f, lambda, 0,
a)` is valid Maxima.

## Node types

`source_file`, `statement` (an expression and its `;` / `$`), `lisp_escape`
(a `:lisp` line), `atom` (`number` / `string` / `identifier`, including
`?lisp` names), `list`, `set`, `function_call`, `array_ref`,
`parenthesized_expression`, `prefix_expression`, `postfix_expression`,
`binary_expression` (also the statement-level `,` and a `tag && expr` label),
`if_expression` / `elseif_clause`, `block_expression`, `lambda_expression`,
and the loops: `for_in_expression` (`for x in l`), `while_expression` and
`unless_expression` (a loop opening with that clause), and `for_expression`
for every other form of Maxima's one loop (`for i : 1 thru n`, `thru 10 do`,
a bare `do`). No fields.
