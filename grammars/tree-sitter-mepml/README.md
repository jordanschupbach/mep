# tree-sitter-mepml

A [tree-sitter](https://tree-sitter.github.io/) grammar for **mepml**, mep's
markup language for literate documents. The language is defined by mep's
own parser (`src/mepml_doc.cpp`) and specified by example in the repo's
`test.mepml`; this grammar gives the same structure to anything that speaks
tree-sitter: mep's own syntax highlighting, and any other editor.

| File | What it is |
|---|---|
| `grammar.js` | the grammar: how tokens combine into nodes |
| `src/scanner.c` | the hand-written external scanner that produces almost every token |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `tree-sitter generate` -- commit them, don't edit them |
| `queries/highlights.scm` | highlight captures (nvim-treesitter naming) |
| `queries/folds.scm` | fold ranges (sections, code blocks, tables, ...) |
| `queries/injections.scm` | code blocks in their own language, maths as LaTeX |
| `test/corpus/*.txt` | `tree-sitter test` cases |

## Why a scanner does most of the work

mepml decides what a line *is* from its first characters, and sometimes its
last (a table row starts and ends with `|`), and its inline markers depend
on context: `*` only opens bold after a space or punctuation, before a
non-space, and only when a matching closer follows in the same paragraph.
The scanner implements those rules the same way `src/mepml_doc.cpp` does,
so the two parsers agree. `mep-mepml-ts-test` checks that they do: on
`test.mepml` both must produce the same blocks at the same rows and the
same count of every inline construct. It also parses thousands of randomly
damaged documents, so run it in the Sanitize build after changing the
scanner.

Headings nest into `section` nodes by depth. A level-N section can't
contain a heading of level N or shallower, so the parse table closes it
without any scanner state, the same approach tree-sitter-markdown uses.

## Working on it

```sh
just mepml-grammar      # regenerate src/parser.c and run the corpus tests
```

which is

```sh
cd grammars/tree-sitter-mepml
nix shell nixpkgs#tree-sitter nixpkgs#nodejs nixpkgs#gcc --command \
  sh -c 'tree-sitter generate && tree-sitter test'
```

Then rebuild mep, which compiles `src/` directly (`ts_mepml` in
CMakeLists.txt) and embeds `queries/highlights.scm` / `folds.scm` into a
generated header at configure time. After adding syntax, also update
`src/mepml_doc.cpp`, `test.mepml` and `help/mepml.org`, and add a corpus
case here.
