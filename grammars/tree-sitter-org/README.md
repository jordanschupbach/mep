# tree-sitter-org

A [tree-sitter](https://tree-sitter.github.io/) grammar for **Org**, written
for mep and compiled into it. It follows the Org syntax specification
(orgmode.org/worg/org-syntax.html) and Org 9.7's manual: headlines with
TODO keywords, priorities and tags; planning lines and property drawers;
drawers, blocks, dynamic blocks, LaTeX environments, lists, tables and
their formulas, footnote definitions, comments and directives; and inline
links, footnote references (inline definitions included), citations,
timestamps, inline source and LaTeX math.

Its node names, fields and tree shapes are the ones the grammar mep vendored
before established (nvim-orgmode's tree-sitter-org 2.0, extended with links,
citations, inline source and math), so the queries written for it work
unchanged: the same 56 node types and 36 fields. Text is mostly words, and
the tree keeps it that way: each word is an `expr` of `str` (letters),
`num` (digits), `sym` (any other character) and punctuation tokens.

## How it compares

Org has no oracle, so the comparison with the old grammar is `just
grammar-diff org --old-clean`, on the repository's 146 `.org` files,
Emacs's Org manual and Modus themes manual, and the docs and tests of
ox-hugo, org-roam, org-ql and org-super-agenda (228 files, 75k lines):

* All 1,459 top-level items (sections, and the document's own body) the old
  grammar parsed without errors are identical. 208 files are identical
  throughout; 4 more differ for one reviewed reason
  (`test/known-differences.txt`): a `# comment` line right after a
  directive, which the old grammar read as a paragraph's text.
* The old grammar fails on 16 files, this one on 4 (none it parses without
  errors), with 99.3% fewer bytes inside ERROR nodes. What is left: a
  citation whose prefix holds a `:`, a `#+` written with zero-width spaces,
  inline source holding `[[`, a LaTeX environment opened mid-line, and
  text after an `\end{...}`.

**Error recovery** (`just grammar-recovery org`): on 3,000 damaged copies of
the corpus, 58.8% fewer bytes end up inside ERROR nodes than with the old
grammar (better in 243 files, worse in 106).

The scanner is clean under ASan + UBSan on the corpus plus the 3,000
damaged copies (`just grammar-fuzz org`).

### Where this grammar parses what the old one could not

* **Blocks close by name.** `#+begin_NAME` ends only at `#+end_NAME`, as in
  Org, so a block may hold a differently named one's lines: an example
  block showing a source block, a `#+begin_details` around a
  `#+begin_summary`. The old grammar closed every block at the first
  `#+end_` and left the rest of the outer block, and often the headlines
  after it, in error. If no line later in the file closes the block by name
  (a typo, an edit half made), any `#+end_` closes it, as before, so one bad
  name cannot swallow a document.
* **Openers need closers.** `\(`, `\[` and `$$` open math only when their
  closer follows on the line, and `[fn:` is a footnote only when a `]`
  follows before a blank line, so Org syntax shown in `=verbatim=` text
  (`=\(x)=`, `=[fn:=`) is text. Four of mep's own help pages had errors from
  this.
* **Inline footnote definitions**, `[fn::TEXT]` and `[fn:LABEL:TEXT]`: an
  `fnref` with a `description`.
* Headlines holding markup (`** Release <2024-06-16>`), a lone `[fn:1]`
  line (a paragraph's reference; its definition follows), and `:NAME:`
  drawers right after a paragraph line.

### Known differences from Org itself (shared with the old grammar)

* A greater block's contents (`quote`, `center`, special blocks) are its
  lines as text, not elements: the old grammar's shape, kept. Links inside
  a quote block are words to this grammar (mep's own link scan draws them).
* There are no emphasis or verbatim objects: `=[[file:x]]=` is a link here,
  where Org (and mep's link scan) leave it literal.
* `str` is `\p{L}`: CJK and the other letters the old grammar's generator
  left out of `\p{L}` (it read `日` as a `sym`) are letters here. This
  changes only anonymous tokens inside words.

## Files

| File | What it is |
|---|---|
| `grammar.js` | the grammar |
| `src/scanner.c` | the external scanner: lists, sections, blocks, drawers, links, math and footnote openers |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `just org-grammar` (mep-ts-generate) -- commit them, don't edit them |
| `queries/highlights.scm` | highlight captures, Org's own names (`OrgHeadlineLevel1`, ...), coloured by `mep.ts_capture_hl` in main.cpp |
| `queries/folds.scm` | fold ranges: sections, blocks, drawers, LaTeX environments |
| `queries/structure.scm` | the structure sidebar's outline: every headline, `heading1`..`heading6` |
| `test/corpus/*.txt` | corpus cases, run by `mep-ts-corpus-test` |
| `test/known-differences.txt` | the reviewed differences from the old grammar, for `just grammar-diff` |

The scanner remembers what a grammar cannot: the indentation and bullet
kind of each open list (a list item ends at a shallower line, a different
bullet at its own indentation, or a blank line followed by another), the
star count of each open section, the open block's name, and whether a `$`
math span is open; all saved with every token, so incremental reparses
resume exactly. It also marks, with zero-width tokens, what only the rest
of a line can tell: a drawer's `:NAME:` line (a word may also start with
`:`), a property drawer where one may start, and the openers above.

Where a line could be read two ways until its end -- a plan line of
timestamps or a paragraph starting with one, a headline's `:tags:` or a
title word, a footnote definition or a reference -- both readings are kept
(`conflicts`) and the line's end decides. Characters a word shares with
markup (`<`, `[`, `:`) are the markup's own tokens for the same reason: if
the lexer decided, it would kill one reading too early. Lexical precedence
is given as numbers (`SPECIAL`): named precedences order rules, not tokens.

Rules are declared in the old grammar's order, which is load-bearing (see
`grammar.js`'s header).

## Agreement with org_doc.cpp

`mep-org-ts-test` checks that this grammar and mep's own org code agree on
every `.org` file in the repository: the same headlines (rows, levels,
priorities, tags) as `ParseOrgOutline`, and the same bracket links as
`ScanOrgLinkSpans` on lines in prose. Making them agree fixed
`ParseOrgOutline` too: it counted a headline-looking line inside a block as
a headline (an example block showing org markup became an agenda entry).

## Working on it

```sh
just org-grammar                    # regenerate src/parser.c and run the corpus tests
just grammar-corpus org             # once
just grammar-diff org --old-clean   # must report 0 items parsed cleanly by both but differently
just grammar-recovery org           # the error-bytes total should not grow
just grammar-fuzz org
```

Then rebuild mep, which compiles `src/` directly (`ts_org` in CMakeLists.txt)
and embeds the queries into a generated header at configure time.
`mep-treesitter-test` checks highlights, folds, the outline and incremental
reparsing (blocks, lists, drawers and math opened and closed by edits);
`mep-org-ts-test` the agreement above.
