# tree-sitter-python

A [tree-sitter](https://tree-sitter.github.io/) grammar for **Python**,
written for mep and compiled into it. It follows the Python 3.14 language
reference (lexical analysis, and the full grammar, `python.gram`), PEP 701
f-strings (a field may hold a string with the same quotes, or another
f-string), PEP 750 t-strings, PEP 695 type parameters and `type`
statements, PEP 634 `match`, PEP 654 `except*`, and the Python 2
statements old code still has (`print >>f, x`, `exec "..." in d`, `<>`,
`1L`, backtick strings).

Its node names, fields and tree shapes are the ones
[tree-sitter/tree-sitter-python](https://github.com/tree-sitter/tree-sitter-python)
0.25 established -- the grammar mep vendored before this one -- so queries
and tools written for that grammar work unchanged: the same 123 node types
and 32 fields.

## How it compares

`just grammar-diff python --oracle`, on CPython 3.13's `Lib/`, numpy,
Django, requests, SymPy and the Python in this repository (7,523 files,
2.6M lines):

* 7,508 files parse to identical trees. The other 15 are listed in
  `test/known-differences.txt`, all for one bug in the old scanner, below.
* Both grammars fail on the same 2 files. Python rejects one
  (`badsyntax_3131.py`). The other, CPython's `test_compile.py`, has a
  line inside brackets indented less than its block:

  ```python
          def f():
              (bar.
          baz)
  ```

  The scanner cannot see bracket depth (brackets are the grammar's
  tokens), so it reads the shallower line as a dedent. This is a shared
  limitation, worth fixing if it ever shows up in real code: Python ignores
  indentation inside brackets entirely.

**The difference: raw strings that end in an escaped backslash.** In
`r'\\'` or `r"C:\\"`, the old scanner forgot the text it had read when it
stepped over the backslash pair, so the string had no `string_content` and
its `string_end` started at the backslashes (`\\'`). Here the text is the
`string_content` and the `string_end` is the quote.

**Error recovery** (`just grammar-recovery python`): on 3,000 damaged
copies of the corpus, 9.6% fewer bytes end up inside ERROR nodes than with
the old grammar (better in 258 files, worse in 145). Two things matter
most there, both measured: Python's keywords are reserved words (`in` or
`def` is never read as a name, so recovery resynchronizes on them), and an
unterminated one-line string stops producing text at its line break.

## Files

| File | What it is |
|---|---|
| `grammar.js` | the grammar |
| `src/scanner.c` | the external scanner: indentation and strings |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `just python-grammar` (mep-ts-generate) -- commit them, don't edit them |
| `queries/highlights.scm` | highlight captures (nvim-treesitter naming) |
| `queries/folds.scm` | fold ranges |
| `queries/structure.scm` | the structure sidebar's outline: classes, functions, `type` aliases, ALL_CAPS module constants |
| `test/corpus/*.txt` | corpus cases, run by `mep-ts-corpus-test` |
| `test/known-differences.txt` | the reviewed differences from the old grammar, for `just grammar-diff` |

The scanner keeps two stacks, both saved with every token so incremental
reparses resume exactly: the indentation of each open block (an indented
line is an INDENT, each level a shallower line closes is a DEDENT, and the
end of a line is a NEWLINE only where a statement can end -- inside
brackets it is whitespace), and each open string's quote and prefix, so a
string inside an f-string's `{...}` can reuse the outer quotes. INDENT,
DEDENT and NEWLINE are zero-width, at the end of the line's last token; a
comment line indented to the block (or deeper) stays in the block, the
dedent coming after it.

Rules are declared in the old grammar's order, which is load-bearing.
Some constructs stay ambiguous until the parse merges (`f(*a.b)`: a splat
of `a.b`, or an attribute of the splat `*a`?). When that happens,
tree-sitter keeps the reading whose node types are numbered lower, and
node types are numbered in declaration order.

## Working on it

```sh
just python-grammar                  # regenerate src/parser.c and run the corpus tests
just grammar-corpus python           # once
just grammar-diff python --oracle    # must report 0 unexplained differences
just grammar-recovery python         # the error-bytes total should not grow
just grammar-fuzz python
```

Then rebuild mep, which compiles `src/` directly (`ts_python` in
CMakeLists.txt) and embeds the queries into a generated header at
configure time. `mep-treesitter-test` checks highlights (most of its
expectations are Python's), folds, the outline and incremental reparsing.
