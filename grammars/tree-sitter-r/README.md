# tree-sitter-r

A [tree-sitter](https://tree-sitter.github.io/) grammar for **R**, written
for mep and compiled into it. It follows R's own grammar and lexer
(`src/main/gram.y` in R's sources) and the operator table in `?Syntax`.

Its node names, fields and tree shapes are the ones
[r-lib/tree-sitter-r](https://github.com/r-lib/tree-sitter-r) 1.x
established -- the grammar mep vendored before this one -- so queries and
tools written for that grammar work unchanged. On R 4.5's own sources and
11 CRAN packages (2,614 files, 543k lines), every file R itself accepts
parses to the same tree as the vendored v1.3.0 parser, node for node,
field for field and byte for byte; the only differences are in files R
rejects, where the two recover from the error differently (in one, a
deliberately broken `f <- (x) ...`, the old parser accepted invalid R).

| File | What it is |
|---|---|
| `grammar.js` | the grammar; precedence follows `?Syntax` |
| `src/scanner.c` | the hand-written external scanner: newlines, raw strings |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `just r-grammar` (mep-ts-generate) -- commit them, don't edit them |
| `queries/highlights.scm` | highlight captures (nvim-treesitter naming) |
| `queries/folds.scm` | fold ranges |
| `queries/structure.scm` | the structure sidebar's outline: functions, R6/S4 classes, generics, methods |
| `test/corpus/*.txt` | corpus cases, run by `mep-ts-corpus-test` |

## Why a scanner

* **Newlines.** R ends an expression at a newline only where one may end
  -- at the top level and in a `{...}` body -- and never inside `(...)` or
  `[...]`. The grammar asks for a newline token exactly where an
  expression may end, so the scanner gives one whenever it is asked, and
  the newline is whitespace everywhere else. A newline before `else` never
  ends the `if`.
* **Raw strings.** `r"(...)"`, `R'[...]'`, `r"--{...}--"` run to their
  matching close bracket, dashes and quote, which the scanner keeps as
  state (serialized, so incremental reparses resume correctly).

## Working on it

```sh
just r-grammar      # regenerate src/parser.c and run the corpus tests
```

Then rebuild mep, which compiles `src/` directly (`ts_r` in
CMakeLists.txt) and embeds the queries into a generated header at
configure time. `mep-treesitter-test` checks highlights, folds, the
outline and incremental reparsing.

After changing the grammar, re-run the comparison and the fuzzer
(tools/ts_grammar_diff/README.md):

```sh
just grammar-corpus r          # once
just grammar-diff r --oracle   # must report 0 differences in files R accepts
just grammar-fuzz r
```
