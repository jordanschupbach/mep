# tree-sitter-ruby

A [tree-sitter](https://tree-sitter.github.io/) grammar for **Ruby**,
compiled into mep. It is
[tree-sitter/tree-sitter-ruby](https://github.com/tree-sitter/tree-sitter-ruby)
0.23.1 (commit `ad907a6`; MIT, Copyright (c) 2016 Rob Rix; see `LICENSE`),
unchanged: `grammar.js`, `src/scanner.c` and the corpus are upstream's, and
`src/parser.c` is regenerated by mep's own generator
(`just ruby-grammar`, checked byte for byte by `just grammar-generate-check`).
Its node names, fields and tree shapes are upstream's, so queries and tools
written for it work unchanged. Its 291 corpus cases (`test/corpus/`) pass
(`mep-ts-corpus-test`).

Before it was compiled in, mep loaded Ruby as an optional dynamic grammar;
the highlight and structure queries that lived in `src/treesitter_queries.h`
and `src/treesitter_structure_queries.h` moved here.

## Queries

* `queries/highlights.scm` -- mep's highlight groups (keywords, method and
  class definitions, calls, constants, symbols, instance/class/global
  variables, string interpolation, heredocs, regexps, comments).
* `queries/folds.scm` -- classes, modules, methods, blocks, conditionals,
  loops, `begin`, arrays, hashes, heredocs.
* `queries/structure.scm` -- the outline: modules, classes, singleton
  classes, methods, singleton methods and constant assignments.

## Users

* highlighting, folding and the outline for `.rb`, `.rake`, `.gemspec` and
  `.ru` files (`src/treesitter.cpp`);
* `mep-ruby-lsp` (`src/ruby_lsp*.cpp`), the Ruby language server;
* mep's Ruby formatter (`src/ruby_format.cpp`).

## Known gaps

Over Ruby 3.4's standard library (981 files), two files do not parse:
`ruby_vm/rjit/insn_compiler.rb` (`?&`, `` ?` ``, `?'` and `?+` character
literals) and `rdoc/rd/block_parser.rb` (an `=begin` comment whose text
mentions `=begin` in a string). The formatter
refuses such files and the language server reports them as syntax errors.
