# tree-sitter-scheme

A [tree-sitter](https://tree-sitter.github.io/) grammar for **Scheme**,
written for mep and compiled into it, so `.scm`, `.ss`, `.sld`, `.sls` and
`.sps` files are highlighted, folded and outlined without a grammar `.so`
on the machine. The tree is what a Scheme reader reads -- atoms, lists,
vectors, the quote family -- and there is no `define` node: what a list
means is decided by the queries, from its first symbol, so a library's own
`define-record-type*` reads exactly like the standard's. One lexical syntax
covers R5RS, R6RS and R7RS-small plus the extensions Guile, Chez and
Racket share, because a highlighter should not stop at a dialect boundary.

Its node names, tree shapes and token boundaries are those of
[6cdh/tree-sitter-scheme](https://github.com/6cdh/tree-sitter-scheme)
(MIT, Copyright (c) 2022 6cdh), the grammar mep loaded from nixpkgs before
this one, so queries written for that grammar work unchanged: the same 22
node types (no fields) and the same rule order. Its reading of the three
reports' number syntax is kept as it was, quirks included (a radix prefix
alone, `#x`, is a number token), since a token boundary that moves is a
tree that changes. Added: R7RS's `#u8(...)` (a `byte_vector`, like R6RS's
`#vu8(`), Guile's `#!/usr/bin/guile -s ... !#` script header (a
`block_comment`), and Guix's G-expressions -- `gexp` (`#~`), `ungexp`
(`#$`, `#+`) and `ungexp_splicing` (`#$@`, `#+@`).

| File | What it is |
|---|---|
| `grammar.js` | the grammar (no external scanner: Scheme's tokens are regular) |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `just scheme-grammar` (mep-ts-generate) -- commit them, don't edit them |
| `queries/highlights.scm` | highlight captures (nvim-treesitter naming): the old grammar's patterns, plus R7RS/Guile special forms, `#:keywords` and G-expressions |
| `queries/folds.scm` | fold ranges: every multi-line list, vector, string and block comment |
| `queries/structure.scm` | the structure sidebar's outline: `define` (procedures and variables), `define-syntax`/`define-syntax-rule`, `define-record-type`, `define-class`/`define-method`, `define-module`/`define-library`/`library` |
| `test/corpus/*.txt` | corpus cases, run by `mep-ts-corpus-test` |
| `test/known-differences.txt` | the reviewed corpus files whose trees differ from the old grammar's |

## The shape of the tree

* Whitespace is not an extra but an (anonymous) child wherever the reader
  allows it, so a prefix owns the datum after it, comments between them
  included: `'` `` ` `` `,` `,@` `#'` `` #` `` `#,` `#,@` `#~` `#$` `#$@`,
  and `#;`, whose `comment` node holds the datum it comments out.
* `#|...|#` nests (`block_comment` inside `block_comment`).
* A token that reads both as a number and as a symbol of the same length is
  a number (`+i`, `-1`); a longer symbol wins (`1+`, `-1-`, `...`).

## How it compares

`just grammar-corpus scheme` collects 3,610 files (2.18 million lines):
Guile's own modules and test suite, Guix (every package definition),
haunt, guile-lib, chibi-scheme's R7RS libraries (`.sld`), Chez Scheme's
compiler and libraries (`.ss`/`.sls`), Gauche, and mep's own query files.

* `just grammar-symbols scheme`: the old API intact (22 node types, no
  fields), plus the three G-expression nodes.
* `just grammar-diff scheme --oracle`: 2,871 files identical; the 739 that
  differ are all files the old grammar had a parse error in -- 678 Guix
  files with G-expressions, 33 with `#u8(`, 4 with `#!/... !#` (all listed in
  `test/known-differences.txt`), and 24 Guile rejects for another reason
  (21 `#u8(` files that also use SRFI 4's other vectors, 3 with Gauche's
  `#/regex/`). Files with parse errors:
  old 1,085, new 380. Before the additions (the same grammar with the old
  token set) all 3,610 files were identical.
* The oracle is Guile's `read` (`tools/ts_grammar_diff/scheme_read.scm`),
  with Guix's G-expression reader extensions installed the way
  `(guix gexp)` installs them.
* `just grammar-fuzz scheme`: the corpus and 3,000 damaged copies (6,610
  files), clean under ASan + UBSan.
* `just grammar-recovery scheme`: 45.2% fewer bytes in ERROR nodes than the
  old grammar on the damaged copies; better in 620 files, worse in none.

## Known limits

* A symbol ends at `'`, as in R7RS: Guile reads `vars'` as one symbol, this
  grammar as `vars` and a quote (the old grammar did the same). Most of the
  remaining parse errors in Guile's own tree are this.
* Guile's `#{...}#` symbols, `#nil`, `#*0101` bit vectors and SRFI 4's
  `#u32(`/`#f64(` vectors, Chez's `#2%car` and `#0=` labels, and Gauche's
  `#/regex/`, `#"..."` and `#[...]` are not read; neither is a reader
  extension a file installs for itself.
* The grammar reads more than any one Scheme accepts (`#x` alone, every
  dialect's character names at once): mep's Scheme language server reports
  what Guile would not read.
