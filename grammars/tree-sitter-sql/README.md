# tree-sitter-sql

A [tree-sitter](https://tree-sitter.github.io/) grammar for **SQL**, written
for mep and compiled into it, so `.sql` files -- and `sql` source blocks in
Org and mepml documents -- are highlighted, folded and outlined without a
grammar `.so` on the machine. One grammar reads the common ground of the
dialects people write: ANSI SQL, PostgreSQL (dollar-quoted bodies, `::`
casts, psql scripts), SQLite (and its shell's dot-commands), MySQL/MariaDB,
T-SQL's `@variables` and bracketless forms, BigQuery/Snowflake/Spark/Hive
table options.

It is a port of [DerekStride/tree-sitter-sql](https://github.com/DerekStride/tree-sitter-sql)
0.3.11 (MIT License, Copyright (c) 2021 Derek Stride) -- the grammar mep
loaded dynamically before this one. Its node names, fields and rule order
are kept: every one of its 523 node types and 53 fields is here, so queries
and tools written for it work unchanged. From the original rules alone,
mep-ts-generate reproduces that release's `parser.c` byte for byte (the
tree-sitter CLI's output, version stamp aside); what mep changed is listed
below and marked `mep:` in `grammar.js`.

| File | What it is |
|---|---|
| `grammar.js` | the grammar |
| `src/scanner.c` | external scanner: dollar-quoted strings and function bodies, sqlite3 dot-commands (rewritten; see below) |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `just sql-grammar` (mep-ts-generate) -- commit them, don't edit them |
| `queries/highlights.scm` | highlight captures (nvim-treesitter naming): the original's query, plus mep's additions |
| `queries/folds.scm` | fold ranges: statements, column lists, CTEs, subqueries, CASE, function bodies, blocks |
| `queries/structure.scm` | the structure sidebar's outline: CREATE TABLE / VIEW / MATERIALIZED VIEW / INDEX / TRIGGER / FUNCTION / TYPE / SEQUENCE / SCHEMA / DATABASE, and CTE names |
| `test/corpus/*.txt` | corpus cases, run by `mep-ts-corpus-test sql`: the original's 412 (all pass unchanged) and `mep.txt` for the additions |
| `test/known-differences.txt` | the reviewed corpus files whose trees differ from the original's in a statement it seemed to parse |

## The shape of the tree

* `program` is a list of `statement`s (and `transaction`s / `block`s), each
  ended by `;` except the last. A statement holds one node saying what it
  is -- `select` + `from`, `insert`, `create_table`, `alter_table`... -- and
  keywords are named nodes (`keyword_select`), case-insensitive.
* Names are `object_reference` (`schema.table`, with `database`/`schema`/
  `name` fields) and `identifier`; a column use is `field`.
* A PostgreSQL function body in `$$` is parsed as SQL between two
  `dollar_quote` nodes when it is SQL; any other dollar-quoted string is one
  `literal`.
* Comments (`--`, `/* */`), psql meta-commands and sqlite3 dot-commands are
  extras, allowed anywhere.

## What mep changed

Each accepts input the original grammar rejected; nothing it parsed changes
shape.

* **psql meta-commands** (`\set x 1`, `\echo`, `\d+ t`, `SELECT 1 \gset`):
  `psql_meta_command`, an extra running to the end of the line. PostgreSQL's
  own test scripts are full of them, and so are people's.
* **sqlite3 dot-commands** (`.mode column`, `.headers on`):
  `sqlite_dot_command`, from the scanner, since only it can tell a `.` in
  the first column from `t.col`.
* Empty statements (`;;`); `EXPLAIN (ANALYZE, COSTS OFF, FORMAT JSON)`;
  `LANGUAGE 'plpgsql'`; a C function's `AS 'MODULE_PATHNAME', 'symbol'`;
  `DO $$ ... $$ [LANGUAGE x]` (`do_statement`); `GRANT` / `REVOKE`
  (`grant_statement`, `revoke_statement`, `privilege`); `ORDER BY x COLLATE
  "C"`; `x LIKE p ESCAPE '^'`; a bare `VACUUM` and `RESET`.
* **The scanner is rewritten.** The original freed its open-tag state while
  serializing it (so tree-sitter's snapshots dropped it), leaked it on every
  deserialize, allocated per character, and had unprototyped entry points:
  UBSan's `-fsanitize=function` reported every file. A dollar-quoted string
  now ends at the first occurrence of its closing tag, as PostgreSQL ends it
  (`$$x$y$$` was read past its end).
* The highlight query's number and float predicates were Lua patterns
  (`%d`), which never match as a regex, so numbers were coloured as strings;
  they are regexes now. New patterns: meta-commands as `@keyword.directive`,
  the GRANT keywords, EXPLAIN's option names.

Two keyword lessons for the next change: a new keyword must be defined
*before* `_identifier` (the word token), or the word wins every tie and
tree-sitter cannot extract it as a keyword -- and then it cannot extract
the keywords valid beside it either (the first try at GRANT quietly turned
`select`, `from`, `on`... into plain regex tokens, and `selections` lexed as
`select` + `ions`). The `selections` / `inserted_at` cases in
`test/corpus/errors.txt` catch exactly that.

## How it compares

`just grammar-corpus sql` collects 2,567 distinct files (208,205 lines):
sqlfluff's dialect fixtures (1,999 files across 30 dialects) and
PostgreSQL's regression, contrib and PL test scripts (769), plus the
repository's own. The original grammar is not vendored, so the comparison
needs its generated source: run `tree-sitter generate` in a copy of
`nix build --inputs-from . nixpkgs#tree-sitter-grammars.tree-sitter-sql.src`
(the source the dynamically loaded `.so` was built from), then
`just grammar-diff sql --old <copy>/src --old-clean`:

* 1,306 files identical; 7 reviewed known differences, where the original's
  "clean" statement was really a zero-width MISSING node (`VACUUM;`,
  `RESET;`, `LIKE ... ESCAPE`) or sat under a whole-file ERROR; every other
  difference is in a file both grammars have errors in.
* All 59,970 top-level statements the original parsed without errors parse
  to the same subtree.
* Files with parse errors 2,096 -> 1,963 (none new); bytes inside ERROR
  nodes -19.0%.
* Error recovery on 3,000 damaged copies (`just grammar-recovery sql`):
  -16.1% error bytes, better in 1,555 files, worse in 59.
* Clean under ASan + UBSan on the corpus and 3,000 damaged copies (`just
  grammar-fuzz sql`); the original's scanner failed every file there.

The oracle (`--oracle`, `tools/ts_grammar_diff/sql_check.py`) asks SQLite
(each statement executed into `:memory:`, only syntax errors counted) and,
when pglast is importable, PostgreSQL's own parser. SQLite accepts 314 of
the corpus files; the original grammar has errors in 107 of them, this one
in 104, none newly. A file only another dialect accepts counts as rejected,
so `--old-clean` is the gate, not `--oracle`.

## Known limits (shared with the grammar it replaces)

* Most files of a real dialect still have some statement the grammar does
  not know -- PostgreSQL's `CREATE TABLE ... PARTITION OF`, `CREATE
  OPERATOR`/`AGGREGATE`/`DOMAIN`/`POLICY`/`RULE`, `ALTER FUNCTION`, T-SQL's
  `DECLARE @x`/`GO`, BigQuery's `CREATE MODEL`... (1,963 of the 2,567 corpus
  files). Error recovery resynchronises at the next statement, so the rest
  of the file still highlights.
* A PL/pgSQL body (`IF`, `RAISE`, `:=`, loops) is parsed as SQL and mostly
  reads as errors inside its `$$`; a `DO` body is a plain string.
* `\gset` and friends end a statement in psql; here the next statement still
  needs its `;`.
