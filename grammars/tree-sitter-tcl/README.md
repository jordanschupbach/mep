# tree-sitter-tcl

A [tree-sitter](https://tree-sitter.github.io/) grammar for **Tcl** 8.6
(and 9.0's syntax, which is the same), written for mep and compiled into
it. It follows Tcl's twelve rules (`Tcl.n`, the "dodekalogue") and Tcl's
own parser (`generic/tclParse.c`): words end only at whitespace, `;`, a
newline or a closing bracket; braces count everywhere inside braces
(comments included); `{*}` expands only when a word follows it directly;
a backslash-newline continues a command and a comment alike.

Its node names, fields and tree shapes are the ones
[tree-sitter-grammars/tree-sitter-tcl](https://github.com/tree-sitter-grammars/tree-sitter-tcl)
(MIT, Copyright (c) 2023 Lewis Russell) established -- the grammar mep
loaded from nixpkgs before this one -- so queries and tools written for
that grammar work unchanged: the same 35 node types and 7 fields. Its
corpus tests (`test/corpus/`, copied from it) pass unchanged.

## How it was checked

The corpus is Tcl 8.6.16's library, tests and tools, Tk's library and
tests, and tcllib: 1,810 files, 973k lines. Tcl's own parser
(`tools/ts_grammar_diff/tcl_check.tcl`, which compiles each file with
`tcl::unsupported::getbytecode` without running it) accepts every one of
them, so the oracle cannot separate the grammars. The old grammar has
parse errors in 1,118 of them (1.74 MB inside ERROR nodes); this one has
errors in 5 (27 bytes), each a construct Tcl accepts but no context-free
reading can: a `}` in the middle of a top-level word (`11}}22`), a stray
`]` inside braces in a test's data, and the like.

So the gate is `just grammar-diff tcl --old-clean`: every top-level
command the old grammar read *without* errors must come out the same.
Of 158,026 such commands, 144,143 are identical and the rest fall in 176
files, all listed with their reasons in `test/known-differences.txt` --
places where this grammar follows Tcl and the old one did not:

* **`::` in names** (52 files): `$a::b` and `::a::b` are one name; the
  old grammar ended it at the `::`.
* **Word splits** (48): the old grammar split one word in two at `:`,
  `"`, `(`, `)`, `${...}` or `\ `, all of which Tcl keeps inside a word.
* **Expression operands** (27): `3-int` or `2,` lexed as one word.
* **One-word commands** (22): `return` or `::tcltest::cleanupTests` on
  its own line was left outside any command.
* **A lone `#`** (12) starts a comment; the old grammar read a word.
* **Unbraced expressions and short commands** (10): `if $a == 1 ...` or
  an `if` with too few words is an ordinary command, not a malformed `if`.
* **Braced data** (9): braces whose content is not a script (an
  unbalanced quote or bracket) hold text; the old grammar read commands
  into it and lost the closing brace.
* **A literal `$`** (8), **comments continued by a backslash-newline**
  (3), **`{*} ` followed by a space** (2, a braced word, not expansion),
  **right-associative `?:`** (1) and **`while true`** (1).

Fuzzing (`just grammar-fuzz tcl`): 4,810 files, 3,000 of them damaged,
clean under ASan and UBSan. Error recovery on the same 3,000 damaged
files: 52.4% fewer bytes in ERROR nodes than the old grammar, better in
2,427 files, worse in 141.

## Why a scanner

Tcl has no grammar in the usual sense: a braced word is a script only
because the command it is passed to evaluates it, and its extent is
fixed by counting braces before anything inside is read. The scanner
does what Tcl does:

* **Brace words.** At a `{` it reads ahead to the matching `}` the way
  `tclParse.c` does, then decides whether the content is something the
  grammar can read as a script (or as a list of words, for
  `braced_word_simple`). If not -- an unbalanced quote or bracket, a `}`
  inside a word -- the whole word becomes data, so one odd string never
  swallows the rest of the file.
* **Comments.** A comment inside braces still counts braces, so
  `#if {$x} {` opens one that a later `#}` closes. The scanner carries
  that count as state (serialized for incremental reparses).
* **Word joins.** Whether `$a(b)` is an array element or `(` starts a
  new piece, and whether the next piece joins the current word, depend
  on what lies ahead; the scanner emits zero-width markers for both.
* **`{*}`** is expansion only with a word right after it.

Builtin commands with a shape (`if`, `proc`, `foreach`, `expr`, ...) get
their own nodes, but every one of them can also be read as an ordinary
command; GLR keeps both, and the shaped reading wins only when the
words fit it.

## Working on it

```sh
just tcl-grammar                       # regenerate src/parser.c and run the corpus tests
just grammar-corpus tcl                # once
just grammar-diff tcl --old-clean      # must report 0 unexplained differences
just grammar-fuzz tcl
```

Then rebuild mep, which compiles `src/` directly (`ts_tcl` in
CMakeLists.txt) and embeds the queries into a generated header at
configure time. `mep-treesitter-test` checks highlights, folds, the
outline and incremental reparsing.
