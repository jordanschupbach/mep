# tree-sitter-typescript

[tree-sitter](https://tree-sitter.github.io/) grammars for **TypeScript**
(`.ts`, `.mts`, `.cts`; this directory) and **TSX** (`.tsx`;
`../tree-sitter-tsx`), written for mep and compiled into it. They extend
mep's JavaScript grammar (`../tree-sitter-javascript`) the way TypeScript
extends JavaScript, and differ in one place: `<T>x` is a type assertion in
`.ts` and a JSX element in `.tsx`, which is how TypeScript itself decides.
The language reference is TypeScript's own parser (5.9).

Their node names, fields and tree shapes are the ones
[tree-sitter/tree-sitter-typescript](https://github.com/tree-sitter/tree-sitter-typescript)
0.23 established -- the grammars mep loaded from nixpkgs before -- so
queries written for those work unchanged: the same 177 node types and 40
fields for TypeScript, 184 and 43 for TSX, plus `using_declaration`. The
rules follow that grammar's `common/define-grammar.js` (MIT; Max
Brunsfeld, Amaan Qureshi and contributors), adapted to mep's JavaScript
grammar, and so does the scanner's TypeScript part.

## How it compares

`just grammar-diff typescript --oracle` and `just grammar-diff tsx
--oracle`, on TypeScript's own `src/` (compiler, services, server and the
lib `.d.ts` files), and two TypeScript front ends, Outline and Mastodon,
plus the TypeScript in this repository (3,063 files, 912 of them `.tsx`;
751k lines). The oracle is TypeScript's parser
(`tools/ts_grammar_diff/ts_check.js`: `ts.createSourceFile`'s parse
diagnostics).

* 2,140 of 2,151 `.ts` files and 806 of 912 `.tsx` files parse to
  identical trees. The other 117 are listed in each grammar's
  `test/known-differences.txt`: the old grammar has a parse error in all
  of them but 19, and TypeScript accepts them all.
* No file in the corpus has a parse error (the old grammars failed on 8
  and 90).

**The differences**, all things the old grammar could not read:

* **Tagged templates with type arguments**, ``styled.div<Props>`...` ``
  (styled-components; 113 files): now a `call_expression` with
  `type_arguments` and a `template_string`, as TypeScript reads it. The
  old grammar failed, or read ``a < b > `c` `` as two comparisons.
* **Variance annotations** (`<in out T>`, 4.7) and `const` type
  parameters together.
* **Labelled tuple elements named by a keyword**: `[symbol: Symbol]`.
* **`keyof readonly T[]`**.

Beyond the corpus, TypeScript's own test suite (`tests/cases/conformance`
and `tests/cases/compiler`: the 11,071 `.ts` and 304 `.tsx` files its parser
accepts, many of them only for its checker to reject) shows the rest of
what changed:

* **Reserved words where TypeScript allows any name**: `a?.delete()`,
  `Q.default.T`, `typeof C.prototype.delete`, `export { x as while }`,
  `<label class="a" for="b">`. mep's JavaScript grammar reserves
  ECMAScript's reserved words (the old grammars reserved none), so each
  place that takes an IdentifierName says so.
* **`using` and `await using` declarations** (5.2), in `for` heads too
  (`using_declaration`, which the old grammar lacked).
* **Auto-accessors** with modifiers: `static accessor x`.
* **`@(expr)` decorators** take any expression, and **`<this.Component />`**.

The old grammars fail on 471 of those `.ts` files and 5 `.tsx`; these on
414 and 6. Three `.ts` files and one `.tsx` file fail only here, all
reserved words used as names where TypeScript's parser accepts them but its
checker reports an error (`typeof default`, `x: break`, `<var var="v" />`).
What both still miss, worth fixing if it comes up in real code: `<<`
opening nested type arguments (`Modifier<<T>(x: T) => T>`), an `infer X
extends Y` constraint inside a conditional's check type, and modifiers
TypeScript only rejects later (`export get f()`, `static const x`).

**Error recovery** (`just grammar-recovery typescript`, `tsx`): on 3,000
damaged copies of each corpus, 13.3% fewer bytes end up inside ERROR
nodes for `.ts` (better in 238 files, worse in 167) and 1.9% fewer for
`.tsx` (better in 204, worse in 155) than with the old grammars.

The scanner is clean under ASan + UBSan on each corpus plus 3,000 damaged
copies (`just grammar-fuzz typescript`, `tsx`).

## Files

| File | What it is |
|---|---|
| `common/define-grammar.js` | the rules, for both dialects |
| `common/scanner.h` | the external scanner, for both dialects: JavaScript's, plus a signature's end (`function f(): T` then a line break, unless `{` follows), optional markers (`x?: T`) that are not conditionals, and a `}` or line break that ends a type |
| `grammar.js` | the TypeScript dialect |
| `src/scanner.c` | `common/scanner.h` under this grammar's name |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `just typescript-grammar` (mep-ts-generate) -- commit them, don't edit them |
| `queries/highlights.scm` | what TypeScript adds to JavaScript's highlights; mep layers it over `../tree-sitter-javascript/queries/highlights.scm` for both dialects |
| `queries/folds.scm` | fold ranges (TSX adds its JSX elements: `../tree-sitter-tsx/queries/folds.scm`) |
| `queries/structure.scm` | the structure sidebar's outline, for both dialects: interfaces, type aliases, enums, namespaces, classes, functions and their overloads, methods and method signatures, function-valued fields and variables |
| `test/corpus/*.txt` | corpus cases, run by `mep-ts-corpus-test` |
| `test/known-differences.txt` | the reviewed differences from the old grammar, for `just grammar-diff` |

`../tree-sitter-tsx` holds the TSX dialect's `grammar.js`, its own
generated `src/`, its corpus and known differences, and its fold additions.

New rules are declared in the old grammar's order, after JavaScript's,
which is load-bearing (see `common/define-grammar.js`'s header). A change
to the JavaScript grammar changes these too: regenerate both.

The scanner keeps no state. Where it puts a comment -- inside the statement
before an automatic semicolon, or after it -- follows the old grammar's
scanner, so trees with comments match.

## Working on it

```sh
just typescript-grammar                  # regenerate both dialects and run their corpus tests
just grammar-corpus typescript           # once (and tsx)
just grammar-diff typescript --oracle    # must report 0 unexplained differences (and tsx)
just grammar-recovery typescript         # the error-bytes total should not grow (and tsx)
just grammar-fuzz typescript             # (and tsx)
```

The oracle needs Node and TypeScript; `grammar-diff` runs it through `nix
shell nixpkgs#nodejs nixpkgs#typescript`. The old grammars are nixpkgs'
`tree-sitter-grammars.tree-sitter-typescript.src` (and `-tsx`), fetched by
`grammar-diff` itself.

Then rebuild mep, which compiles `src/` directly (`ts_typescript` and
`ts_tsx` in CMakeLists.txt) and embeds the queries at configure time.
`mep-treesitter-test` checks highlights, folds, the outline and incremental
reparsing for both dialects.
