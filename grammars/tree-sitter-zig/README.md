# tree-sitter-zig

A [tree-sitter](https://tree-sitter.github.io/) grammar for **Zig** (0.16),
compiled into mep. It is
[tree-sitter-grammars/tree-sitter-zig](https://github.com/tree-sitter-grammars/tree-sitter-zig)
1.1.2 (nixpkgs' `1.1.2-unstable-2025-09-10`; MIT, Copyright (c) 2024 Amaan
Qureshi; the license is reproduced in `grammar.js`'s header) -- the grammar
mep loaded from nixpkgs before this one -- taken in-house and checked
against Zig's own parser, so its node names, fields and tree shapes are that
grammar's: the same 95 node types and 17 fields, and queries or tools
written for it work unchanged. Upstream ships no corpus tests;
`test/corpus/mep.txt` covers the changes below and a few basics.

## What changed

Places where Zig's parser (`std.zig.Ast`) accepts code the old grammar
could not read:

* **Assembly clobbers as one expression** (Zig 0.16:
  `asm volatile ("" ::: .{ .memory = true })`). The old list of strings
  still reads, for older code.
* **`async` and `await` as ordinary names** (`.async = async`,
  `enum { sync, async }`, `io.async(f, .{})`): they stopped being keywords
  in Zig 0.15. `async_expression`/`await_expression` stay in the node API
  for older code (`async foo(x)`), at a lower dynamic precedence.
* **An `if` type after `!`, `[]`, `[*]` or `[N]`**
  (`fn f() !if (c) T else U {`, `[]if (w) u16 else u8`): the old grammar
  read the function body that followed as an initializer list.
* **Field types that are not primary type expressions**: `error{...}`,
  `(A || B)`, `(fn () u32)` and a labeled block `T: { ... }`.
* **`true:` (and `false`, `null`, `undefined`) as a block label** -- to
  Zig's tokenizer they are identifiers.

## How it was checked

The corpus (`just grammar-corpus zig`) is the Zig 0.16 tree's own `lib/`
(std, compiler_rt), `src/` (the compiler) and `test/` (including the
compile-error cases), zls, ghostty, river, waylock, ncdu and linuxwave from
nixpkgs, and tigerbeetle's and bun's sources from GitHub: 4,889 files after
dropping 18 duplicates, 2.53M lines. The oracle is Zig's own parser, as
`zig fmt --stdin` runs it (`tools/ts_grammar_diff/zig_check.sh`): parse
only, since `zig ast-check` also reports AstGen errors (an unused local)
that are not syntax.

* `just grammar-symbols zig`: identical, 95 node types, 17 fields.
* `just grammar-diff zig --oracle`: 4,817 of 4,889 files identical; 69
  reviewed known differences (`test/known-differences.txt`, every one an old
  parse error, all in files Zig accepts), 3 differ in files Zig rejects, 0
  unexplained. Files with parse errors: old 156, new 88 (0 only in the new
  grammar). Of the 88, 64 are files Zig rejects; the other 24 are compile
  error tests whose malformed number or character literals (`1_.0`,
  `0x1.0p1ab1`, `''`, `'\u{}'`) Zig's tokenizer reads as one token and
  AstGen rejects.
* `just grammar-fuzz zig`: 7,889 files (3,000 damaged) clean under ASan +
  UBSan.
* `just grammar-recovery zig`: 0.8% more bytes in ERROR nodes than the old
  grammar on the 3,000 damaged copies (better in 95 files, worse in 76;
  seed 11: +0.3%, better in 97, worse in 102) -- the cost of `async`/`await`
  being names as well as keywords and of the wider field and clobber rules.
  Reading valid Zig 0.16 was judged worth that.

| File | What it is |
|---|---|
| `grammar.js` | the grammar |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `just zig-grammar` (mep-ts-generate) -- commit them, don't edit them |
| `queries/highlights.scm` | highlight captures (nvim-treesitter naming) |
| `queries/folds.scm` | fold ranges |
| `queries/structure.scm` | the structure sidebar's outline: named structs, unions, enums, opaques and error sets with their fields/members and declarations nested, functions (a function returning `type` as a class), tests, other constants and variables |
| `test/corpus/mep.txt` | corpus cases, run by `mep-ts-corpus-test` |
| `test/known-differences.txt` | the reviewed differences from the old grammar, for `just grammar-diff` |

## Working on it

```sh
just zig-grammar                     # regenerate src/ and run the corpus tests
just grammar-corpus zig              # once
just grammar-diff zig --oracle       # must report 0 unexplained differences
just grammar-fuzz zig
just grammar-recovery zig
```

Then rebuild mep, which compiles `src/` directly (`ts_zig` in
CMakeLists.txt) and embeds the queries into a generated header at
configure time. `mep-treesitter-test` checks highlights, folds and the
outline.
