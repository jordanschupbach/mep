Driving mep from an agent

The socket

Every running mep binds a Unix socket at

~/.local/share/mep/agent-sockets/<pid>.sock

speaking JSON-RPC 2.0 with Content-Length framing. No handshake: connect and send a request.

mep-mcp is the MCP server in front of it -- a dependency-free C++ binary -- which is what an agent normally talks to. A script can speak to the socket directly instead.

Conventions

  • Rows and columns are 0-indexed, and line ranges are [start, end) with the end exclusive. This differs from the Lua API, which is 1-indexed.
  • An agent has its own virtual cursor, drawn in the human's panes under its name. Moving it never moves the human's cursor or changes what their panes show.
  • command.run takes cmd, not command. A wrong key silently runs an empty command and returns success.

The rule that matters

Edit open files through mep's buffer tools, not by writing to disk.

mep does not watch files for external changes, so a disk write will not appear in an open buffer -- and when the human next saves that buffer, their stale copy overwrites the agent's work silently.

Being visible

Agents appear as participant chips in the tab bar and in the AI Agents sidebar, with a status they set themselves. An agent that reports its status is one the human can supervise without interrupting.

mep.participants() exposes the same snapshot to Lua.

Full reference

MEP_AGENT_API.md in mep's source tree has every method, its parameters, the pivot table for 3D primitives, and a worked example.
