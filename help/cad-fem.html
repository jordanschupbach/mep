CAD and finite elements

What this is

mep carries its own boundary-representation CAD kernel and its own finite-element solver. Both are written from scratch in this repository: there is no OpenCASCADE, no CalculiX, no Eigen. The kernel keeps exact geometry -- a cylinder is a cylinder, not a fine polygon -- through modelling, meshing, solving and back out again, and that is what makes adaptive refinement possible at all: refining a mesh means going back to the shape and meshing it again, which a program holding only facets cannot do.

Getting started

Everything is reachable from Lua as mep.part_* and mep.fem_*, from an agent over the RPC socket as cad.* and fem.*, from an MCP client as mep_part_* and mep_fem_*, and from the command line with no display at all:

sh Copy
mep --cad-fem study.json out.json
mep --cad-export part.step part.stl

A script is a list of calls. Name one with as and later calls refer to its result with $name.field:

js Copy
[
  {"method": "part.new",     "as": "doc"},
  {"method": "part.box",     "as": "block", "params": {"document": "$doc.document", "size": [10, 6, 4]}},
  {"method": "part.face_at", "as": "base",  "params": {"document": "$doc.document", "body": "$block.body", "normal": [0, 0, -1]}},
  {"method": "part.face_at", "as": "top",   "params": {"document": "$doc.document", "body": "$block.body", "normal": [0, 0, 1]}},
  {"method": "fem.mesh",    "as": "mesh",  "params": {"document": "$doc.document", "body": "$block.body", "size": 2.0}},
  {"method": "fem.study",   "as": "study", "params": {"document": "$doc.document"}},
  {"method": "fem.support", "params": {"study": "$study.study", "face": "$base.face"}},
  {"method": "fem.load",    "params": {"study": "$study.study", "kind": "pressure", "face": "$top.face", "magnitude": 5e6}},
  {"method": "fem.solve",   "as": "result", "params": {"study": "$study.study", "mesh": "$mesh.mesh"}}
]

Things worth knowing

Faces are named by direction

There is no clicking here, so cad.face_at returns the face whose outward normal is nearest a direction you name. It is also the only addressing that survives a rebuild: a study captures its faces as persistent names, not as ids, so the same study still means the same thing after the part changes size -- which is exactly what the adaptive loop does on every cycle.

Every solve reports how wrong it is

fem.solve returns a relative_error alongside the stresses: the estimated error of that mesh in the energy norm, from a superconvergent patch recovery of the stress field. A stress number handed to someone who will act on it, with no indication of how converged it is, is the most dangerous output this system produces. Above roughly ten percent, the mesh has not resolved the problem.

Sizes are in your model's units

Element size, chord tolerance and displacement scaling all default to a fraction of the model's own diagonal rather than to an absolute number. An absolute default is right for exactly one size of model and it is never the one in front of you.
