mep ships its own C++ language server, =mep-cpp-lsp=, built beside the
editor and attached to every C++ buffer by itself. It needs no compiler,
no =compile_commands.json= and no =clangd= install: it is an entire C++
front end -- tokenizer, preprocessor, parser and scope model -- with the
standard library's names compiled into it.

* What it gives you

Open a =.cpp= or =.h= file and you get, with nothing installed:

- *Diagnostics* as you type: syntax and preprocessor errors, a local that
  is assigned and never read, a static function nobody calls, a
  declaration that shadows another, an assignment used as a condition, a
  member initializer list out of declaration order, a class with virtual
  functions and a public non-virtual destructor, a member a class does
  not have, a call with the wrong number of arguments.
- *Completion* of everything in scope, of a class's members after =.=,
  =->= or =::=, of the standard library after =std::=, of the standard
  headers inside =#include <>=, and of the headers next to your file
  inside =#include ""=.
- *Hover* showing a declaration, its type or signature, and the comment
  written above it.
- *Document symbols* for the outline sidebar: namespaces, classes, members,
  enums, typedefs and macros, nested the way the file is.
- *Folding* of braced blocks, comment runs, the include block and
  =#if= groups.
- *Go to definition*, including into a header sitting next to the file,
  and onto the header an =#include= names.
- *References, document highlight and rename* over the scope the
  declaration actually lives in.
- *Signature help* while typing a call's arguments.

* What it deliberately does not do

It does not type-check, and it never will. A language server that cannot
see the headers a file includes -- beyond the ones next to it, which this
one does read -- would be guessing, and a C++ linter that guesses is one
bad heuristic away from being switched off. So every check reports only
what a careful reader could confirm from the file in front of them, and
several of them switch themselves off entirely when the file turns out to
include a header the server could not read:

- The *undefined name* check is off for any file that includes a header
  the server could not open, that says =using namespace= of a namespace
  it cannot see, that does not parse cleanly, or in which six or more
  distinct names cannot be placed. In a file whose includes all resolve
  -- your own headers, plus standard ones -- it is on, and it catches
  typos.
- The *no such member* check runs only for a class defined in the file
  (or in a header next to it) whose base classes are all visible too.
- The *argument count* check steps aside as soon as a name has more than
  one declaration, or takes =...=, or is a template.

The preprocessor is modelled, not run: =#if= groups are resolved against
the macros the file itself defines plus a host-shaped predefined set
(=__cplusplus=, =__GNUC__=, =__linux__=, ...), and only the surviving
branch reaches the parser. =#error= behind a macro the server cannot know
about is not reported -- it would fire in half the standard headers.

* Settings

Three optional settings, passed through the server registry in your
=init.lua=:

#+begin_src lua
mep.lsp_servers.cpp_ls.init_options = {
  maxLineLength = 110,                    -- hint past this column; off by default
  defines = {'MEP_DEBUG', 'VERSION=3'},   -- your build system's -D flags
  includeDirs = {'/path/to/project/src'}, -- where quoted #includes resolve
}
#+end_src

=defines= is what decides which =#if= branches the server reads, and
=includeDirs= is what lets it resolve (and index) a header that is not
next to the file. Both are worth setting for a project of any size.

* Choosing clangd instead

=clangd= is still registered. Give it back the filetypes and clear this
server's to use it:

#+begin_src lua
mep.lsp_servers.clangd.filetypes = {'c', 'cpp', 'h', 'hpp', 'cc', 'cxx'}
mep.lsp_servers.cpp_ls.filetypes = {}
#+end_src

clangd knows what a real compilation knows, which is more than this
server can; it also needs a compile database and an install. This one is
always there.

* How it is built

- =src/cpp_ast.{h,cpp}= -- tokenizer (line splices, raw strings, every
  literal form) and preprocessor (directives, conditional groups, macro
  expansion with =#= and =##=).
- =src/cpp_parse.cpp= -- the parser: declarations, statements and
  expressions, with documented heuristics for the three things C++ cannot
  decide without a symbol table (declaration versus expression, template
  argument list versus less-than, and what an unknown SHOUTED identifier
  in declaration position means).
- =src/cpp_lsp.cpp= -- the scope model, plus the one place the server
  reads another file: a quoted =#include= that resolves is parsed too, so
  a name from your own header resolves and go to definition lands in it.
- =src/cpp_lsp_diagnostics.cpp= and =src/cpp_lsp_features.cpp= -- the
  checks, and everything that is not a check.
- =src/cpp_lsp_vocab.cpp= and =src/cpp_lsp_std_names.cpp= -- the curated
  vocabulary and the generated name list. Regenerate the latter from the
  standard headers on your machine with
  =scripts/gen_cpp_std_names.sh=; it is committed, so building mep never
  needs them.
- =src/cpp_lsp_test.cpp= -- the windowless test suite
  (=mep-cpp-lsp-test=), which asserts as carefully that ordinary code
  produces *no* diagnostics as it does that broken code produces them.
