* Buffers are not files

A *buffer* is a file's contents in memory, together with its undo history,
cursor and modified flag. Opening a file creates a buffer; writing a buffer
sends it back to disk. Everything in between is buffer work.

A buffer does not need a file at all -- =:e notes.txt= on a path that does
not exist gives you a buffer named =notes.txt= that appears on disk only
when you =:w=. That is how you create a file, not an error.

* Opening and writing

| Command       | Does                                          |
|---------------+-----------------------------------------------|
| =:e {file}=   | open a file into a buffer                     |
| =:e!=         | reload from disk, discarding changes          |
| =:w=          | write the buffer to its file                  |
| =:w!=         | write it even if the file changed on disk     |
| =:w {file}=   | write it somewhere else                       |
| =:wa=         | write every modified buffer that has a name   |
| =:q=          | close the pane; quit once it is the last one  |
| =:q!=         | close it even with unsaved changes            |
| =:wq= =:x=    | write, then close                             |
| =:qa= =:qa!=  | quit the whole session                        |
| =:wqa= =:xa=  | write everything, then quit                   |

=:q= refusing means the buffer has unsaved changes. =:qa= applies that check
across every buffer in every workspace, so quitting never loses something
you had forgotten about in another tab.

* When the file changed underneath the buffer

mep does not watch the filesystem. If something rewrites a file while you
have it open -- a =git pull= or =git checkout=, a rebase, a formatter,
another editor, =git= in one of mep's own terminal panes -- the buffer goes
on showing the text it was read with.

So mep remembers each file's size and timestamp as of the moment it read or
last wrote it, and *refuses a write whose file no longer matches*:

#+begin_example
E13: "main.py" changed on disk since it was read -- :e! reloads it, :w! overwrites it
#+end_example

Nothing has been written when you see this, and nothing has been lost. The
buffer still holds your version and the file still holds the other one; you
just have to say which wins:

| Command | Keeps                                             |
|---------+---------------------------------------------------|
| =:e!=   | the file -- re-reads it, discarding buffer edits  |
| =:w!=   | the buffer -- overwrites what is on disk          |

=:e!= is undoable: the discarded text goes onto the undo stack, so =u= brings
it back if you chose wrong.

The git panel handles the common case for you. After any git command it
re-reads every open buffer whose file changed and which has no unsaved edits,
and warns about the ones it left alone:

#+begin_example
Pull: done, 3 buffers reloaded
Changed on disk, but has unsaved edits: main.py -- :e! takes the file, :w! keeps the buffer
#+end_example

Without this, pulling a branch with files open would leave stale text on
screen and write it back over the pulled version at the next save, while
=git pull= correctly reported "Already up to date" -- only the working tree
having been reverted.

* Moving between buffers

| Command                     | Does                          |
|-----------------------------+-------------------------------|
| =:bnext= =:bn=              | next buffer                   |
| =:bprevious= =:bp=          | previous buffer               |
| =:bdelete= =:bd= =:bd!=     | close a buffer                |
| =<leader>bb=                | the buffer picker             |
| =<leader>bi=                | buffer info popup             |
| =:ls=                       | list buffers                  |

These cycle through the *current workspace's* buffers, not everything open
in the process, and they include buffers that are not currently shown in any
pane. See [[file:pickers.html][Pickers]] for the picker's own keys.

* Buffers belong to a workspace

Buffers are scoped to the workspace they were opened in. =:ls=, the buffer
picker and =:bnext= all show that workspace's buffers.

The guards are deliberately *not* scoped that way: =:wa= writes modified
buffers everywhere, and =:qa= refuses if anything anywhere is unsaved. The
listing is scoped so it stays useful; the safety net is global so nothing
hidden is ever lost.

* Buffer info

=<leader>bi= (=:MepBufferInfo=) toggles a popup with the less common facts
about the current buffer: its *buffer id* first, then its path, filetype,
line count and cursor, whether it is modified or on screen, its workspace,
and -- for a terminal -- the running program and exit state. It also shows
the send-to-terminal wiring in both directions: which terminal this buffer
sends to (=<leader>rc= sets it, see [[file:repl.html][send-to-terminal]]) and which
buffers send into it, plus the LSP client attached to it.

Below that it lists every open buffer with its id, so the number a prompt
asks for is always one keystroke away. A =*= marks the current buffer, =#=
one shown in a pane, =!= one with unsaved changes.

The box closes on any key; =<leader>bi= over it closes it too, and any other
=<leader>= sequence typed over it closes it and runs as usual.

* Scratch buffers

=<leader>bs= (=:MepScratch=) opens a scratch buffer: a real, editable buffer
with no file behind it, for notes and experiments. It is not one of the
"pristine" buffers the [[file:dashboard.html][start screen]] looks for, so opening one dismisses
the dashboard.

* What opens as what

mep decides how to present a file from its extension. A =.md= or =.org= file
is text with extra rendering; a =.pdf=, =.docx=, =.xlsx=, =.ipynb=, =.png=
or =.obj= opens in a viewer or editor built for it, in an ordinary pane.

An HTML file is a special case worth knowing: =:e page.html= opens the
*source* as text, while opening it through a link, the file tree or
=:Browse= renders it.
