* Formatting a buffer

=gf=, or =:MepFormat=. It formats the buffer's *current text*, including
unsaved changes -- it never needs the file written first and never formats a
stale copy from disk.

* What runs

| Filetype             | Formatter      |
|----------------------+----------------|
| C, C++ and friends   | =clang-format= |
| Python               | =black=        |
| R                    | =styler=       |
| anything else        | =mep.lsp_format=, if a server is attached |

That is a deliberately short table. Most languages already have a formatter
behind their language server, so the table only carries the cases where a
dedicated tool is clearly better.

* Org code blocks

In an =.org= file =gf= formats *code*, never the prose around it.

| Where the cursor is        | What =gf= does                          |
|----------------------------+-----------------------------------------|
| inside a =#+begin_src= block | formats that block's body             |
| anywhere else              | formats every block that has a formatter |

=:MepOrgFormatBlock= and =:MepOrgFormatBlocks= are the same two, by name.

The block's language picks the formatter -- =#+begin_src python= is
formatted by =black=, the same as a =.py= file, because the block's
language name is translated through its babel file extension before the
table above is looked up.

A block indented under a heading is dedented before the formatter sees it
and re-indented after, so the org file's own layout survives. A body whose
lines do not share one indent (tabs on some, spaces on others) is passed
through exactly as written.

For a language with *no* entry in the table, a single-block =gf= falls back
to that block's own language server -- the one already answering
[[file:org-polyglot.html][hover and completion inside the block]]. The
whole-file sweep does not: it only runs the table, and reports those blocks
as skipped.

* Adding one

#+begin_src lua
mep.format_languages.js = {'prettier', '--stdin-filepath', '{}'}
mep.format_languages.ts = mep.format_languages.js
#+end_src

The entry is an argv array. =\{\}= anywhere in it is replaced by a path.

Two modes:

- *filter* (the default): the buffer is written to the formatter's stdin and
  its stdout replaces the buffer. =\{\}= is the buffer's real absolute
  filename.
- *file*: add =mode = 'file'=, and =\{\}= is a temporary file the formatter
  edits in place.

Entries are looked up by *bare extension*, so every extension of a language
needs its own key -- which is why the built-in table aliases =.h=, =.cc=,
=.hpp= and the rest onto the C entry.

* Why the placeholder matters

A formatter reading stdin has no idea what file it is looking at. Both
=clang-format= and =black= have to be told -- =--assume-filename= and
=--stdin-filename= -- or they cannot find the =.clang-format= or
=pyproject.toml= the project configures them with, and they silently format
to their own defaults instead.

So a filter-mode entry should almost always pass =\{\}= somewhere.
