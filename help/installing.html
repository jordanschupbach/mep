Installing and running

Getting a toolchain

mep builds with CMake and a C++20 compiler. The repository ships a Nix flake that provides everything -- cmake, the compiler, emscripten, deno, just -- at the right versions:

direnv allow      # or, per shell:
nix develop

Everything below assumes you are inside that shell.

Building and running

CommandWhat it does
just runbuild the native binary and launch it (the default)
just build-nativebuild only, into build/native
just build-webbuild the wasm target, into build/web
just run-wasmbuild wasm and open it in a Deno-hosted window
just testbuild and run every test that needs no display
just cleanremove all build output

For a faster edit/test loop there is just build-native-dev, an -O0 build in its own directory that never collides with the release one. Use it for iteration, not for anything performance-sensitive.

The command line

mep [--project <dir>] [--no-session] [file]
mep --export-org <in.org> <out.html>
OptionEffect
--project <dir>open dir as the project instead of the current directory
--no-sessionneither restore nor save this project's workspaces and tabs
--export-orgrender one Org file to HTML and exit, with no window
-h, --helpprint this usage and exit
fileopen file once the project is set up

$MEP_PROJECT does the same job as --project, for launchers that find setting an environment variable easier than building an argument list.

Configuration

On startup mep runs ~/.config/mep/init.lua if it exists. That file is ordinary Lua with mep's whole scripting API available, and it runs before any saved session is restored, so options that affect restoring take effect in time.

lua Copy
-- ~/.config/mep/init.lua
mep.colorscheme('everforest-dark')
mep.opt.restore_workspaces = false
mep.leader_map('xx', 'Say hello', function() mep.notify('hello') end)

:source <file> runs another Lua file, and :lua <code> runs a line directly -- useful for trying something before committing it to init.lua.

The wasm build

mep also compiles to WebAssembly. just run-wasm builds it and opens it in a native window via Deno and webview, with file reading and writing bridged to a loopback-only HTTP server on the host.

Opening build/web/mep.html directly in a browser tab works too, but there is no server behind it: :e, :w and :source fail there with an ordinary read/write error, and there is no init.lua to load. Clipboard access in the browser is best-effort.
