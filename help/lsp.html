Language servers

Attaching

Open a file mep has a server for, and if that server is on $PATH it starts automatically. Nothing to configure.

A client runs per language per workspace root, so two workspaces on two branches each get their own -- which is what makes branch-per-workspace work without servers fighting over one project.

:MepLspAttach attaches by hand; :MepLspStop stops a client.

Diagnostics

Errors, warnings and hints are underlined in the buffer and marked in the sign column. Q shows the current line's diagnostics in a popup, and :MepDiagShow lists them.

]e and [e jump to the next and previous error in the file (wrapping at either end), then pop up that line's errors. For diagnostics of any severity there are mep.lsp_next_diagnostic and mep.lsp_prev_diagnostic, unbound by default -- mep.map_bracket_next('d', mep.lsp_next_diagnostic) puts them on ]d=/[d=.

The popup is a list, one entry per diagnostic -- long messages are wrapped but stay a single entry:

KeyDoes
C-n / C-pnext / previous entry (j / k too)
ycopy that message to the system clipboard
Ycopy every message in the popup
Enterjump to that diagnostic's own line:column
Escdismiss

The gutter mark says which kind, by shape as well as by colour:

MarkSeverity
a disc with an xerror
a hazard triangle with a !warning
a disc with an iinformation
a disc with a ?hint

So a glance tells you an error from a warning without having to know the theme's red from its yellow -- and so does a reader who cannot tell them apart at all.

The worst severity on a line is the one its mark shows. When a line has more than one, the message beside it is prefixed with the count -- =(3) ...= -- so nothing is lost by the mark naming a kind rather than a number.

Severity maps to the Error, Warn, Info and Hint highlight groups, so the colours follow your theme.

If a server is missing, nothing breaks -- the file simply opens without one.

The two mep brings itself

mep-org-lsp is mep's own org-mode server, built and installed alongside mep, so org files get diagnostics and completion with nothing to install. See The org language server.

mep-r-lsp is the same idea for R: it parses R itself and never starts R, so a .R file gets diagnostics, completion, hover and signature help on a machine with no R installed. See The R language server.

R's own languageserver package is still registered, under r_languageserver, with no file types claimed. It knows what an installed package exports, which mep's own server cannot. To prefer it:

lua Copy
mep.lsp_servers.r_languageserver.filetypes = {'R', 'r'}
mep.lsp_servers.r_ls.filetypes = {}

Inside org code blocks

Code blocks in an Org file get language-server support too, through a shadow buffer per block. See Language servers in code blocks for what that covers and what it does not.

In an org file both run at once -- the org server on the markup, a real language server on each block's contents -- and their diagnostics are merged rather than replacing one another.
