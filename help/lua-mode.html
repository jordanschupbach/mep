Lua mode

Opening it

The language UI toggle (see Language UI modes) in a .lua file. The tab becomes a Lua workspace: your file, an interactive lua below it, and panels showing what that interpreter holds.

The console is the stock interpreter, lua -i, so line editing, history and the printing of an expression's value are its own. It starts with mep's environment: the lua on PATH and LUA_PATH, LUA_CPATH and LUA_INIT, as a project's dev shell or direnv set them, so require finds the same modules it would in a terminal in that project.

Working in it

Key / callDoes
<leader>rrrun the whole file in the console
<leader>rerun the top-level statement at the cursor in the console
ghhelp for the name under the cursor, in the Help panel
mep_help('name')the same, from the console
mep_view('name')a value, key by key, in the Inspect panel
mep_run(file)run a file the way <leader>rr does

<leader>re finds the statement around the cursor -- from the nearest line above that starts one at column 0 to just before the next: a whole function, an if or loop, a table constructor, or a single line.

Neither key pastes your code into the prompt. The stock interpreter reads a paste one line at a time, and each line is its own chunk, so a local from one line is gone by the next. Instead the code is written to a file and run as one chunk with a single mep_eval(...) or mep_run(...) line. It runs under your file's name with its own line numbers, so an error names the right line, and so does gh on a function it defined.

Top-level local declarations -- the ones at column 0, outside long strings -- become global assignments first, so what a block or a file defines stays reachable from the console and shows up under Globals: local M = {} runs as M = {}, local function f as function f. Locals inside functions and do blocks are left alone. An expression's values are printed, as at the prompt; so is what a file returns.

<leader>rr runs the buffer as it is in the editor, unsaved changes included. mod1+Enter still pastes the current line or the selection straight into the prompt (see REPL and send-to-terminal).

The panels

PanelShows
Globalsthe globals the session has set, with type and value
Modulesthe modules =require=d this session, then the preloaded ones
Inspectmep_view of a value: its keys, two levels deep
Helpa function's signature, doc comment and source; a module's or object's functions and fields; the manual link for the standard library

Clicking a Globals row inspects it; clicking a Modules row shows the module's functions and fields in Help. What existed when the console started -- the standard library, LUA_INIT's globals -- is left out.

The panels refresh after every command: the init script hooks _PROMPT, which Lua 5.4 converts with __tostring before each prompt. Under 5.1 to 5.3 or LuaJIT (picked with a REPL: comment) they refresh only after the mep_* calls.

gh and the language server

For a function written in Lua, Help shows its signature and its source with the comment block above it. A C function -- the standard library's, or a native module's -- has no source the console can show, so in a .lua buffer gh also opens the language server's hover, which has the documentation from the module's annotations. Without the mode open, gh is that hover alone.

Options

lua Copy
mep.opt.lua_ui_cmd = {'luajit'}            -- the console's interpreter
mep.opt.lua_ui_globalize_locals = false    -- keep top-level locals local

A -- REPL: nix develop --command lua line in the file overrides lua_ui_cmd for that file. The mode appends -i and its init script, so the command must accept them, as lua and luajit do.
