mepml is mep's own markup language for literate documents: prose, maths,
code blocks you can run, and their results, in one plain-text =.mepml=
file. The file =test.mepml= at the top of the mep repository uses every
construct below and is the reference for the language.

A =.mepml= buffer is rendered in place, the way org is: markup is hidden
on every line except the cursor's, headings are drawn large, maths is
typeset, images are shown, and code blocks are highlighted in their own
language.

* Keys and commands

| Key / command         | Does                                                      |
|-----------------------+-----------------------------------------------------------|
| play button, =gr=     | export the document and open the result beside it         |
| =<leader>rr=          | the same                                                  |
| =C-c C-c=             | run the code block under the cursor                       |
| =<leader>kx=          | the same                                                  |
| =C-c C-k=             | stop the block running under the cursor (a terminal)      |
| =<leader>ks=          | the same                                                  |
| =<leader>kt=          | type into the running block's terminal                    |
| =<leader>ka=          | run every code block, top to bottom                       |
| =<leader>ke=          | export as... (pick a format: HTML, PDF, Word, ...)        |

Folding (=za=, =zM=, =zR=) folds heading sections, code blocks,
citations, display maths, tables, lists, comment runs and the rendered
=\toc= and =\bibliography=. A code block and
its results fold separately: =za= on the opening fence folds the code,
=za= on the =// result_begin:= line folds the results, so either can be
put away while the other stays open (a running program's terminal or
window hides with its results). The =-= button at the right of either
card's title bar does the same with the mouse. A folded card keeps its title
bar (language, options, play button, and a count of the hidden lines), and its
=+= button unfolds it. A document opens with the code its exports leave
out already folded -- every block under =//? Exports: results= (or =none=),
and any block with =exports=results=, =exports=none= or =echo=false= -- so it
reads the way it exports, results showing. A rendered =\toc= or =\bibliography= folds too:
=za= on it collapses the block to its title and a count (/Contents • 3
headings/), and =za= again, =zR= or its =+= opens it. The Structure sidebar
lists the headings.

* Document options and comments

#+begin_example
//? Title: Some title
//? Option: OptionA=10
//? Option: OptionB=1.1
//? Option: OptionC="asdfasdf"
// A comment: never rendered, never exported.
#+end_example

=//?= lines hold metadata as =Key: value=. =Title:= names the document;
=Option: Name=value= sets an option whose value is an integer, a decimal
or a string (quote it to force a string). Any other key is kept as-is.

A run of =//?= lines on consecutive rows is a header block, drawn as a
card of its own. The title is large and bold, a =Subtitle:= sits under it
in italics, and every other key becomes a muted label in a column, with
the values lined up beside it. An option reads =OptionA = 10=, its value
coloured as a number or a string. The line under the cursor shows its
raw =//?= text, as any marked-up line does.

A header block folds like any other block (=za=, or the =+=/=-= in the
gutter). Folded, it reads as its title and a tally of the rest: /Some
title • 3 options/. =<leader>kh= folds every header in the document at
once, or unfolds them.

** Importing in the header

#+begin_example
//? Title: A Test Document
//? Import: opts.mepml
//? Import: refs.mepml
//? Option: speed=5
#+end_example

=//? Import: file= brings another mepml file into this one, from the
header:

- Its header is inherited: its options, and keys such as =Author:= or
  =Date:= that this document does not set. This document's own always
  win -- above, =speed= is 5 even if =opts.mepml= sets it too -- and its
  =Title:= is used only if this document has none.
- Its content is included where the =Import:= line is, so imported files
  arrive in the order the header lists them, ahead of this document's own
  text. Its citations join this document's, ready for =\cite(key)=.
- A file can import others in turn. A file imported twice (by the header
  and again with =\import= in the body) is included once, where it is
  first named; a file that imports itself round a loop is reported.

The import's path is a link: =<leader>kl= (or a click) opens the file.
The buffer shows this document's own text; the imported content appears
in every export and in the language server's checks.

A =//= line is a comment. On a prose line, a =//= after a space starts a
comment that runs to the end of that line.

* Callouts

A comment that starts with a keyword and a colon is a callout, drawn in
the editor as a coloured note; the =//= lines right under it continue it.
It is still a comment -- a note to yourself while writing -- and like every
comment it is left out of every export.

#+begin_example
// TODO: check these numbers against the 2024 data,
// and this line is part of the same note.
// QUESTION: does this belong before the proof?
#+end_example

For something said to the /reader/ -- a note, a tip, a warning, an example
-- use a box: =\note(=, =\tip(=, =\warning(= and =\example(= (see
Boxes, below).

The keywords are =NOTE=, =INFO=, =TIP=, =HINT=, =SUCCESS=, =WARNING=,
=CAUTION=, =ERROR=, =DANGER=, =IMPORTANT=, =TODO=, =FIXME=, =QUESTION= and
=EXAMPLE=.

* Headings, paragraphs and rules

#+begin_example
> Heading level 1
>> Heading level 2
>>> Heading level 3
#+end_example

Up to six levels. A blank line separates paragraphs. A line of three or
more of the same one of =-=, ~=~, =_= or =*= is a dividing rule.

* The abstract

#+begin_example
\abstract(
What the document is about, with any *inline* markup, $maths$ and
\cite(key) citations.

A blank line starts a second paragraph.
)
#+end_example

The prose runs to the matching =)=, over as many lines as it needs; a
blank line inside starts a new paragraph. Every line inside is prose, even
one that begins with =-= or =>=. Parentheses inside are fine as long as
they pair up; an unmatched one takes a backslash, =\)=.
=\abstract(One sentence.)= on one line works too. A document has one
abstract; a second is flagged. The older =@abstract{...}= spelling is no
longer an abstract: it is flagged, and the language server's fix rewrites
it.

The editor draws it as a card, with =\abstract(= shown as a centred
*Abstract* label (or a run-in *Abstract.* when text follows it on the same
line) and the closing parenthesis hidden. It folds like a code block. Each export
writes its own format's abstract: LaTeX's =abstract= environment, Org's
=#+begin_abstract=, Word's and LibreOffice's /Abstract/ styles, and a
=<section class="abstract">= in HTML. Imports read these back, and pandoc's
abstracts as well.

* Slides

#+begin_example
\slide(
> What we found
- Any blocks at all: lists, code, pictures, tables, maths
- *Inline* markup as anywhere else
)
#+end_example

=\slide(= on a line of its own opens a slide, and a line holding just its
=)= ends it (a =// comment= may follow either). Everything between is
ordinary mepml -- headings, lists, code blocks with their results,
pictures -- so a slide is written the way the rest of the document is.
=\slide{= ... =}= and =@slide{= ... =}= work too. The slide's first heading
is its title.

Slides do not nest: a =\slide(= inside an open slide ends that slide there,
and both are flagged as never closed. A slide left open runs to the next
=\slide(= or the end of the document. The language server offers to close
it. Content on the opening line itself (=\slide(text)=) is flagged. The
content goes on the lines after the opener.

The editor draws a slide as a card: the opener becomes its title bar,
labelled /Slide N/, and the closer its bottom edge, with the cards of the
code blocks and results on the slide set inside it. A slide still missing
its closer is drawn as a rule labelled /Slide N: title/ instead. A slide
folds as one block, collapsing to its title bar, and appears in the
outline. In an ordinary document, the HTML export puts each slide in a
=<section class="slide">=, and the other document exports keep a slide's
content as ordinary blocks, without the slide boundaries.

** Presentations

A header line makes the whole document a presentation:

#+begin_example
//? Title: Slides in mepml
//? Subtitle: What a slide can hold
//? Author: A. Person
//? Type: presentation
#+end_example

Its exports are then slide decks. Each starts with a title slide made
from =Title=, =Subtitle=, =Author= and =Date=, followed by one slide per
=\slide=, titled by its first heading:

| Export            | A presentation becomes                                                  |
|-------------------+-------------------------------------------------------------------------|
| =html=            | a slideshow in one page                                                 |
| =tex=, =pdf=      | a Beamer deck (16:9), compiled by =tectonic= for the PDF                |
| =pptx=            | a PowerPoint deck                                                       |
| =odp=             | a LibreOffice Impress deck                                              |

In the slideshow, =h= and =l=, the arrow keys, space, a click or a swipe step
through the slides, as do the =<= and =>= buttons that show when the mouse
is over the bottom of the window. =Home= and =End= jump to either end, and =f= goes full screen.
Printing it gives one slide per page. Slides are 16:9 in every format. A
slide whose content is too tall for it is shrunk to fit: the slideshow
scales it down, and the PowerPoint and Impress decks use smaller type.

What is not on a slide is left out of these exports, and the language
server flags it. Header lines and comments are not flagged. The =pptx= and =odp= decks
can also be made from an ordinary document that has slides.
=//? Type: document= is the default, and any other value is flagged.

** Presenting in the editor

=<leader>kp= (=:MepmlPresent=) shows the deck one slide at a time in the
editor itself, starting at the slide the cursor is on: the pane takes the
whole editor area, the slide's text is set as prose, and the cursor is
hidden until you ask for it (=n=, normal mode). =<leader>kP= (=:MepmlPresent full=) takes the window full screen
too, hides everything else and sets the text large enough to read across
a room; a slide too full for the screen gets smaller text so that all of
it shows.

A slide reads the way an export does. A code block shows its results, not
its code, unless the header or the block says otherwise (=exports=both=,
=exports=code=, =echo=true= ...); a block that has not been run yet shows
its code. Code shows without its options, figures without their
=// \image(...)= lines, and comments, result markers and =\define=s are
left out. Your commands are expanded for the =present= export name, so
=\when(present, ...)= can say something for this view only, and
=\otherwise(...)= applies wherever nothing else does. Citations read as
their labels.

| Key                                   | Does                                          |
|---------------------------------------+-----------------------------------------------|
| =l=, =→=, =↓=, space, =PageDown=, =Enter= | the next slide                            |
| =h=, =←=, =↑=, =Backspace=, =PageUp=      | the previous slide                        |
| =C-n= / =C-p=                         | the next / previous slide, in normal mode too (every slide starts in presentation mode) |
| =g=, =Home= / =G=, =End=              | the first / last slide                        |
| =n= / =P=                             | normal mode: a cursor on the slide, at its first character, and vim's keys; =P= goes back to presentation mode |
| =C-c C-c=                             | run the code block under the cursor; with no cursor, every one on the slide (a web page or app it shows too, even with its code hidden; =C-c C-c= again stops one that runs) |
| =f=                                   | switch between filling the editor and full screen |
| =+=, =-=, =0=                          | larger, smaller, back to the starting size    |
| =r=                                   | rebuild the slides from the document          |
| =:=                                   | a command line                                |
| =q=, =Esc=                            | stop, back in the document at the slide shown |

=f=, =+=, =-=, =0=, =r= and =q= do the same in normal mode (so there
they are not vim's), and every slide you turn to starts in presentation
mode again.

A code block runs as the document's own block -- with the options the
slide leaves out -- and its results go into the document, so the slide
shows them as soon as they are in. Only a block whose code the slide
shows can be run from it.

The slides follow the document: an edit made elsewhere, or a block that
finishes running, shows on the slide within half a second. The slides
themselves are not for editing (an edit in normal mode is undone, and =:w=
refuses them); edit the document instead.

In the PowerPoint and Impress decks, a slide's text, lists, code and
results, tables and pictures are real text boxes, tables and pictures you
can edit. A single picture beside text goes on the right. Footnotes go at
the bottom of their slide. Maths is set as real equations: Office
equations in PowerPoint, formula objects in Impress. Inline maths in
Impress is typeset text (a text box cannot hold a formula), and so is
every equation in a =pptx= opened by a program without Office equations,
except that a deck exported from mep's editor (rather than by
=mep-mepml=) shows its display equations there as pictures.

* Boxes: definitions, theorems and their kin

#+begin_example
\definition(Orthogonal projection,
The point of a subspace $S$ closest to $\mathbf{y}$:

$$
\hat{\mathbf{y}} = P\mathbf{y}
$$
)

\theorem(Pythagoras, If $\mathbf{a} \perp \mathbf{b}$, the squared lengths add up.
)

\remark(A one-liner, closed where its text ends.)
#+end_example

=\definition(Title,= on a line of its own opens a box, and a line holding
just =)= closes it (a =// comment= may follow). Everything between is
ordinary mepml -- paragraphs, display maths, lists, code, pictures, other
boxes -- so a box holds whatever a slide can. The kinds are:

| Command         | Label       | Colour                         |
|-----------------+-------------+--------------------------------|
| =\definition=   | Definition  | blue                           |
| =\theorem=      | Theorem     | purple                         |
| =\lemma=        | Lemma       | purple                         |
| =\proposition=  | Proposition | purple                         |
| =\corollary=    | Corollary   | purple                         |
| =\fact=         | Fact        | orange                         |
| =\example=      | Example     | green                          |
| =\remark=       | Remark      | teal                           |
| =\proof=        | Proof       | grey, ending with a tombstone ∎ |
| =\note=         | Note        | slate blue                     |
| =\tip=          | Tip         | green                          |
| =\warning=      | Warning     | amber                          |

The title is everything before the first comma (escape a comma that
belongs to it: =\,=), and may hold inline markup and maths. Text after
the comma on the opening line starts the box's first paragraph, which runs
on over the lines after it like any paragraph; a box whose =)= ends that
paragraph (=\remark(Title, text)= on one line) needs no closing line of its
own. Leave the title out with nothing before the comma, or with nothing at
all for a box opened on a line of its own (=\proof(=); a box closed on its
opening line without a comma is all text (=\example(Just text.)=).

A box of a kind of your own is =\boxed(kind, Title,= ... =)=: the kind is
any name (letters, digits and =-=), and everything after it reads as it
does for the kinds above.

#+begin_example
\boxed(axiom, Choice,
Every family of non-empty sets has a choice function.
)
#+end_example

It is labelled with its kind ("Axiom"; =key-result= reads "Key result")
and drawn like a plain box until a style sheet says otherwise --
=box[kind=axiom] { --accent: #e07a00; }= for its colour,
=box[kind=axiom]::label { content: "Axiom"; }= for its label (see Style
sheets below).

Boxes nest, each closing before the one around it, and on a slide they
close before the slide does: a =)= line ends the innermost box first. A
box left open is flagged and closed where its slide (or the document)
ends. The names are built in, so =\define= cannot take them.

The editor draws a box as a card tinted in its kind's colour with a rule
down its left edge: =\definition(= reads as a bold *Definition:* label in
that colour, the title is bold, and the comma and the closing =)= are
hidden (a proof's becomes its ∎). Moving the cursor onto a line shows it
as written. A nested box is set inside the one around it. A box folds as
one block, collapsing to a bar with its kind and title, and the
presentation view draws boxes the same way. In the exports, HTML (and the
HTML slideshow) draws the box with its label in small capitals, LaTeX and
the Beamer deck a coloured =tcolorbox=, Markdown and Org a bold heading
(Org as a =#+begin_definition= special block), and Word, LibreOffice, RTF,
PowerPoint and Impress a coloured heading over the box's content. HTML,
Markdown and Org imports read boxes back.

* Inline formatting

| Markup                    | Result                     |
|---------------------------+----------------------------|
| =*bold*=                  | bold                       |
| =~italic~=                | italic                     |
| =_underlined_=            | underlined                 |
| =x^2^=                    | superscript (x²)           |
| =H,,2,,O=                 | subscript (H₂O)            |
| =<small>=                 | small text                 |
| =>big<=                   | big text                   |
| ~=highlighted=~           | highlighted                |
| =-strikethrough-=         | struck through             |
| =+inserted+=              | inserted                   |
| =!deleted!=               | deleted                    |
| =`verbatim`=              | code, nothing inside is formatted |

Two more use a pipe character: =|monospaced|= is monospaced text that is
still formatted inside, and =[text|https://...]= is a link (a bare
=[https://...]= works too).

A marker only opens after a space or punctuation and before a non-space,
and only closes before a space or punctuation, so =snake_case=, =a * b=,
=1 + 2= and =well-known= are left alone. Superscript and subscript are the
exception and work inside words: =x^2^=, =H,,2,,O=. Put a backslash before
any character to take it literally: =\*not bold\*=.

A line that starts with =>= and a space is always a heading, so =>big<= at
the very start of a line must not have a space after the =>=.

Commands are written =\name(argument, text)= and nest:

| Command                  | Does                                  |
|--------------------------+---------------------------------------|
| =\f(Helvetica, text)=    | font family                           |
| =\fs(12, text)=          | font size in points (12 is body size) |
| =\color(red, text)=      | colour: a name or =#rrggbb=           |
| =\fn(text)=              | a numbered footnote                   |
| =\cite(key)=             | Author (Year)                         |
| =\citep(key)=            | (Author, Year)                        |

A command's arguments end at its first commas, so the text after them may
hold commas of its own: =\fs(12, Helvetica, font size 12)= is 12-point
"Helvetica, font size 12". Parentheses in the text are fine as long as they
pair up; an unmatched one takes a backslash, =\)=. A two-argument command
without its comma (=\fs(12)=) is left as plain text. The older
=\fs{12}{text}= spelling, with each argument in braces, still works.

The editor draws these for real, as it does big, small, superscript and
subscript text: a line holding text taller than a line gets room above it,
so everything on the line shares one baseline. Families map onto the faces
mep embeds: Helvetica, Arial and other sans faces draw in Liberation Sans;
Times, Georgia and other serif faces in Liberation Serif; Courier and other
monospace faces in Liberation Mono. Inside a table cell, text is drawn at
most a quarter larger than body text, so the row stays one line tall. The
cursor's own line always shows the raw markup, for editing.

* Maths

#+begin_example
Inline $E=mc^2$ or \(\frac{a}{b}\)\alttext(a over b).
$$
  \int_{-\infty}^{\infty} e^{-x^2} dx = \sqrt{\pi}
$$
\alttext(The Gaussian integral)
\[ \sum_{n=1}^{\infty} \frac{1}{n^2} = \frac{\pi^2}{6} \]
#+end_example

Maths is typeset in the buffer with the same preview org uses
(=<leader>otl= toggles it; it needs =tectonic= and =pdftoppm=). An
=\alttext(...)= right after a formula says how it is read aloud: a screen
reader speaks that instead of the symbols (see Accessibility, below). A lone
dollar amount such as =$5= is never maths.

* Code blocks and results

#+begin_example
//? Option: Option1=value1
```{bash, Option3="value3"}
echo "Hello, world"
```
// result_begin:
// Hello, world
// result_end
#+end_example

The header is =```{lang, Name=value, ...}=, or just =```lang=.
=//? Option:= lines directly above the block add more options. Running the
block (=C-c C-c=) writes its output between the =result_begin:= and
=result_end= markers, creating them under the block if they aren't there
yet. =eval=false= stops a block from running.

In the editor a code block is drawn as a card: a title bar with its
language, its header options and a play button (click it to run the
block), and its results as an =output= card underneath. The raw lines come
back when the cursor is on them.

A block with a =file= option draws a figure:

#+begin_example
```{r, file="squares.png"}
plot(1:10, (1:10)^2, type = "b")
```
\caption(Squares)
#+end_example

R gets a plot device opened at that file, and Python gets matplotlib
pointed at it (just plot; no =savefig= needed). Any other language is
expected to write the file itself. After the run, the results hold an
=\image(squares.png)= line: the editor draws the figure inside the output
card, and the export shows it as an image. The block's =\caption= then
captions the figure.

** What the exports show

By default an export shows each code block and its results. org-babel's
=exports= option changes that: =code=, =results=, =both= or =none=. Set it
for the whole document in the header, or on one block, where it wins:

#+begin_example
//? Exports: results
```{r, exports=both}
summary(fit)
```
#+end_example

=echo=false= (knitr's name) also means results only. A report written
this way exports as its text, tables and figures, with the code that made
them left in the =.mepml= file. The editor always shows everything, and
runs every block as usual. Results that are not exported (=exports=code=
or =none=) are not numbered, in the editor either: a figure or table
caption's number is always the one a reader sees.

** HTML output

A block with =results=html= prints HTML, and its results are that HTML,
drawn rendered:

#+begin_example
```{python, results=html}
print("<table><tr><th>Fruit</th><th>Count</th></tr>")
print("<tr><td>apple</td><td>3</td></tr></table>")
```
#+end_example

After a run the results open with =// result_begin: html= and hold the
markup the block printed. In the buffer the output card shows it laid out
by mep's own HTML engine -- tables, headings, lists, colours, borders,
inline SVG, pictures -- at the text width. Move the cursor into it to see
and edit the markup; move out and it is drawn again. A whole document
(=<html>=, =<head>=, =<body>=) works as well as a fragment; its scripts are
not run, since the results show what the code produced.

The exports keep it as HTML where the format can: the HTML export embeds
it (a whole document's body, with its =<style>=), Markdown carries it as
raw HTML, and Org as the =#+begin_export html= block org-babel itself
writes for =:results html=. Word, OpenDocument, RTF and plain text show
its text, and the three document formats also carry the markup itself, so
importing one of them brings the HTML back.

** Markdown output

A block with =results=markdown= prints Markdown, and its results are read
as part of the document. A table it prints is a table, numbered and
captioned like one typed in:

#+begin_example
```{r, results=markdown}
knitr::kable(head(iris, 3))
```
// result_begin: markdown
|  Sepal.Length|  Sepal.Width| Species |
|-------------:|------------:|:--------|
|           5.1|          3.5|setosa   |
|           4.9|          3.0|setosa   |
|           4.7|          3.2|setosa   |
// result_end
\caption(The first flowers)
#+end_example

The output is written between the markers as it is, without the =// =
prefix, and the blank lines a printer puts around a table are dropped.
=results=md=, =results=asis= (knitr's name) and =results=raw= (org's) mean
the same. A caption under the closing marker belongs to the table (or
picture, or displayed maths) the results end with, so it stays put when
the block is run again: running it replaces everything between the
markers. The exports write the results as the document's own tables and
text; which block printed them is not kept, so after importing a document
back, running that block adds a fresh copy of its results.

** Programs in a terminal

An =exec= block's body is a command line, and running it starts that
program in a terminal inside the block's results -- a prompt, a REPL, a
full-screen program such as =htop=:

#+begin_example
```{exec, rows=14}
htop
```
#+end_example

While it runs, the output card shows its live screen, colours and all, and
both cards carry a stop button. To use it:

| Key                   | Does                                                   |
|-----------------------+--------------------------------------------------------|
| =Enter= (or a click)  | send the keyboard to the program                       |
| =Ctrl-\= =Ctrl-N=     | give the keyboard back to the document                 |
| =C-c C-k=             | stop it (a second time kills it outright)              |

Everything typed goes to the program while it has the keyboard, =Escape=
included, the same as in mep's own terminal. When the program ends -- by
itself, by =q= or =Ctrl-D= from inside, or by being stopped -- its last
screen is written into the results as text, so the document keeps a record
of the session (a full-screen program's last frame, even though it clears
the screen as it leaves). =[stopped]= or its exit status follows when
that is worth knowing.

=rows= sets the terminal's height (16 by default) and =cols= its width
(the text width by default). The program runs through =/bin/sh= in the
document's own directory, so pipes, =&&= and several lines all work. A
shell block does the same with =results=terminal=:

#+begin_example
```{bash, results=terminal}
for i in 1 2 3; do echo $i; sleep 1; done
```
#+end_example

** A program of your own in a terminal

=results=exec= does the same for a block in any language: its body is a
program, which is written out -- and compiled first, for a compiled
language -- exactly as a normal run would, and then run in a terminal in
the results rather than as a batch job. It can prompt, read what you type,
redraw the screen, and be stopped, like an =exec= block:

#+begin_example
```{c, results=exec, rows=8}
#include <stdio.h>
int main(void) {
    char name[64];
    printf("What is your name? ");
    fflush(stdout);
    if (fgets(name, sizeof name, stdin)) printf("Hello, %s", name);
    return 0;
}
```
#+end_example

The language's own options still apply: =flags= and =libs= go to the
compiler, =cmdline= to the program. When the compile fails, its errors
become the results and nothing runs. The source and the program itself are
temporary files, deleted once it ends. (A language whose client reads its
script on standard input, such as SQL, has no program to run this way.)

** A program's window in the document

An =exec-gui= block starts a program that opens a window, and shows that
window inside the block's results -- live, where the output would be:

#+begin_example
```{exec-gui, rows=12}
xclock -update 1
```
#+end_example

=results=exec-gui= does the same for a program written in the block, in
any language (compiled first when the language is), exactly as
=results=exec= does for a terminal program:

#+begin_example
```{python, results=exec-gui, rows=14}
import tkinter as tk
root = tk.Tk()
tk.Button(root, text="Quit", command=root.destroy).pack()
root.mainloop()
```
#+end_example

The window keeps to the block: it scrolls with the document, is cut off at
the pane's edges, and is hidden while its block is off screen or another
buffer is shown. =rows= sets its height (20 rows by default) and =cols= its
width (the text width by default).

| Key                     | Does                                                  |
|-------------------------+-------------------------------------------------------|
| =Enter= (or a click)    | send the keyboard and mouse to the program            |
| =Ctrl-\=                | give them back to the document                        |
| a click outside it      | the same                                              |
| =C-c C-k= (or the stop button) | ask it to close; again to stop it, a third time to kill it |

Until you hand it the keyboard, the document keeps it: typing with the
mouse resting over the program still edits the text. When the program ends
-- closed from inside, or stopped -- its last picture is saved as a PNG
beside the document (=file== names it; otherwise it is called after the
document and the block) and becomes the results, followed by anything the
program printed, and its exit status when that was not 0. A program that
opens no window within 20 seconds is still running (the block says so, and
still takes one if it comes later), and the stop key ends it. Programs are
tied to mep: when mep exits, however it exits, they close too.

This needs mep running on X11 (which includes XWayland). The program is
started with its toolkit pointed at X11 (=GDK_BACKEND=x11=,
=QT_QPA_PLATFORM=xcb=, =SDL_VIDEODRIVER=x11=), so GTK, Qt and SDL programs
open their windows where mep can take them. Elsewhere the block says why it
cannot run.

Blocks run through the same language table org babel uses, so every
language org can run works here (=bash=, =python=, =r=, =c=, =cpp=,
=julia=, ...), and so do babel's header options such as =cmdline= and
=stdin=. =mep-lua= runs inside mep itself and returns its values. Blocks
run in the document's own directory.

** Web pages and apps

=results=web= shows what a block makes as a live web page, in a browser
window inside the block's results -- a d3 graphic you can hover, a Shiny
app you can drive. An =html= block is the page itself:

#+begin_example
```{html, results=web, rows=12, file="figs/scatter.png"}
<script src="js/d3.v7.min.js"></script>
<svg width="600" height="300"></svg>
<script> d3.select("svg").append("circle").attr("cx", 50).attr("cy", 50).attr("r", 20) </script>
```
#+end_example

Any other block is a program that serves a page, opened at the first
=http://= address it prints -- a Shiny app prints =Listening on
http://127.0.0.1:...= when it is ready:

#+begin_example
```{r, results=web, rows=16, file="figs/app.png"}
library(shiny)
ui <- fluidPage(sliderInput("n", "Points", 10, 500, 100), plotOutput("p"))
server <- function(input, output) output$p <- renderPlot(plot(rnorm(input$n)))
runApp(shinyApp(ui, server), launch.browser = FALSE)
```
#+end_example

=C-c C-c= starts it, and =C-c C-k= stops it -- for an app, its server
too. The mouse reaches the page directly (hovering, clicking and dragging
just work), while the keyboard stays with mep even with the mouse over
the page; =Enter= on the block (or the page taking it, for a text field)
hands it the keyboard, and =Ctrl-\= or a click outside takes it back. Stopping keeps a picture of the page as the block's results (at
=file==, else beside the document), and that picture is what the slides,
PDF and Office exports show until it runs again; an HTML export embeds an
=html= block's page itself, live. =rows== sets its height. The page is
written beside the document, so the paths it names (a script, a picture)
are the document's. The browser is the first of =chromium=,
=chromium-browser=, =google-chrome= or =brave-browser= on =PATH= (or
=$MEP_WEB_BROWSER=), and an app's language needs whatever it uses (Shiny
for R). In a presentation (=<leader>kp=), a slide's web pages and apps start by
themselves when the slide is shown and run live on it, code hidden or
not; they keep running while other slides show, and stop (each leaving
its picture as its results) when the presentation ends. =C-c C-c= on a
slide stops or restarts them.

* Images and tables

#+begin_example
\image(./figures/plot.png)
\caption(A caption, with *formatting*)
\alttext(What the image shows)

| Left | Centre | Right |
| :--- | :----: | ----: |
| a    |   b    |     1 |
\caption(
  A longer table caption, its parentheses
  on lines of their own
)
#+end_example

=\caption= and =\alttext= are optional and go on the lines directly after
the image, table, display maths or code block they describe. Either can
run over several lines, with its parentheses wherever suits, up to the next
blank line; the line breaks read as spaces. Images are drawn in the buffer.

Figures (images, and code blocks that drew one) and tables are numbered:
a caption reads "Figure 2: ..." or "Table 1: ..." in the editor and in
the export alike. In the editor a caption is wrapped to the text width
(=:set textwidth=, 80 by default) and centred under a figure; its source
comes back while the cursor is on it. An alt text is for readers who cannot
see the page, so it takes no room on it: its lines are hidden, and while the
cursor is on the block it describes it shows in a popup just under the
block (an inline formula's while the cursor is in the formula) -- in the
presentation view too (=n= puts a cursor on the slide). Move onto its own line to
see and edit its source, which also stays on one line: a long one slides
sideways to keep the cursor in view rather than wrapping.

GitHub-flavoured Markdown tables work as they are. After a header row
and a delimiter row with as many cells, the outer pipes are optional, and
=\|= is a pipe inside a cell:

#+begin_example
Species    | Petal length | Petal width
:--------- | -----------: | ----------:
setosa     |         1.46 |        0.25
versicolor |         4.26 |        1.33
#+end_example

Without that delimiter row a line needs a pipe at both ends to be a
table row, so prose with a =|= in it stays prose.

Tables are drawn as a grid: an outline, a shaded header and striped rows.
The pipes don't need to line up in the file, because mep lines the columns
up when drawing, without changing the text. Colons in the separator row
align a column left (=:--=), right (=--:=) or centre (=:-:=). The table
under the cursor shows its raw text.

A cell holding only an image puts that picture in the table:

#+begin_example
| \image(./figs/setosa.jpg) | \image(./figs/versicolor.jpg) |
| ~Iris setosa~             | ~Iris versicolor~             |
#+end_example

In the editor the picture columns share the text width that the other
columns leave (at most half of it each), and the row gets taller to fit
the tallest picture. When the cursor is on that row, the pictures stay
above its raw text. The export puts an =<img>= in the cell. A cell with
anything else next to the image is plain text.

* Accessibility

A document is also read by people who cannot see it -- through a screen
reader, which speaks the text and has to be told what a picture shows, how
a formula is said and which cells of a table are its headers. mepml has a
place for each of these, and every export carries them:

#+begin_example
//? Title: Growth of squares
//? Lang: en-GB

\image(./figures/plot.png)
\caption(Squares of the first ten numbers)
\alttext(A curve rising from 1 at x = 1 to 100 at x = 10)

\image(./figures/ornament.png)
\alttext()

The area is \(x^2\)\alttext(x squared), and in general
$$
  \sum_{k=1}^{n} k = \frac{n(n+1)}{2}
$$
\alttext(The sum of k from 1 to n equals n times n plus 1, over 2)

| Side | Area |
| ---- | ---- |
| 2    | 4    |
| 3    | 9    |
\caption(Areas)
\alttext(The area of a square for sides 2 and 3)
#+end_example

| Write                         | For                                                              |
|-------------------------------+------------------------------------------------------------------|
| =//? Title:=, =//? Lang:=     | the document's title and language (=en=, =en-GB=, =fr= ...): what a screen reader announces, and the voice it reads in |
| =\alttext(text)= under a figure | the text read in the picture's place (an =\image=, or the plot a code block drew) |
| =\alttext()= under a figure   | nothing to read: the picture only decorates, and is skipped       |
| =\alttext(text)= on maths     | how the formula is said aloud; without one mep says the TeX itself ("theta hat 1 equals a over b"), which is right for most formulas and worth overriding where it is not |
| =\alttext(text)= under a table | what the table shows, read before its cells                      |
| a table's header row          | (the row above its separator line) heads the columns: each cell is read under its header |
| =\caption(text)=              | read with what it captions                                        |

What each export does with them:

| Export              | Carries                                                                |
|---------------------+------------------------------------------------------------------------|
| PDF (and Beamer)    | a *tagged* PDF: the whole structure (headings, paragraphs, lists, tables with header cells, figures, formulas), alt text as =/Alt=, a table's as its =/Summary=, decoration and page numbers as artifacts, the title and language |
| HTML                | =lang=, =alt= (=alt=""= + =role="presentation"= for decoration), =role="math"= + =aria-label=, =aria-description= on a table, =<th scope="col">= |
| Word (=.docx=)      | picture descriptions, "decorative" pictures, the table's description, repeated header rows, the language |
| Writer (=.odt=)     | the same, in ODF's own terms                                           |
| PowerPoint, Impress | picture descriptions                                                   |
| Markdown, Org       | a picture's alt text, the language                                     |

Word and Writer have no place for a formula's alt text (they read the
formula itself), nor Markdown and Org for a table's.

To see what a screen reader will get -- of the document you are writing or
of any export -- use these on a mepml buffer, a PDF, a web page or an
office document:

| Command              | Shows                                                              |
|----------------------+--------------------------------------------------------------------|
| =:A11yRead=          | how it reads, line by line: figures as their alt text, tables cell by cell under their headers, decoration left out |
| =:A11yTree=          | its structure: headings, lists, tables, figures and their alt text |
| =:A11yCheck=         | what is missing: a figure with no alt text, a table with no header row, no title, no language, a skipped heading level ... |
| =:A11ySpeak= [stop]  | reads it aloud, when =espeak-ng= or =espeak= is installed          |

Each opens in a pane beside the document; =Enter= on a line goes to what it
is about. The language server marks a figure with no =\alttext= and a table
with no header row as hints while you write, and from a shell
=mep-mepml a11y FILE [read|tree|check]= prints the same for a =.mepml=,
=.pdf=, =.html=, =.docx= or =.odt= file -- so an export can be compared
with its source (=check= exits 1 when a figure has no alt text or a PDF is
not tagged).

A PDF made by anything but tectonic (XeTeX) from the exported =.tex= is the
same document without the tags.

* Citations, imports and contents

#+begin_example
\citation(asdf1,
  author = author1,
  title = {The title},
  year = 1999
)
@article{knuth84, author = {Donald E. Knuth}, year = 1984}
\import(refs.bib)
\toc
\bibliography
#+end_example

A citation is =\citation(key, fields)=, or an ordinary BibTeX entry, so
an existing =.bib= file can be imported. =\import(path)= pulls in
another file (relative to this one); its content, citations and options
join this document. =\toc= is a table of contents and
=\bibliography= lists every cited entry, in the order first cited
(=@printbibliography=, its oldest name, still works).

Every directive is written =\name(...)=, or bare (=\toc=). The older
=@name{...}= spelling (=@image{path}=, =@caption{text}=,
=@citation{key}{fields}=, =@toc=, ...) still works, except for the
abstract; BibTeX entries keep their =@article{...}= form.

Both are drawn in the buffer: =\toc= as the document's headings, indented
by depth (click one to jump to it), and =\bibliography= as the numbered
reference list, titles in italics, wrapped to the text width. Like an
image, the block stays drawn when the cursor is on it; toggle concealment
(=<leader>km=) to see the directive itself.

The cursor moves through either block a line at a time. =j= and =k= step
from entry to entry, with the current one highlighted, and past the first
or last line they move on to the text around it. On a contents entry,
=Enter= jumps to its heading (=C-o= comes back).

* Commands of your own

=\define= makes a command. Its first argument is the command's name and
its parameters, written the way a call is written, and the rest is the
template the call is replaced by:

#+begin_example
\define(today, 29 September 2026)
\define(term(word, meaning), *#word* (#meaning))

Written \today(); a \term(monad, a monoid in the category of endofunctors).
#+end_example

In the template, =#word= (or =#{word}=, when a letter follows it, or
=#1=, =#2= ... by position) is replaced by that argument, and =##= is a
=#=. A =#= before anything else stays as it is, so an HTML colour such as
=#2c7fb8= is safe. Arguments end at the call's first commas, one per
parameter but the last, and the last argument takes the rest of the call,
commas and all, as the text of =\color(red, text)= does. A command without
parameters is called with empty parentheses: =\today()=. A template may
run over any number of lines, blank ones included, and may call other
commands (a command that calls itself is stopped after 64 levels).

A call alone on its lines is a block: =\glossary(...)= may hold several
paragraphs, split by blank lines, like =\abstract(...)=. A call inside a
paragraph is expanded in place. Code blocks, maths and =`verbatim`= text
are never expanded.

** Choosing by export

=\when(formats, text)= keeps its text only in the exports it names, and an
=\otherwise(text)= right after one or more =\when(...)= keeps its text when
none of them matched:

#+begin_example
This page is \when(html, interactive) \when(pdf, printable) \otherwise(plain).
#+end_example

A format list is names separated by spaces or =|=: =\when(tex pdf, ...)=.
=!html= means every export but HTML, and =*= means every export. Each
export answers to several names, most specific first:

| Export                    | Names                                        |
|---------------------------+----------------------------------------------|
| HTML                      | =html=, and =slides= for a presentation     |
| LaTeX                     | =tex=, =latex=                               |
| PDF                       | =pdf=, =tex=, =latex=                        |
| Beamer (and a presentation's =tex=, =pdf=) | =beamer=, =tex=, =latex=, =slides=, and =pdf= for the PDF |
| Word                      | =docx=, =word=, =office=                     |
| OpenDocument text         | =odt=, =office=                              |
| PowerPoint                | =pptx=, =powerpoint=, =office=, =slides=     |
| Impress                   | =odp=, =impress=, =office=, =slides=         |
| Markdown, Org, RTF, text  | =md= (=markdown=), =org=, =rtf=, =txt= (=text=) |
| Presenting in the editor  | =present=, =slides=                          |

The language server flags a name no export has, but it still works: it
simply never matches.

** Writing an export's own markup

=\raw(formats, text)= writes its text, exactly as it is, into the exports
it names and leaves it out of every other: HTML for =html=, LaTeX for
=tex=, =pdf= and =beamer=, Markdown for =md=, and so on. On lines of its
own it is a block, and the text may run over several lines:

#+begin_example
\raw(html, <kbd>Ctrl</kbd>)
\raw(tex pdf,
\clearpage
)
#+end_example

The text's parentheses must balance. The slide decks (=pptx=, =odp=) take
no raw markup. Use =\when= to give them ordinary mepml instead.

** Putting it together: a glossary entry

Definitions, theorems and the like are built in (see /Boxes/); a command
of your own suits anything else that should look a particular way in
each export, such as a glossary entry:

#+begin_example
\define(glossary(term, body),
\when(html,
\raw(html, <div class="glossary" style="border-left: 4px solid #2c7fb8; padding: .5em 1em">)
\raw(html, <b>#term</b>)

#body

\raw(html, </div>)
)
\when(beamer,
\raw(beamer, \begin{block}{#term})

#body

\raw(beamer, \end{block})
)
\otherwise(
*#term.* #body
)
)

\glossary(Monad, A monoid in the category of endofunctors.)
#+end_example

The HTML export draws a box, the Beamer deck a titled block, and every
other export a paragraph that opens with the term in bold. The =#term=
inside =\raw= goes in as written, so keep it to plain text and TeX maths.
Put commands in a file of their own and =//? Import:= it to share them
between documents: commands defined in an imported file work in the
document that imports it.

The editor shows a document as written. A =\define= is drawn as code and
a call keeps its name, so the source stays editable, and the exports are
where the commands are expanded. The language server completes the
commands you define (and export names inside =\when(= and =\raw(=), shows
a command's template when you hover over a call, and flags calls of
commands that are not defined and calls missing an argument.

* Style sheets

What a document /is/ and how it /looks/ are separate. mepml says the
first -- this is a heading, that a definition -- and a style sheet says
the second. mep's own look is a style sheet too
(=assets/mepml/default.mepss=), so everything it draws can be changed
from a file.

#+begin_example
//? Style: paper.mepss
#+end_example

names a sheet for the document, a path relative to the document. Several
=Style:= lines apply in order, a file brought in with =//? Import:=
contributes its sheets ahead of the document's own, and a sheet in
=~/.config/mep/mepml.mepss= applies to every document. Later sheets win.
Saving a sheet restyles the documents that use it at once.

A sheet can also be written in the document, as a =\raw= block for the
format =style= (which no export has, so the block is in none of them):

#+begin_example
\raw(style,
box[kind=axiom] { --accent: #e07a00; }
.term { color: #00a080; font-weight: bold; }
)
#+end_example

It applies after the sheets the header names.

A sheet is a list of rules in CSS's syntax:

#+begin_example
/* Definitions in green, under another name. */
box[kind=definition]        { --accent: #2e8b57; }
box[kind=definition]::label { content: "Def."; }

heading[level=1]  { font-size: 1.8; color: theme(Blue, #0b5cad); }
verbatim          { color: #d95f0e; font-weight: bold; }
list-item::marker { content: "→"; }

@media present { heading[level=1] { font-size: 2.4; } }
#+end_example

- A selector names an element (=heading=, =paragraph=, =bold=, =italic=,
  =verbatim=, =link=, =math=, =list-item=, =table-cell=, =code=,
  =results=, =box=, =callout=, =slide=, =abstract=, =meta= ...), narrows
  it by attribute (=heading[level=2]=, =box[kind=proof]=,
  =callout[kind=warning]=, =list-item[checked=true]=,
  =meta[key=title]=), by what it is inside (=slide heading=,
  =box > paragraph=), and picks a part of it with =::=: =::label= (a
  box's "Definition", a callout's badge, "Slide 3"), =::title=,
  =::marker= (a list's bullet), =::end= (a proof's tombstone),
  =::markup= (the syntax characters on a line shown as source),
  =::header= (a code block's title band), =::option= (its option chips),
  =::button= (its run, stop and fold controls),
  =::rule= (a table's grid lines). =:active= is the block the
  cursor is in.
- =.name= selects text given that name in the document,
  =\class(name, text)=: a =\class(term, group)= is styled by
  =.term { ... }=, in the editor and in the HTML and PDF exports. It has
  no look of its own.
- Properties: =color=, =background=, =font-weight=, =font-style=,
  =text-decoration= (=underline=, =line-through=, =none=),
  =text-decoration-color=, =font-size= (a multiple of the surrounding
  text, or =14pt=), =font-family= (=serif=, =sans=, =mono=),
  =vertical-align=, =text-align=, =content= (generated text; =%n= is the
  element's number and =%k= its kind), =border-color= and
  =border-left-color=.
- In the editor =text-align= sets a heading and running text (a
  paragraph, a list, a callout, the abstract) centred or flush right line
  by line; the line the cursor is on stays where you type it.
  =text-decoration= draws a rule under or through a heading too.
- Generated text is a part's =content=: a list's marker, a box's label
  and end mark, a callout's badge (=" %k "=), "Abstract", a slide's
  "Slide %n", and the word before a caption's number
  (=caption[of=figure]::label { content: "Fig. %n"; }=). The editor
  draws any character its text face has; one it lacks shows as =?=.
- Colours are =#rrggbb=, a colour name, =theme(Group, #fallback)= -- the
  colour your editor theme gives =Group= (=Blue=, =Comment=, =Accent=
  ...), and the fallback in an export -- or =fade(colour, 0.2)=. =none=
  removes one. A custom property (=--accent: ...;=, read back with
  =var(--accent)=) is inherited, which is how one line recolours a box's
  label, rule and paper together.
- =@media= limits rules to a renderer: =editor=, =source= (a line shown
  as its source, like the cursor's), =present= (the presentation view),
  and the export names =\when()= takes.

An unknown property or a value a property cannot take drops that one
declaration, never the sheet. In a =.mepss= file the language server
underlines both, along with selectors that name an element or a part mepml
has none of, and completes element names, =[attributes]= and their values,
=::parts=, property names and each property's values (colour functions,
theme groups, colour names) and =@media= tags; hover explains a property,
a part or a function. =docs/mepml-spec/= is the full
specification -- the elements, the language and what a renderer must do
-- and =examples/mepml-styles/= has three complete sheets to start from
(a quiet one, a loud one, and one for presenting a deck). =test.mepml=,
the document that shows everything mepml can do, names =test.mepss=
beside it.
From a shell, =mep-mepml style FILE= prints the style every element of a
document computes to, and =mep-mepml tree FILE= its structure as JSON.

While presenting (=<leader>kp=) a page is its slide: =slide heading= and
=slide box= select on it, the slide's =background= is the page's paper
and its =color= the page's text. The title page is =slide[title]=, with
the header's =meta[key=title]=, =meta[key=subtitle]= and
=meta[key=author]= on it:

#+begin_example
@media present {
  slide        { background: #0b1d33; color: #e6edf5; }
  slide[title] { background: #12345a; }
  slide[title] meta[key=title] { color: #ffd000; font-size: 2.4; }
  slide heading[level=1]       { font-size: 2.2; }
}
#+end_example

The exports take the same sheets, each as far as its format goes, over
its own built-in look (so a document with no sheet exports exactly as
before). Use =@media= to give paper its own colours -- =html=, =print=
(PDF, Word, Writer, RTF), =slides=, or a single format's name:

#+begin_example
heading { color: #ffd000; }                    /* on the editor's dark page */
@media html, print { heading { color: #8a5a2b; } }
#+end_example

- *HTML* (and the HTML slideshow): every rule that has something to
  select on the page, written into it as CSS -- colours, weights, sizes,
  faces, alignment, list markers, box and callout accents and labels.
- *PDF and LaTeX* (and Beamer): colour, weight and slant of headings,
  paragraphs and inline markup; a box's colours, label and end mark.
- *Word and Writer*: the same colour, weight and slant, kept as named
  character styles so the text reads back into mepml as it was written;
  a class's look; a box's label and colours.
- *PowerPoint and Impress*: colour, weight and slant of inline markup; a
  box's label and colour.
- *RTF*: a box's label and colours.
- *Markdown, plain text*: a box's label.

A =theme(Group)= colour needs its fallback (=theme(Blue, #0b5cad)=) to
reach an export, which has no editor theme to ask.

* Exporting and importing

The play button in the pane's header (or =gr=, or =<leader>rr=) saves the
document, exports it, and opens the result in a split on the right -- an
HTML page, a PDF, a Word document -- refreshing that split on the next run
instead of opening another. It exports HTML unless the header names a
format:

#+begin_example
//? Title: My report
//? Export: pdf
#+end_example

Any format the table below lists works (=html=, =pdf=, =beamer=, =docx=, =odt=,
=rtf=, =md=, =org=, =tex=, =txt=, =pptx=, =odp=). =Export:= is singular: =//? Exports:=
is a different key, choosing which parts of each code block the exports
show. =beamer= is the =\slide= blocks as a Beamer PDF whatever the
document's =Type=, and a slide-deck PDF opens sized to show a whole slide.

=<leader>ke= (or =:MepmlExport=) exports the document beside its file,
=notes.mepml= becoming =notes.docx= and so on. Imports are expanded,
commands are expanded for the format (see Commands of your own), and
pictures are embedded where the format can hold them:

| Format                | Written as                                                  |
|-----------------------+-------------------------------------------------------------|
| HTML                  | a standalone page (=<leader>ko= opens it)                    |
| PDF                   | the LaTeX export, compiled by =tectonic= in the background  |
| Beamer (=beamer=)     | the slides as a Beamer deck, compiled to PDF the same way   |
| Word (=.docx=)        | named styles, real lists, footnotes, links, embedded images |
| OpenDocument (=.odt=) | the same, for LibreOffice                                   |
| Rich Text (=.rtf=)    | the same, with a stylesheet and list tables                 |
| Markdown (=.md=)      | GitHub/pandoc Markdown: alerts, fenced code, footnotes      |
| Org (=.org=)          | org-mode: =#+begin_src= blocks, =[cite:@key]=, footnotes     |
| LaTeX (=.tex=)        | a standalone article                                        |
| Plain text (=.txt=)   | the text, tables lined up, references listed                |
| PowerPoint (=.pptx=)  | the slides as a deck (see Presentations, above)            |
| Impress (=.odp=)      | the same, for LibreOffice                                   |

=<leader>ki= (or =:MepmlImport file=) goes the other way: an HTML,
Markdown, Org, RTF, Word, OpenDocument or plain-text file becomes a
=.mepml= beside it, which is then opened (you are asked before an
existing one is replaced). Pictures inside a Word, OpenDocument or RTF
file are saved to a =file_media= directory next to it.

A round trip keeps the document. Headings, paragraphs, every kind of
inline formatting, links, footnotes, maths, code blocks with their
results, figures and tables with captions, lists, callouts, the abstract,
the table of contents and the bibliography all come back. Word, OpenDocument and RTF
also carry what they have no place for as custom document properties:
the =//?= options, each code block's language and options, and the
bibliography's entries. Markdown and Org carry the bibliography in a
comment. What a format cannot say is lost or approximated. For example,
Org has one strike-through for both =-struck-= and =!deleted!= text, and
Word shows maths as its TeX source.

Documents written by other programs import by their styles (Heading 1,
Title, Quote, Source Code, Caption ...), so a typical Word or LibreOffice
document keeps its structure. Word equations and LibreOffice formulas
become TeX.

The same converters are a command-line tool:

#+begin_src sh
mep-mepml convert notes.mepml notes.docx   # any format to any format,
mep-mepml convert report.docx report.mepml # by way of mepml
#+end_src

and Lua functions: =mep.mepml_export(path)= writes the current buffer in
the format =path= names, =mep.mepml_export_as(fmt)= also does PDF, and
=mep.mepml_import(in, out)= writes =out=.

* Language server

mepml has a language server of its own, =mep-mepml-lsp=, which attaches
to a =.mepml= file by itself. It checks citations, heading links, pictures
and imports across the document, completes directives, citation keys,
colours and paths, renames citation keys and headings, and lines tables
up. See [[file:mepml-lsp.html][The mepml language server]].

* Tree-sitter grammar

mepml has its own tree-sitter grammar in =grammars/tree-sitter-mepml= in
the mep repository. mep uses it to colour a document's structure: the
metadata keys and values, code block languages and options, citation
fields, and callout kinds. Other editors can use it too. It comes with
highlight, fold and injection queries (a code block's body is highlighted
in its own language). Headings nest into sections, so any tree-sitter
client can fold and outline a document. =just mepml-grammar= regenerates
the parser and runs its tests.
