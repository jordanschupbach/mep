* What mod1 is

=mod1= is a modifier key -- =Alt= by default -- carrying a layer of window
management commands. Unlike =Ctrl-W=, these work in *every mode*, so you can
move between panes without leaving Insert mode first.

#+begin_src lua
mep.set_mod1('super')   -- 'alt' (default), 'ctrl', 'shift', 'super'/'cmd'/'meta'
#+end_src

* Splitting and focusing

| Key             | Does                                        |
|-----------------+---------------------------------------------|
| =mod1+s=        | split horizontally                          |
| =mod1+v=        | split vertically                            |
| =mod1+h j k l=  | focus the pane left / down / up / right     |
| =mod1+d=        | close the pane's active buffer tab          |
| =mod1+Enter=    | run the cell under the cursor and insert a new one (notebooks) |

Focus movement is spatial, using the same overlap-then-distance heuristic as
=Ctrl-W hjkl=. It is a no-op when there is no pane that way.

* Hiding the border

=mod1+b= (=:MepBorder=) hides the menu bar, the tab bar and the status line
together, leaving only the panes; pressing it again brings all three back.
Unlike the rest of this layer it only works in Normal mode -- elsewhere the
key is left alone. =<leader>um=, =<leader>ub= and =<leader>us= toggle the
three one at a time; the menu bar alone is also on =mod1+Shift+m= (=:Menu=),
which works in any mode.

* Hiding the pane bars

=mod1+t= (=:MepPaneBar=, =<leader>up=) hides the header strip above every
pane -- the filename/breadcrumb, the buffer tabs and the split and close
buttons -- so each pane's buffer runs right up to its top edge; pressing it
again brings them all back. It applies to every pane at once, works in any
mode, and is reachable from Lua as =mep.panebar_toggle()=,
=mep.panebar_set_visible(on)= and =mep.panebar_visible()=.

* Hiding all the sidebars

=mod1+Shift+s= (=:MepSidebars=, also the Window menu's /Toggle Sidebars/)
hides every sidebar at once -- the file tree, git, Structure, Tests, Todo,
Buffers and the rest, whether they're open as panes or docked -- so the
document panes get the whole window. Press it again and each comes back
exactly where it was, at the size it was, even if you split or closed
document panes in the meantime. It works in any mode, and in every tab.

Reopening one sidebar while they're hidden (its own key or command) brings
just that one back, in its old place. A tab that has nothing but sidebar
panes keeps them, so there's always something on screen. From Lua:
=mep.sidebars_toggle()= (false when there was nothing to hide) and
=mep.sidebars_hidden()=.

* Hiding the window title bar (macOS)

On macOS mep's window starts without a title bar -- no close, minimize and
zoom buttons, the content running right up to the top edge, like iTerm2's
"No Title Bar" style. The Window menu's /Toggle Title Bar/ item,
=:MepTitleBar= and =<leader>uw= bring it back (and take it away again).
The choice is saved with the other settings, so it sticks across restarts;
it is also the /Window title bar/ row of =:MepSettings=.

With no title bar there is nothing to drag, so =Ctrl+Cmd= and a drag
anywhere in the window moves it. From Lua: =mep.titlebar_toggle()=,
=mep.titlebar_set_visible(on)= and =mep.titlebar_visible()=. On other
platforms the window manager owns the title bar and these do nothing.

* Resizing

=mod1+Shift+h j k l= moves the split boundary between the current pane and
its neighbour.

It grows against a neighbour on that side if there is one, and otherwise
shrinks against whichever neighbour it does have on that axis. That is what
makes opposite keys always do opposite things. A pane alone on an axis does
not move.

This is a two-way boundary drag rather than Vim's full window-layout resize
algorithm -- a deliberate simplification.

* Rearranging

| Key                | Does                                              |
|--------------------+---------------------------------------------------|
| =mod1+Ctrl+h j k l= | move this pane's active buffer tab into the neighbouring pane |
| =mod1+Ctrl+Shift+h j k l= | swap this whole pane with the neighbouring one |
| =mod1+m=           | maximize this pane, or restore the previous layout |

Moving the last buffer tab out of a pane closes that pane.

Swapping exchanges the two panes' places in the layout -- each takes over
the other's slot and size -- and focus stays on the pane that moved, so the
cursor travels with it and the same chord can be pressed again to keep
walking that pane across the layout. =mod1+Ctrl+Shift+j= sends the pane you
are in below the one that was under it.

=mod1+m= shrinks every other pane to the minimum the resize keys stop at.
Pressing it again restores the layout from before; pressing it in a
*different* pane while one is maximized maximizes that one instead.

* Buffer tabs within a pane

| Key                  | Does                                            |
|----------------------+-------------------------------------------------|
| =mod1+Tab=           | next buffer tab in this pane                    |
| =mod1+Shift+Tab=     | previous buffer tab                             |
| =mod1+Ctrl+Tab=      | move this buffer one place along the pane's tab bar |
| =mod1+Ctrl+Shift+Tab= | move it one place back                         |

The Ctrl pair reorders the tab strip rather than stepping through it: the
buffer you are in stays the one you are in, it just changes place (wrapping
around at either end), which is the same "move the thing I'm looking at"
relationship =mod1+Ctrl+h j k l= has to =mod1+h j k l=.

* Inside a sidebar

The same keys mean something related when a sidebar is focused:

| Key                | Does                                          |
|--------------------+-----------------------------------------------|
| =mod1+j= =mod1+k=  | step focus between stacked sidebars           |
| =mod1+Shift+j/k=   | re-split the boundary between two of them     |
| =mod1+Ctrl+j/k=    | swap this sidebar with the one above or below |
| =mod1+m=           | pop the sidebar out into a large centred float |

Swapping keeps the sidebar focused, so the cursor travels with it.

* Other modifiers

| Key                        | Does                        |
|----------------------------+-----------------------------|
| =Ctrl-Alt-]= =Ctrl-Alt-[=  | next / previous workspace   |
| =Alt-1= .. =Alt-9=         | jump to the Nth workspace   |
| =Ctrl+Shift+== =Ctrl+Shift+-= | grow / shrink the font   |

* Rebinding

Every default above is a =mep.map_mod1()= call made at startup, so any of
them can be replaced or removed from =init.lua=:

#+begin_src lua
mep.map_mod1('h', function() mep.nav_pane('left') end)
mep.map_mod1('S-l', mep.some_function)   -- mod1+Shift+l
mep.map_mod1('C-j', mep.other_function)  -- mod1+Ctrl+j
#+end_src

A bare letter is =mod1+letter=; =S-=, =C-= and =C-S-= prefixes add Shift,
Ctrl, and both. =Tab= takes the same prefixes, and =CR= / =S-CR= are also
accepted.

The functions behind the defaults are callable directly:
=mep.nav_pane(dir)=, =mep.resize_pane(dir, step)=,
=mep.pane_move_buffer(dir)=, =mep.swap_pane(dir)=,
=mep.pane_reorder_buffer(delta)=, =mep.pane_close_buffer()= and
=mep.pane_maximize_toggle()=.
