The Octave language server

What it is

Octave (and MATLAB) files get a language server of their own, mep-octave-lsp, built and shipped with mep. Open a .m file and it attaches by itself -- nothing to install, and nothing in the file is ever run. It knows Octave 11: its 1,763 built-in and library functions, each with the usage lines from Octave's own help.

The same binary is a command-line linter; see Linting from the command line below.

The same errors as Octave

Its reader follows Octave's own lexer and parser (lex.ll and oct-parse.yy) rule for rule, so a syntax error is reported where Octave reports it, in Octave's words:

parse error: syntax error near line 3, column 10
'endfunction' command matched by 'endif'
x: invalid use of symbol as both variable and command
duplicate subfunction or nested function name

That includes the checks Octave makes after parsing: a command-syntax call to a name the same function assigns (x -1 after x = 2), mismatched end keywords, a classdef not named after its file, duplicate functions, parameters and outputs.

This is checked against Octave itself (just octave-parse-check): each of the 6,676 files of Octave's own scripts and tests and of 30 Octave Forge packages, and five damaged copies of each (a slice deleted or duplicated, a keyword, bracket or quote inserted), goes through Octave's __parse_file__ and through the server. On 113,492 files the two agree on every verdict, message, line and column.

Calibration

  • unused-local leaves alone parameters, outputs, global and loop variables, varargin=/=varargout and ans, scripts (their variables live on in the workspace), and any function that can reach its variables by other means: one that calls eval, evalin, evalc, assignin, load, clear, inputname, exist or who (and the like), and the parent of a nested function or anonymous function that does.
  • A %#ok on the line (MATLAB's code-analyzer pragma) silences the lints there.

Run over the corpus: no file Octave accepts gets an error or a false warning. The 22 syntax errors are the 22 files Octave itself rejects (its own deliberate bug-50014 test cases, a configure template, a few packages using syntax Octave 11 no longer takes). The 13 duplicate-case warnings are real repeated labels (in Octave's __unimplemented__.m and the io package), and the 8 unreachable statements are code after a return. unused-local marks 1,086 variables in 666 files; the samples read were all values never used, most of them outputs of a multiple assignment ([m, n] = size (x)) that could be ~.

What else it does

  • Hover shows an Octave function's usage lines (zeros, cellfun, regexprep) and, on the file's own functions, their signature.
  • Completion offers the variables of the function at the cursor (a nested function sees its parent's), the file's functions, Octave's keywords and functions, and after a . the field names the file uses.
  • Signature help for Octave's functions (from their usage lines) and the file's own, with the active argument.
  • Go to definition, references and rename for variables -- per function, following nested functions into their parent -- and for the file's functions.
  • The outline lists functions and nested functions, and a classdef's properties, methods and events.
  • Folding covers functions, every block (if, loops, switch, try, unwind_protect), classdef sections, block comments and runs of comment lines.
  • Formatting is mep's own Octave formatter, the one gf runs (MISS_HIT's mh_style layout). Only the lines that change are edited. See Formatting.

While a file is broken, completion and navigation keep working on the rest of it: the server re-reads it with the offending line set aside.

Help text from other files

Hover and signature help show a function's help text, found as Octave finds it: the comment block above the function line (copyright blocks skipped), a function file's leading block, or the block right below. Texinfo help is rendered as Octave's help shows it. A function the file does not define is looked up as NAME.m (or +pkg/NAME.m) in the file's directory, the directories its literal addpath ('dir') calls name, the workspace and MEP_OCTAVE_PATH.

Classes and packages

A classdef file's help is the comment block after the classdef line (not the constructor's), followed by the class's properties and methods unless the help text lists them already. A method's help is the block after its function line inside methods ... end. pkg.Class is +pkg/Class.m, and pkg.Class.method is a method of that class or of its superclasses. Properties in Hidden or Access blocks are left out.

A variable's class is worked out from the assignments before it, for example df = datamunge.DataFrame (). A call's result is typed from the Output: block in the method's help (the class named after the output variable, as Rosetta writes it). With that:

  • hovering df shows its class;
  • hovering df.select shows DataFrame's select, and chains like df.select (c).sort_by (k) work too;
  • signature help on df.select ( drops the obj parameter;
  • completion after df. lists the instance's methods and properties. After pkg.Class. it lists the static methods, and after pkg. the package's functions, classes and subpackages.

If the receiver's class is unknown, hover shows the first class's method of that name and lists the other classes that have one.

A bare name the file doesn't define is resolved through the file's import pkg.* / import pkg.Name lines first. Otherwise it is the one package member of that name; when several packages have it, hover lists them all.

From the command line

mep-octave-lsp --doc NAME [--path DIR]... [--file FILE]... prints the same help text, for the Octave mode's Help tab. NAME can be any of these:

  • a function;
  • pkg.fn;
  • a class (pkg.Class);
  • a method (pkg.Class.method);
  • a bare package member such as DataFrame. It is resolved through the imports of the --file files. If none matches, it is the unique package member of that name, unless Octave has a function by that name.

Linting from the command line

sh Copy
mep-octave-lsp --lint *.m
cat f.m | mep-octave-lsp --lint -

prints every diagnostic as

f.m:12:5: warning: this case label repeats the one on line 9; only the first is ever taken [duplicate-case]

-- 1-based line and column, then the severity (error, warning, info, hint), the message and the code. It exits 1 if anything printed is an error or a warning, 2 if a file could not be read, and 0 otherwise. With no arguments, mep-octave-lsp is the language server on stdio.

mep-octave-lsp --octave-check FILE... prints what Octave's __parse_file__ would say about each file: ok, or the message with "near line L, column C".
