* What it is

Octave (and MATLAB) files get a language server of their own,
=mep-octave-lsp=, built and shipped with mep. Open a =.m= file and it
attaches by itself -- nothing to install, and nothing in the file is ever
run. It knows Octave 11: its 1,763 built-in and library functions, each with
the usage lines from Octave's own help.

The same binary is a command-line linter; see /Linting from the command line/ below.

* The same errors as Octave

Its reader follows Octave's own lexer and parser (=lex.ll= and
=oct-parse.yy=) rule for rule, so a syntax error is reported where Octave
reports it, in Octave's words:

#+begin_example
parse error: syntax error near line 3, column 10
'endfunction' command matched by 'endif'
x: invalid use of symbol as both variable and command
duplicate subfunction or nested function name
#+end_example

That includes the checks Octave makes after parsing: a command-syntax call
to a name the same function assigns (=x -1= after =x = 2=), mismatched
=end= keywords, a classdef not named after its file, duplicate functions,
parameters and outputs.

This is checked against Octave itself (=just octave-parse-check=): each of
the 6,676 files of Octave's own scripts and tests and of 30 Octave Forge
packages, and five damaged copies of each (a slice deleted or duplicated, a
keyword, bracket or quote inserted), goes through Octave's =__parse_file__=
and through the server. On 113,492 files the two agree on every verdict,
message, line and column.

* What it reports

| Code               | Severity | What it means                                                                  |
|--------------------+----------+--------------------------------------------------------------------------------|
| =syntax-error=     | error    | what Octave's parser says, at the same line and column                          |
| =duplicate-case=   | warning  | a =case= label that repeats an earlier one in the same =switch=: only the first is ever taken |
| =unused-local=     | hint     | a function assigns a variable and never reads it (shown faded)                  |
| =unreachable-code= | hint     | statements after =return=, =break= or =continue= in the same block (faded)      |

** Calibration

- =unused-local= leaves alone parameters, outputs, =global= and loop
  variables, =varargin=/=varargout= and =ans=, scripts (their variables live
  on in the workspace), and any function that can reach its variables by
  other means: one that calls =eval=, =evalin=, =evalc=, =assignin=,
  =load=, =clear=, =inputname=, =exist= or =who= (and the like), and the
  parent of a nested function or anonymous function that does.
- A =%#ok= on the line (MATLAB's code-analyzer pragma) silences the lints
  there.

Run over the corpus: no file Octave accepts gets an error or a false
warning. The 22 syntax errors are the 22 files Octave itself rejects (its
own deliberate =bug-50014= test cases, a configure template, a few
packages using syntax Octave 11 no longer takes). The 13 =duplicate-case=
warnings are real repeated labels (in Octave's =__unimplemented__.m= and the
=io= package), and the 8 unreachable statements are code after a =return=.
=unused-local= marks 1,086 variables in 666 files; the samples read were
all values never used, most of them outputs of a multiple assignment
(=[m, n] = size (x)=) that could be =~=.

* What else it does

- *Hover* shows an Octave function's usage lines (=zeros=, =cellfun=,
  =regexprep=) and, on the file's own functions, their signature.
- *Completion* offers the variables of the function at the cursor (a nested
  function sees its parent's), the file's functions, Octave's keywords and
  functions, and after a =.= the field names the file uses.
- *Signature help* for Octave's functions (from their usage lines) and the
  file's own, with the active argument.
- *Go to definition*, *references* and *rename* for variables -- per
  function, following nested functions into their parent -- and for the
  file's functions.
- The *outline* lists functions and nested functions, and a classdef's
  properties, methods and events.
- *Folding* covers functions, every block (=if=, loops, =switch=,
  =try=, =unwind_protect=), classdef sections, block comments and
  runs of comment lines.
- *Formatting* is mep's own Octave formatter, the one =gf= runs (MISS_HIT's
  =mh_style= layout). Only the lines that change are edited. See
  [[file:formatting.html][Formatting]].

While a file is broken, completion and navigation keep working on the rest
of it: the server re-reads it with the offending line set aside.

* Linting from the command line

#+begin_src sh
mep-octave-lsp --lint *.m
cat f.m | mep-octave-lsp --lint -
#+end_src

prints every diagnostic as

#+begin_example
f.m:12:5: warning: this case label repeats the one on line 9; only the first is ever taken [duplicate-case]
#+end_example

-- 1-based line and column, then the severity (=error=, =warning=, =info=,
=hint=), the message and the code. It exits 1 if anything printed is an
error or a warning, 2 if a file could not be read, and 0 otherwise. With no
arguments, =mep-octave-lsp= is the language server on stdio.

=mep-octave-lsp --octave-check FILE...= prints what Octave's
=__parse_file__= would say about each file: =ok=, or the message with
"near line L, column C".
