Octave mode

Opening it

The language UI toggle (see Language UI modes) in a .m file. The tab becomes an Octave workspace: your file, an interactive octave-cli below it, and panels showing what that session holds.

The console is the stock octave-cli (no GUI), so line editing, history, completion and value display are Octave's own. It starts with mep's environment (OCTAVE_PATH included), and its load path gets:

  • the directory of your file, so functions in sibling .m files resolve;
  • every directory in MEP_OCTAVE_PATH;
  • the --path DIR / -p DIR directories of an octave command in the file's % CMD: line (see Run button), with $(pwd) read as mep's working directory.

Working in it

Key / callDoes
<leader>rrrun the whole file in the console
<leader>rerun the statement at the cursor (or the selection)
ghhelp for the name under the cursor, in the Help panel
mep_help ('name')the same, from the console
mep_view (x)a value -- its disp, class, size and fields -- in Inspect
mep_run (file)run a file the way <leader>rr does

<leader>re finds the top-level statement around the cursor: a whole function, if, for, while, switch, try or unwind_protect block up to its end, or a single line with its ... continuations and open brackets. end inside an index (x(end)) and keywords inside strings and comments do not count.

Neither key pastes your code into the prompt. The code is written to a file in the session directory, named after your file and padded to its line numbers, and run with one source (...) line in the base workspace. Variables it assigns stay in the workspace, and an error names your line. <leader>rr runs the buffer as it is in the editor, unsaved changes included, through mep_run: like Octave's run, it changes to the file's directory for the run and adds it to the load path.

A file with a % CMD: line still runs that line on the Run button, as without the mode.

The panels

PanelShows
Workspacewhos of the base workspace: name, class, size and a short value
Paththe directories added to the load path, and the loaded packages
Inspectmep_view of a value
Helpthe help text of a function

Clicking a Workspace row inspects it. The panels refresh after every command, through an input-event hook that runs while the prompt waits.

Help

mep_help ('name') -- and gh over a name in your file -- first asks Octave: help name shows a .m file's comment block or a built-in's documentation (Texinfo rendered), and which where the function comes from.

When Octave has no help text -- a compiled .oct function without a docstring, or a command-line function -- the Help tab reads the comment blocks of the .m files instead, with mep-octave-lsp --doc (see The Octave language server): NAME.m in the directories on the session's load path, and the functions of the scripts the session ran. A Rosetta-generated Octave binding ships such .m stubs, carrying the C++ library's documentation, next to its .oct functions.

In a .m buffer gh also opens the language server's hover, which shows the same help text without a running session.

Options

lua Copy
mep.opt.octave_ui_cmd = {'octave', '--no-gui'}   -- the console's command
mep.opt.octave_ui_info_share = 0.3               -- the panels' width

A % REPL: nix develop --command octave-cli line in the file overrides octave_ui_cmd for that file. The mode appends =-q --persist --eval "source (...)"=, so the command must accept them, as octave-cli and octave do.
