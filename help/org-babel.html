Executing code blocks

Inserting a block

The </> button in an org buffer's pane header drops down a dozen common languages; picking one writes an empty block at the cursor and puts you on its body line.

KeyDoes
<leader>oipick a language from every one babel knows

:MepOrgInsertBlock is the same picker, and :MepOrgInsertBlock rust skips it for a language you already know you want -- any tag is accepted, listed or not.

A blank line under the cursor becomes the block itself; any other line keeps its text and the block goes in below it. With the cursor already inside a block, the new one lands after that block's #+end_src rather than nesting inside it.

Typing <s and expanding it (see Capture) does the same without the mouse, for a block with no language tag.

Running a block

Put the cursor in a #+begin_src block and press C-c C-c (:MepOrgBabelExecute). The result is written back into the file as a #+RESULTS: block below it.

org Copy
#+begin_src python
print(40 + 2)
#+end_src

#+RESULTS:
: 42

Or click the play button on the block's own card (block cards): same execution, same block, no need to put the cursor there first.

Languages

Thirty-one, each used when its toolchain is on $PATH:

lua, python, sh / bash, javascript / js, typescript / ts, c, cpp / c++, csharp / cs / c#, ruby, elixir, julia, clojure, perl, r, php, rust, go, fortran, scala, zig, nim, crystal, java, kotlin, haskell, ocaml, d, maxima, gap, sql / sqlite, latex / tex.

Compiled languages go through a real compile-then-run step rather than being interpreted. :flags are handed to the compiler, :libs follow the source file (so a linker flag resolves against it), and for the C family :includes, :defines and :namespaces write the #include / #define / using namespace lines for you. A block that supplies its own main says :main no; one that does not gets the language's own entry point wrapped around its body.

:flags, :libs and :cmdline are shell-expanded before the command is built, which is the practical way to compile against a real library:

org Copy
#+header: :main no :flags -std=c++20 $(pkg-config --cflags datamunge)
#+header: :libs $(pkg-config --libs datamunge)
#+begin_src C++
#include <datamunge/datamunge.hpp>
int main() { return 0; }
#+end_src

$(command) and `command` run the command and substitute its output (a command's own nested substitutions are its business -- the whole thing is handed to /bin/sh), ${NAME} and $NAME substitute an environment variable, and a backslash before $ or a backtick keeps it literal. Everything runs in the block's own :dir, so a substitution may name a relative path exactly as the block's code would. Nothing else in a header argument is touched, and a value with no $ or backtick in it never starts a shell at all.

The same expansion feeds the language server: a C or C++ block's :flags become the compile flags clangd is given for it, so headers behind a pkg-config -I are found by completion and hover too, not only by the compiler.

A maxima block is piped into the computer-algebra system on stdin, so every statement the body ends with ; prints its value and every $ one stays quiet -- no print() around each line, unlike org's own maxima backend. Results come back as one line each; :display2d yes asks for maxima's centred 2D art instead, and :linel sets the width it wraps at. Maxima reports a bad block by writing the error into its results rather than by failing: it exits successfully whatever happened.

A statement whose whole job is to write something out -- tex, print, disp, ldisp, display, ldisplay, grind, printf -- is run as if it were $-terminated however it was written, so it prints once instead of printing and then having maxima echo the value it handed back (false, done, or a %t label). With :results verbatim that makes a tex(...) block write bare $$...$$ into the document, which is what the math renderer reads.

A gap block works the same way -- piped into GAP on stdin, so a ;-terminated line displays its value and a ;;-terminated one stays quiet, and an error is written into the results rather than reported as a failed run. Two things are worth knowing:

  • Every block runs with GAP's line width at its maximum, so a long value arrives as one line instead of GAP's default 80-column fragments joined by backslashes. :screen-width 80 asks for that wrapping back; any width is clamped to GAP's own 20..4096.
  • :packages no skips the packages GAP autoloads -- a faster start, and quiet on an installation whose autoload list names packages it does not have (GAP writes an #I ... is not available line per package, on stdout, which would otherwise land in the results). Bear in mind that SmallGroup, PrimitiveGroup and CharacterTable are among the things those packages provide.
  • :memory 2g is a size GAP will not grow its workspace past. Hitting it ends the run, with the message in the results.

Each of those is a gap option (-x, -A, -K) rather than a line added to the block, so what GAP runs is the body as written plus any :var bindings.

org Copy
#+begin_src gap :results value
G := SymmetricGroup(5);;
Size(G);
#+end_src

GAP's break loop is disabled for these runs (-T): an error in the middle of a block is reported and the statements after it still run, rather than the rest of the block being read as answers to a brk> prompt.

mep-lua blocks

One language is special. A mep-lua block runs inside mep's own Lua state, with the whole mep.* API available -- org-babel's emacs-lisp analogue. Every other language is a subprocess and cannot see the editor.

org Copy
#+begin_src mep-lua
mep.notify('hello from inside the editor')
return mep.line_count()
#+end_src

The return value becomes the block's #+RESULTS:, unless the block is marked :results silent.

This is what lets a document drive the editor -- a deck of learning games launching itself, a notebook of editor commands.

Header arguments

A block's arguments are read from four places, each beating the one before it: a file-wide #+PROPERTY: header-args, a #+PROPERTY: header-args:<lang> for that language, the #+HEADER: lines directly above the block, and the #+begin_src line itself. A value runs to the next :key, so it can hold spaces; quote it if it contains a colon.

org Copy
#+PROPERTY: header-args:python :results output
#+HEADER: :var greeting="hello"
#+begin_src python :dir ~/my notes :prologue import sys
#+end_src

What comes back

ArgumentDoes
:results valuethe value of the last expression
:results outputwhatever the block printed
:results tableread the output as a table (:sep sets the field separator)
:results listone org list item per output line
:results scalarno interpretation at all, just quoted =: = lines
:results verbatimthe output exactly as the block wrote it, unquoted
:results raw / orginsert the output as org markup, unfenced
:results html / latexfence it as an export block for that backend
:results codefence it as a src block in the block's own language
:results drawerput it in a :results: drawer
:wrap examplefence it in that block instead (beats the above)
:results silentrun it, write nothing back
:results append / prependadd to the results already there rather than replacing them
:post NAME(arg=*this*)run the results through another named block first

How it runs

ArgumentDoes
:var name=valuebind a variable; repeat it to bind more than one
:eval nonever run this block, including on export
:exports codeexport the code only (org's default)
:exports results / both / nonewhat an export includes for this block
:dir PATHrun the block in that directory
:prologue / :epiloguecode around the body (\n separates lines)
:cmdline ARGSarguments the block's own program is run with
:flags / :libscompiler and linker arguments (compiled languages)
:main nothe body supplies its own entry point
:stdin NAMEfeed another block's results in on stdin
:cache yesre-run only when the body or arguments change
:session NAMEshare state with the other blocks in that session (export only)
:noweb yesexpand <<name>> references from other named blocks

:eval no matters for export: code blocks are executed as part of exporting, matching real org-mode's default, so a block you do not want run during a build needs to say so. :exports is the other half of that decision -- it controls what the exported document shows, and applies whether or not the block ran.

Files a block writes

:file names what the block produces, and the results become a link to it. :file-ext derives that name from the block's #+NAME: instead, :output-dir puts it in a directory, and :file-desc gives the link its text. For a language with a graphics device (R, LaTeX, Maxima), =:results graphics file= opens it around the body for you, sized by :width / :height / :units / :res. A maxima block has both of its plotting front ends pointed at the target -- plot2d / plot3d and the draw package's draw2d / draw3d -- and the file's own extension picks the terminal, so :file plot.svg really is an SVG. It needs gnuplot on $PATH as well as maxima.

A relative :file (or :output-dir, :dir, :tangle) is relative to the org file's own directory, not to mep's working directory, and the block's own subprocess is run there too -- so a bare plt.savefig("plot.png") or write.csv(d, "out.csv") in the body lands next to the document as well, and the resulting [[file:plot.png]] link points at what was written. Name an absolute (or ~/...) path to put a file anywhere else.

Line switches

-n numbers the block's lines when it is displayed or exported, +n continues the numbering from the previous numbered block, and -r / -k remove or keep its (ref:name) labels. An #+begin_example block takes them too.

Setting them from a popup

The gear button on a block card's title bar -- or <leader>os / :MepOrgBlockSettings with the cursor in the block -- opens that block's header arguments as a list you can edit without remembering how any of them are spelled. Every argument org honours for the block is there, whether or not the block sets it: the common ones first, grouped into Results, Execution, Output, Tangle and Noweb, then the ones only that language takes (:width / :height / :res for R, :includes / :flags / :libs for anything that compiles, :return for Python, :engine / :database for SQL, :display2d for Maxima, :screen-width for GAP, and so on), then the line switches.

Each row is the kind of input the argument actually takes -- a dropdown of the words org accepts, a number, or free text -- so the popup will not let you write :exports bth. :results gets four rows rather than one, since its value is up to four words from four independent groups (output, table, raw, silent); setting one leaves the other three alone.

KeyDoes
j / k, h / lmove between rows
Enter or iedit the focused row
Ctrl-N / Ctrl-Pchange the focused value without opening it
d or xclear the argument off the block entirely
q or Escapeclose

Inside a row, j / k (and Ctrl-N / Ctrl-P) cycle a dropdown or step a number, typing edits a text field -- digits type an exact number too -- and Enter or Escape commits it and goes back to the list. The mouse works as well: a click on a row focuses it, a click on its value opens it.

Each committed change is written straight into the file, as one undo entry, so u after closing the popup takes the last one back. Values are written where they already live: an argument set on a #+HEADER: line above the block is edited there, and a new one goes on the #+begin_src line. Clearing an argument is not the same as setting it to no -- an argument that isn't there lets a #+PROPERTY: line or org's own default decide, which is why the popup shows -- for one the block doesn't set.

An #+begin_example block has the same popup with only the line switches in it (-n to number its lines, +n, -r, -k); a quote or export block has no header arguments at all, so it gets no gear.

Tangling

:MepOrgBabelTangle writes the code blocks out to real source files, which is the literate-programming direction: the org file is the source, and the code files are generated from it. Blocks sharing a :tangle target are concatenated into it in document order.

ArgumentDoes
:tangle FILEthe file this block is written to
:shebang LINEthe tangled file's first line
:tangle-mode o755the permissions it ends up with
:mkdirp yescreate the target's directory when it is missing
:padline nopack the blocks with no blank line between them
:comments linkbracket each block with a link back to the org file
:no-expand yeswrite the body as-is, with no :var prelude or noweb expansion
