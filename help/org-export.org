* The formats

| Key           | Command                    | Produces            |
|---------------+----------------------------+---------------------|
| =<leader>oeh= | =:MepOrgExportHtml=        | a standalone =.html= |
| =<leader>oem= | =:MepOrgExportMarkdown=    | =.md=               |
| =<leader>oea= | =:MepOrgExportAscii=       | =.txt=              |
| =<leader>oep= | =:MepOrgExportPdf=         | =.pdf=              |
| =<leader>oeo= | =:MepOrgExportOdt=         | =.odt=              |
| =<leader>oel= | =:MepOrgExportLatex=       | =.tex=              |

Each writes its file next to the =.org= source; =<leader>oep= also opens (or
refreshes) the PDF in a viewer pane, where =:MepOrgExportPdf= only exports.
=:MepOrgExportSubtreeHtml= and =:MepOrgExportSubtreeMarkdown= export just
the subtree under the cursor.

* The Export button

An org buffer's pane header carries an *Export* button, left of the
insert-block and Run buttons. Clicking it drops down the formats above;
picking one exports the document *and* opens the result in a split to the
right -- HTML in the browser pane, PDF in the PDF viewer, ODT in the office
pane, Markdown/LaTeX/ASCII as ordinary text buffers.

Run it again and the preview refreshes in place rather than piling up a new
split each time.

| Key           | Command                    | Does                            |
|---------------+----------------------------+---------------------------------|
| =<leader>oee= | =:MepOrgExportOpen=        | pick a format, export, and open |
|               | =:MepOrgExportOpen pdf=    | that format directly            |

The buffer is written first, so an export never renders a stale file.

* The Run button and =#+EXPORT:=

=<leader>rr= on an org document does the same export-and-open, with the
format taken from a document keyword instead of a menu:

#+begin_src org
,#+EXPORT: pdf
#+end_src

=html= (the default when the keyword is absent), =pdf=, =odt=, =markdown=,
=ascii= and =latex= are recognized, as are the =md=, =txt= and =tex=
aliases. A bare =:MepOrgExportOpen= with no argument uses the same keyword.

* Document keywords

#+begin_src org
,#+TITLE: The document's title
,#+AUTHOR: Your name
,#+DATE: 2026-09-20
,#+HTML_HEAD: <link rel="stylesheet" href="custom.css">
,#+HTML_MATHJAX: nil
#+end_src

=#+HTML_HEAD:= lines are inserted into the exported =<head>=, after the
generated stylesheet, so a page can override the defaults rather than only
add to them. It is repeatable.

=#+HTML_MATHJAX: nil= suppresses the MathJax loader described below.

* HTML

A complete document: doctype, charset, title, and a readable default
stylesheet. Code blocks are syntax-highlighted with a copy button, and
tables become real HTML tables.

This manual is built with it -- see [[file:writing-help.html][Writing help pages]].

** Maths in the exported page

A document with maths in it gets a MathJax loader in its =<head>=, so
=$\alpha$= arrives as a formula in a browser instead of as four
characters. Only a document that really has maths gets it: code blocks are
excluded from the search first, so an R block full of =iris$Sepal.Length=
does not count, and neither does a price of =$5= in a sentence.

The loader adds =$...$= to MathJax's default set of inline delimiters
(=\(...\)=, =$$...$$= and =\[...\]= are on by default), because that is the
form org files are usually written in. Two things follow from it:

- The page fetches MathJax from a CDN, so it needs a network connection to
  typeset. =#+HTML_MATHJAX: nil= turns it off for an export that has to
  work offline or that is going somewhere with its own typesetter.
- Since =$...$= is enabled, a stray lone =$= in the same document's prose
  can be read as the start of a formula by MathJax, which is the usual
  cost of that delimiter. Write =\(...\)= if a document mixes maths and
  literal dollar signs.

None of this applies to reading the page *in mep*, which needs no
JavaScript for maths at all -- see [[file:browser.html][the browser]].

* PDF, LaTeX and ODT

PDF goes org → HTML → LaTeX → =tectonic=, leaving the =.tex= on disk as a
real artifact rather than scratch. Exporting to LaTeX stops one step
earlier: the same =.tex=, with no =tectonic= run -- which is what a
submission with its own LaTeX pipeline wants, and it needs no TeX toolchain
installed. ODT is written directly, with no external tool needed.

Both carry the code-block highlighting through, so a PDF's code looks like
the editor's.

* Code blocks are executed

By default, exporting *runs* the document's code blocks first and splices in
their results -- matching real org-mode's =org-export-use-babel=.

A block that should not run during export needs =:eval no=.

* Escaping org syntax

Inside a block, a line starting with =,#+= or =,*= has that comma stripped
on export. That is how a document shows org syntax without the example
ending the block.
