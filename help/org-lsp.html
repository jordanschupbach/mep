The org language server

What it is

Org files get a language server of their own, mep-org-lsp, built and shipped with mep. Open a .org file and it attaches by itself -- there is nothing to install and nothing to configure.

It checks the org markup: blocks, drawers, timestamps, links, footnotes, keywords and source-block header arguments. It completes the same vocabulary as you type it.

This is the outer org file. Code inside a #+begin_src block is handled separately, by a real server for that language -- see Language servers in code blocks. The two run side by side and their diagnostics are merged, so a Python error in a block and a malformed timestamp in the prose both show up at once.

Everything inside a #+begin_src, #+begin_example, #+begin_export or #+begin_comment block is left alone, and so is anything inside verbatim or code markup. A help page showing broken org syntax does not get told its syntax is broken.

Keywords match whichever case you are typing: #+ti completes to #+title:, #+TI to #+TITLE:.

Hover, outline, folding, jumps

K over a timestamp says which weekday it falls on; over a header argument, option switch, keyword or entity it explains what that one does; over a headline it summarises state, priority, tags and planning.

gd on a link jumps to it -- a headline, a #+NAME:, a <<target>>, a :CUSTOM_ID: or another file, including file.org::42.

Headlines are the document outline, so the symbol views and folding both work from the server as well.

Turning it off

It is an ordinary entry in the server registry, so init.lua can drop it:

lua Copy
mep.lsp_servers.org_ls = nil

Or point it at your own build:

lua Copy
mep.lsp_servers.org_ls.cmd = {'/path/to/mep-org-lsp'}

It also runs standalone, over stdio, in any editor that speaks LSP.
