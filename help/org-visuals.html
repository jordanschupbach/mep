Images, LaTeX and tables

Inline images

Key / commandDoes
<leader>otitoggle inline images
:MepOrgImagesTogglethe same
:MepOrgImageScanrescan the buffer for images

A link to an image file is drawn in place, in the buffer:

[[file:diagram.png]]

This is on by default; the toggle is there to get the raw [[file:...]] markup back.

A figure is drawn at 80% of the text width (:set textwidth, 80 columns by default) or at its own size, whichever is smaller -- so a small icon stays small instead of being blown up -- and is centred in that column. It reserves exactly as many lines as it is tall: no empty band above or below it, and widening the window doesn't stretch it. A picture tall enough to run past 40 lines is scaled down to fit rather than cropped.

A figure is one buffer row but many lines tall, so j and k scroll over one rather than past it: while the cursor is on a figure, each press moves the view by a single line and leaves the cursor where it is, until the edge you are heading for -- the figure's bottom going down, its top going up -- has passed the middle of the window, which is where the caret rides while it is over a picture. The next press steps off the figure onto the row after (or before) it. The mouse wheel scrolls a figure the same way, three lines to a notch. A counted motion (10j), an operator (dj), Visual mode and the explicit scroll commands (Ctrl-D, zz, zt, zb) all treat a figure as the single row it is.

A link whose target is not on disk yet -- a plot a code block has still to produce -- stays plain text, and turns into the picture on the next edit after the file appears.

Block cards

Key / commandDoes
<leader>otbtoggle block cards
:MepOrgBlockCardsTogglethe same

Every #+begin_.../#+end_... block is drawn as a rounded card: a tinted background, an outline in the theme's accent colour for a src code chunk (muted for example, quote, export and the rest), and a title bar in place of the header lines.

The bar carries the block's language, its name and its header arguments, each in its own box, however they were written:

#+HEADER: :var x=1
#+NAME: read-config
#+begin_src python :tangle "my file.py" :results output
#+end_src

reads as python | read-config | :var x=1 | :tangle my file.py | :results output. Quoted values keep their spaces, a bare flag such as :cache shows on its own, :var is listed once per variable, and a long value is shortened from the front. A #+CAPTION: stands in as the title when there is no #+NAME:, and a :title header argument does too.

Nothing is rewritten: put the cursor on the header (or select across it) and the raw #+begin_src ... line comes straight back to edit. The card also steps aside for a folded block, and for a block holding an image or a maths fragment that is being previewed in place.

The play button

A src card's title bar ends with a play button, docked against its right edge so a page of blocks lines its buttons up in one column. Click it and that block runs -- the same execution C-c C-c (org-babel) performs, on the same block, writing its #+RESULTS: back into the file. Clicking one in an unfocused split focuses that split first.

The button is muted, rather than in the accent colour, when the block would refuse to run: no language tag on the #+begin_src line, or an :eval no / :eval never header argument. It is still clickable -- the click says which of the two it is. Hovering any button says what it will do.

A block that has no #+end_src yet gets none (there is nothing to run), and neither does any non-=src= block. If the card is too narrow for both the button and the block's language, the language wins and the button is dropped -- C-c C-c is unaffected.

How wide a card is

As wide as the wider of its own longest line and textwidth (=:set tw=N=, 80 by default) -- and never wider than the pane, less a small margin.

So a page of short blocks lines its cards up on one edge at the text width instead of each one ending wherever its longest line happens to, and a block that genuinely runs wider still gets a card that contains its code rather than one the code hangs out of. Past the pane's own width the card stops there; a line that long is soft-wrapped inside it anyway.

Every line the card encloses counts, including the #+NAME:=/=#+HEADER: stack and the #+begin_ line -- so the header still fits inside the card on the frame the cursor moves onto it and the raw line comes back.

Errors reported on the header line

A diagnostic whose line is one the card covers -- the #+begin_src line itself, most often, where the org language server reports an unknown language or a bad header argument -- is drawn *after the card's right border*, not where the row's own text would be. The title bar stands where that text was, so a message left there would be painted over by it and never seen.

If the card reaches the pane's own edge and leaves no room past the border, the message moves inside the bar's right end instead, over a band of the bar's own colour. Either way it is shortened with ... to fit; the gutter badge marks the row as it always did, and :MepDiagShow (or just moving the cursor onto the line) gives the full text.

The language-server status line

Key / commandDoes
<leader>otstoggle the status line
:MepOrgLspStatusTogglethe same
:MepOrgLspStatusScanrefresh it now

A src card carries one line along its bottom edge, under a rule separating it from the code, saying what its own language server (per-block LSP) is doing. It sits on the #+end_src row, which the card was already blanking out, so it costs the block no extra height.

A coloured dot carries the state at a glance and the text spells it out:

ReadsMeans
LSP: no server for shnothing is registered for that language
LSP: no language setthe block has no #+begin_src <lang> tag
pyright: idle (attaches on first use)a server is registered, nothing started yet
pyright: starting...spawned, still initialising
pyright: not runningit failed to start, or it died
pyright: ready, no diagnosticsattached and happy
pyright: ready, 2 errors, 1 warningattached; what it found inside this block

The counts cover the block's own body lines only, so a bad header argument on the #+begin_src line (org's own lint, shown beside the card -- see above) doesn't get counted against the code. They also outrank the state: a perfectly healthy server reporting errors reads red, not green.

This is on by default. Like every other concealed row, put the cursor on #+end_src and the raw text comes back in place of the status.

Servers attach lazily -- the first time an LSP feature actually runs inside the block (hover with K, completion, gd), not merely on the cursor entering it -- which is why an untouched block reads idle.

LaTeX and maths

Key / commandDoes
<leader>otltoggle the maths preview
:MepOrgLatexTogglethe same
:MepOrgLatexScanrescan for fragments

Fragments written \(...\), \[...\], $...$ or $$...$$ are rendered and drawn in place of the source. It works in .tex files as well as org.

This is on by default too. Rendering shells out to tectonic and pdftoppm (both in the flake's dev shell); without them on PATH the maths simply stays as source text, and mep says so once per session rather than once per fragment.

Markup concealment and heading sizes

Key / commandDoes
<leader>otmtoggle markup concealment
:MepOrgConcealTogglethe same
<leader>othtoggle scaled heading sizes
:MepOrgHeadingScaleTogglethe same
<leader>otctoggle the plain cursor line
:MepOrgPlainCursorLineTogglethe same

Concealment is what draws *bold* as bold text, [[file:x][Notes]] as Notes, a |---+---| row as a line, and a heading without its leading stars (indented one column per level below the first instead -- see Org files in mep). It is on by default, and always steps aside for the row the cursor is on.

A concealed row closes up behind what it hides. The markup is almost always longer than what replaces it, and the difference is not left behind as a hole: the rest of the row slides left by it, so a rendered line reads as prose rather than as prose with gaps punched through it. Only a rendered row does this -- the row the cursor is on is showing its real characters on the real column grid, which is the grid the caret is drawn on.

Inside a table the closing-up is per cell. A table's | columns are what the grid's rules are drawn down, so the slack a concealed cell frees up is handed back at that cell's own end instead of pulling the rest of the row left: the text in the cell tightens and every pipe stays where the row above put it.

Heading sizes are separate because they are the one piece of org rendering that changes a row's height rather than which characters it shows.

The plain cursor line goes one step further than concealment's own step-aside: the row the cursor is on is drawn as nothing but its own raw characters -- no syntax colours, no emphasis faces, no link colouring, no inline $...$ maths painted over it -- so what you are editing is exactly what is in the file. On by default, org buffers only.

Whole-row substitutions are the exception: an inline image or a whole-row maths preview claims many screen rows, so reverting one under the cursor would shuffle everything below it on every cursor move. <leader>oti and <leader>otl get that source back instead.

Tables

A table is drawn as a grid: a rule down every column, a drawn line for each |---+---| row, and a tint behind the header block. The grid follows the text, so a table is realigned on its pipes whenever the cursor leaves it -- after an edit, never after a read-only visit. :MepOrgTableAlign does the same on demand, for the table under the cursor.

A literal pipe inside a cell must be escaped as \vert or \|, or it will be read as a column separator.

Wide tables

A table whose columns add up to more than :set textwidth (80 by default) is rendered narrower than it is stored. The columns are re-budgeted to fit the line width and any cell too long for its column wraps onto further lines, so one row of the file draws as several:

RenderingOn
<leader>otwtoggle wrapped rendering of over-wide tables
:MepOrgTableWrapTogglethe same

Narrow columns keep their natural width and only the wide ones give up columns, so a table of one long prose column beside three short ones spends the budget on the prose instead of shaving all four evenly. A column is never widened past its own longest cell, and a word too long for its column is split rather than left to overflow. :set tw=N re-renders every table in the buffer at the new width.

This is rendering only: the file keeps its long lines. Wrapping them into the file would still be valid org -- a continuation row is an ordinary row with an empty first cell -- but it would add rows, which shifts spreadsheet references like @3$2 under the table, and a continuation row can never be told back apart from a row whose first cell is genuinely empty, so the wrap would be one-way.

The row the cursor is on is never wrapped: it shows its real stored columns, so a cell is always edited against the widths that are in the file. Only that one row steps aside -- the rest of the table stays wrapped around it, at the same column widths it already had, since those are planned from the whole table's stored cells and not from where the cursor is. Moving off the row wraps it again, and the rows a Visual selection covers step aside the same way (the selection is drawn against the stored columns too).

A row showing its stored text is left out of the grid: no header tint, no column rules and, on a |---+---| row, no drawn rule over the dashes -- the rules above and below it simply stop there, because the columns it is showing are not the ones the rest of the table is drawn in. Because a wrapped row's drawn text is not the row's own text, its syntax colouring is skipped for as long as it is wrapped, and it comes back fully decorated the moment the cursor leaves it.

Links are the exception, because the layout resolves them itself. A cell's link markup is turned into its display text before the columns are budgeted, so a [[https://orgmode.org/manual/Tables.html][Tables]] cell costs the table the six columns of Tables rather than the fifty of its markup -- no other column is shaved to pay for a URL that is never drawn -- and the link is then coloured and clickable exactly where the layout put it, underlined when its markup is showing just as a link in prose is. A description the wrap breaks across lines stays a link on every line it lands on. With concealment off (<leader>otm) the markup is what gets measured, wrapped and drawn, and flipping the setting re-lays out the table.

This is also why a table that fits can still be laid out. A table of link cells is padded in the file to its markup's width -- which is what :MepOrgTableAlign should write, since the file's own columns have to line up -- so the drawn cell is a short description followed by a stretch of dead gutter before the |. Whenever the layout comes out genuinely narrower than the stored rows, the table is drawn from the layout and the columns close up. A table already as tight as its layout, and an unaligned one whose layout comes out wider, are both left alone.
