PDF

Reading

Open a .pdf and it renders in a pane. Scrolling, zoom and the usual pane keys work.

From LuaDoes
mep.pdf_goto_page(n)jump to a page
mep.pdf_current_page()which page is showing
mep.pdf_outline()the document's outline
mep.pdf_reload()re-read the file
mep.is_pdf_buffer(buf)is this a PDF?

The outline

A PDF with bookmarks gets an outline you can navigate rather than scrolling -- the table of contents the author built, used as a jump list.

Links

Internal links jump within the document; external ones open in the browser.

Text

Text is extracted, not just rasterised, so search finds real words -- and what you select is real text, not a picture of it: words and lines are reconstructed from the glyphs, ligatures are written out as the letters they stand for, and a word broken over a line end is put back together. So a quoted passage reads as prose rather than as investiga- tor.

Annotating

a enters annotate mode -- a modal state of its own, like Visual.

KeyDoes
hjklmove the caret a character or a line
w b eby word
0 $to the ends of the line
clickplace the caret
vstart or stop a selection
ycopy the selection
Kask about the selection
Escclear the selection; again to leave

The caret moves down the page, not through the file: a content stream emits a page in whatever order it likes -- body text, then the running header, then the footnotes -- and following that order would send the caret back to the top of the page mid-paragraph.

Displayed equations are stepped over. Their glyphs sit on several baselines at once -- a summation, its indices, the main line -- so a caret walking through one lurches up and down rather than along. Mathematics inside a line of prose is ordinary text and stays selectable.

Esc unwinds one layer at a time, as it does in Visual mode: with a passage selected it drops the selection and keeps you in annotate mode, and only an Esc with nothing selected leaves. A key you press constantly to mean "never mind this bit" should not also throw away the mode.

<space> is the annotation leader: h highlights the selection, n attaches a note, d deletes what is under the caret, c and 1-=5= pick the highlight colour, q leaves.

Asking about a passage

Select a passage and put it to a model, without leaving the page.

Key / commandDoes
Ka short answer in a popup
Chand it to Claude Code in a pane
o over a popupmove that answer into the sidebar
:MepPdfYankcopy the selection
:MepPdfAskthe popup, by name
:MepPdfClaudeClaude Code, by name

K asks nothing first: it sends a fixed prompt -- keep it short, explain the concept in simpler terms or define it -- and shows the reply in a box over the page. That is the whole interaction.

When the selection is very short -- under mep.pdf_ask_context_under characters, 40 by default, so a lone symbol or a bare term -- the rest of the page goes along as background so the model has something to go on. Above that a quoted passage stands on its own. Raise the threshold if you want more context, or set it to 0 to never send the page:

lua Copy
mep.pdf_ask_context_under = 0

A word of warning about raising it: the page is quoted as background only, and the prompt says so, but a one-line passage followed by a few thousand characters of page does not reliably hold the model's attention -- you get a summary of the page instead of an answer about the passage. That is why the default is as low as it is.

When the short answer is not enough, o over the box hands the same passage to Claude Code, carrying on there rather than starting over.

C goes straight there, and is the route that needs no API key: it types the passage into Claude Code running in a pane -- which brings its own credentials and keeps its own history across restarts -- opening one first if none is running. The reply is the agent's, in its own pane, so nothing streams back into the page.

C is the same key, and the same gesture, as highlighting a run of ordinary text and pressing C in Visual mode. See Claude Code in a pane.

All of them read the selection the keyboard made with v or the one a mouse drag left behind -- in any PDF pane, not only in annotate mode.

With nothing selected they fall back to a highlight, so the obvious reading order works: highlight a passage as you read, then ask about it. That fallback matters because highlighting a selection consumes it -- <space>h turns the selection into an annotation and clears it -- so by the time you press K there is no selection left, only the highlight.

Three sources are tried, in order of how specifically you pointed at the passage:

OrderPassage used
1the selection, if there is one
2the highlight under the mouse, else under the caret
3the newest highlight on the page you are looking at

The third exists because the first two both need a position: a plain PDF pane has no caret, and the mouse is usually nowhere near the text. It only ever considers the page on screen, so it cannot quote something you cannot see. When it is not your selection that was used, mep says which it took.

With none of the three, they say so rather than doing nothing.

How much context goes along with the passage is a setting -- <leader>hS, under PDF lookup. See Settings.

The model, the key and everything else come from the AI settings; the prompt K sends is mep.pdf_ask_prompt.

Accessibility

A tagged PDF says what each piece of a page is and carries the words that stand for what cannot be read as text. mep reads those tags:

  • Rest the pointer on a figure, a formula or a table: its alternative text (or the table's summary) pops up beside it.
  • :A11yRead opens the document as a screen reader would read it -- headings, paragraphs across page breaks as one, figures as their alt text, tables cell by cell under their headers, page numbers left out. Enter on a line jumps to its page.
  • :A11yTree shows the structure tree; :A11yCheck lists what is missing (not tagged at all, no title, no language, a figure with no alt text ...).
  • :A11ySpeak reads it aloud when espeak-ng or espeak is installed.

A PDF with no tags still reads -- as its text in page order -- and the check says so. PDFs exported from mepml are tagged.

Encrypted files

A password-protected PDF is handled, including the common encryption revisions. An unsupported one says so rather than rendering blank.

Theming

Like other rendered documents, a PDF is re-tinted to your theme by default -- a white page in a dark editor is jarring. The header reads [theme, Ctrl-R]; Ctrl-R shows the document's real colours, which is what you want when checking how something will print.
