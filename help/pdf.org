* Reading

Open a =.pdf= and it renders in a pane. Scrolling, zoom and the usual pane
keys work.

| From Lua                     | Does                      |
|------------------------------+---------------------------|
| =mep.pdf_goto_page(n)=       | jump to a page            |
| =mep.pdf_current_page()=     | which page is showing     |
| =mep.pdf_outline()=          | the document's outline    |
| =mep.pdf_reload()=           | re-read the file          |
| =mep.is_pdf_buffer(buf)=     | is this a PDF?            |

* The outline

A PDF with bookmarks gets an outline you can navigate rather than scrolling
-- the table of contents the author built, used as a jump list.

* Links

Internal links jump within the document; external ones open in the browser.

* Text

Text is extracted, not just rasterised, so search finds real words -- and
what you select is real text, not a picture of it: words and lines are
reconstructed from the glyphs, ligatures are written out as the letters
they stand for, and a word broken over a line end is put back together.
So a quoted passage reads as prose rather than as /investiga- tor/.

* Annotating

=a= enters annotate mode -- a modal state of its own, like Visual.

| Key             | Does                                    |
|-----------------+-----------------------------------------|
| =hjkl=          | move the caret a character or a line    |
| =w= =b= =e=     | by word                                 |
| =0= =$=         | to the ends of the line                 |
| click           | place the caret                         |
| =v=             | start or stop a selection               |
| =y=             | copy the selection                      |
| =K=             | ask about the selection                 |
| =A=             | discuss the selection                   |
| =Esc=           | leave                                   |

The caret moves down the page, not through the file: a content stream
emits a page in whatever order it likes -- body text, then the running
header, then the footnotes -- and following that order would send the
caret back to the top of the page mid-paragraph.

Displayed equations are stepped over. Their glyphs sit on several
baselines at once -- a summation, its indices, the main line -- so a
caret walking through one lurches up and down rather than along.
Mathematics *inside* a line of prose is ordinary text and stays
selectable.

=<space>= is the annotation leader: =h= highlights the selection, =n=
attaches a note, =d= deletes what is under the caret, =c= and =1=-=5=
pick the highlight colour, =q= leaves.

* Asking about a passage

Select a passage and put it to a model, without leaving the page.

| Key / command    | Does                                          |
|------------------+-----------------------------------------------|
| =K=              | a short answer in a popup                     |
| =A=              | open a discussion in the AI Agent sidebar     |
| =C=              | hand it to Claude Code in a pane              |
| =o= over a popup | move that answer into the sidebar             |
| =:MepPdfYank=    | copy the selection                            |
| =:MepPdfAsk=     | the popup, by name                            |
| =:MepPdfDiscuss= | the sidebar, by name                          |
| =:MepPdfClaude=  | Claude Code, by name                          |

=K= asks nothing first: it sends a fixed prompt -- keep it short, explain
the concept in simpler terms or define it -- and shows the reply in a box
over the page. That is the whole interaction. When the selection is short,
a lone symbol or a bare term, the rest of the page goes along as
background so the model has something to go on.

When the short answer is not enough, =o= over the box moves the passage
and the reply into the [[file:ai-agents.html][AI Agent]] sidebar and leaves you in a follow-up
prompt, carrying on rather than starting over. =A= goes straight there,
asking for your question first.

=C= is the one route that needs no API key. It types the passage into
[[file:ai-terminal.html][Claude Code]] running in a pane -- which brings its own credentials --
opening one first if none is running. The reply is the agent's, in its
own pane, so nothing streams back into the page.

All of them read the selection the keyboard made with =v= or the one a
mouse drag left behind. The model, the key and everything else come from
[[file:ai-commands.html][the AI settings]]; the prompt =K= sends is =mep.pdf_ask_prompt=.

* Accessibility

A /tagged/ PDF says what each piece of a page is and carries the words that
stand for what cannot be read as text. mep reads those tags:

- Rest the pointer on a figure, a formula or a table: its alternative text
  (or the table's summary) pops up beside it.
- =:A11yRead= opens the document as a screen reader would read it --
  headings, paragraphs across page breaks as one, figures as their alt
  text, tables cell by cell under their headers, page numbers left out.
  =Enter= on a line jumps to its page.
- =:A11yTree= shows the structure tree; =:A11yCheck= lists what is missing
  (not tagged at all, no title, no language, a figure with no alt text ...).
- =:A11ySpeak= reads it aloud when =espeak-ng= or =espeak= is installed.

A PDF with no tags still reads -- as its text in page order -- and the
check says so. PDFs exported from [[file:mepml.html][mepml]] are tagged.

* Encrypted files

A password-protected PDF is handled, including the common encryption
revisions. An unsupported one says so rather than rendering blank.

* Theming

Like other rendered documents, a PDF is re-tinted to your theme by default
-- a white page in a dark editor is jarring. The header reads
=[theme, Ctrl-R]=; =Ctrl-R= shows the document's real colours, which is what
you want when checking how something will print.
