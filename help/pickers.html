Pickers

What a picker is

A centred list you filter by typing, with a preview beside it. Most of the ways to find something in mep are one.

Every picker shares the same shape: type to filter, Up/Down or =Ctrl-P=/ Ctrl-N to move, Enter to accept, Esc to cancel. Each one lists its own extra keys along its bottom edge, so you never have to remember them.

The tab bar's three search buttons are the first, second and fourth of these.

The buffer picker

<leader>bb previews the highlighted buffer's live contents -- unsaved edits included -- around its cursor position.

KeyDoes
Entershow it in the focused pane
C-vopen in a new vertical split
C-sopen in a new horizontal split
C-topen in a new tab
C-iopen as a buffer tab of the focused pane
C-ddelete the buffer, confirming if unsaved

mep.buffer_open_with(id, how) is the scriptable form, where how is switch, vsplit, split, tab or pane_tab.

The theme picker

<leader>ut is worth singling out because it previews live: every change of the highlighted row re-tints the whole interface immediately, before you commit. Enter keeps the theme, Esc restores the one you started with. There are 62 to look through.

Live grep

<leader>pr searches every file under the workspace root and lists matching lines. Because the working directory follows the active workspace, this searches that worktree and not the others.

Writing your own

Pickers are ordinary Lua, and the built-in ones are defined the same way yours would be:

lua Copy
mep.picker_open('Pick a colour', {'red', 'green', 'blue'}, function(item)
  if item then mep.notify('you chose ' .. item) end
end)

The callback receives nil when cancelled. Further arguments add a preview and a per-row callback for live-preview behaviour like the theme picker's. mep.picker_set_hint(text) writes the key list along the bottom edge, and mep.picker_set_tabs gives a picker several tabbed sources, as the command runner does.
