The Python language server

What it is

Python files get a language server of their own, mep-python-lsp, built and shipped with mep. Open a .py file and it attaches by itself -- there is nothing to install, no pip, no node, and no Python interpreter involved. It is mep's own tokenizer, parser and scope analyser, with a table of the standard library compiled into it.

That last point is the whole design: everything it knows, it knows from the file in front of it plus that table. It will tell you that a name is never defined anywhere in the file, and it will not tell you that you passed a str where an int was wanted -- because it cannot see the modules you import, and a checker that guessed about them would be wrong far more often than it was right.

What it deliberately stays quiet about

A linter that cries wolf gets switched off, and then its true reports go unseen too. So:

  • from x import * switches the undefined-name check off for the whole file rather than guessing what the star brought in -- and says so, once, on the import itself.
  • So does anything that writes the namespace at run time (globals().update(...), eval, exec).
  • A file with a syntax error gets no scope diagnostics at all until it parses again: mid-edit is exactly when a screenful of invented "undefined name" errors would be least welcome.
  • from __future__ import annotations, a name listed in __all__, and every import in an __init__.py are never "unused".
  • A string annotation (='Node'=) counts as using the name, never as claiming it exists -- Literal['w'] must not invent one.
  • @property setters, @overload runs, try:/except ImportError: import fallbacks and import os beside import os.path are all redefinitions on purpose, and pass without comment.
  • with pytest.raises(TypeError): a + b is a test, not a dead expression.
  • An unused half of a tuple unpacking, and any name starting with _, are not unused variables.

A line-length hint exists but is off unless asked for:

lua Copy
mep.lsp_servers.python_ls.init_options = {maxLineLength = 100}

Completion

Completion is context-aware rather than a word list:

Where you areWhat you get
anywhere in codeevery name in scope, then builtins, then keywords
after os.that module's members, from the built-in table
after self.the class's own methods and fields, and its bases'
after text. where text is a stringstr's methods
after c. where c = MyClass()that class's members
after importthe standard library, plus the .py files beside this one
after from json importthat module's members
after raisethe builtin exceptions
after def in a classthe special methods, __init__ first
after @property, staticmethod, dataclass, and what is in scope

Inside a comment or a string it offers nothing -- except inside an f-string's {...}, which is code and is treated as such.

Hover, signatures, outline, jumps

K over a name gives its definition line: a function's full signature and the first line of its docstring, a class and its bases, a parameter and its annotation, a variable and what it was assigned. Over a builtin, a keyword or a standard-library member it answers from the built-in table.

<leader>lk (signature help) shows the signature of the call the cursor is inside, with the parameter you are on highlighted -- including while you are typing a string argument, and with self dropped from a method called through an instance. It fires by itself as you type ( and =,=.

gd jumps to where a name is bound. On self.field it jumps to the method that first assigns it; on an import of a module that sits beside this file, it opens that file at the definition, not at line 1.

:MepLspReferences lists every use of the binding under the cursor -- the one in this scope, not every name that happens to match, so a local value and a module-level value stay separate. <leader>rn renames the same set, and refuses names it cannot rename safely (a builtin, or an attribute whose owner is defined in another file).

Classes, functions, methods and module-level assignments are the document outline, so the symbol views work from the server. Folding covers every suite, each else=/=except=/=finally arm, runs of comment lines, the import block at the top and multi-line strings.

What it does not do

  • No type checking. See the opening section.
  • One file is the whole world. An imported name is known to exist and nothing more. Attribute completion on an object from another module falls back to "attribute names this file already mentions".
  • No project-wide rename or references. Both stop at the file's edge, which is why a rename that cannot see the other users is refused rather than half-done.
  • No formatting. mep.lsp_format falls through to the configured formatter for Python; the server does not claim the capability.

Turning it off

It is an ordinary entry in the server registry, so init.lua can drop it, or hand py back to pyright:

lua Copy
mep.lsp_servers.python_ls = nil
mep.lsp_servers.pyright.filetypes = {'py'}

Or point it at your own build:

lua Copy
mep.lsp_servers.python_ls.cmd = {'/path/to/mep-python-lsp'}

It also runs standalone, over stdio, in any editor that speaks LSP.
