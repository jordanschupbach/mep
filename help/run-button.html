Running the current file

Run what you are looking at

KeyDoes
<leader>rrrun or compile the current file
grthe same
<leader>rsconfigure the interpreter or compiler for this filetype

The command runs in this tab's terminal, so its output appears where you would expect and stays there.

Note gr is run in mep, not LSP references.

What it does per filetype

FiletypeDefault
.pypython3 <file>
.rRscript <file>
.ccc <file> -o <tmp> && <tmp>
.cppc++ <file> -o <tmp> && <tmp>

A compiled language gets a real two-step build-then-run. The binary lands outside the project tree, in a temporary file, so repeated runs never race a half-written executable and nothing needs cleaning up.

Setup

<leader>rs (:MepRunButtonSetup) prompts for the interpreter or compiler and the flags to use for the current filetype, and saves them per project. So one checkout can use python3.12 and another python3.9 without either knowing about the other.

lua Copy
-- change the defaults for every project
mep.opt.run_button_defaults.py = {interpreter = 'python3.12', flags = ''}
mep.opt.run_button_defaults.cpp = {compiler = 'clang++', flags = '-std=c++20 -Wall'}

Where flags go

For a compiled language the flags are placed after the source file:

c++ main.cpp `pkg-config --cflags --libs gtk+-3.0` -o /tmp/xyz && /tmp/xyz

That is not cosmetic. A pkg-config line mixes -I=/-D= flags, which are order-independent, with -l link flags, which GNU ld resolves left to right against whatever object files came before them. Put the flags first and the link silently drops symbols -- an "undefined reference" that looks like your code's fault.
