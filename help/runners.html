The command runner

Pick a target and run it

<leader><Space> (:Runner) fuzzy-picks a target from whichever build system the project uses, and runs it in this tab's terminal.

It looks for just, then make, then ninja, then cmake:

lua Copy
mep.opt.runner_order = {'make', 'just'}   -- or your own precedence

The preview

The preview column beside the list shows, for the highlighted target:

  • the command that will run;
  • a tree of its dependency graph;
  • the recipe body.

The graph comes from the build system itself -- just --dump json, make -pRrq, ninja -t graph -- so it is what will actually happen, not a guess. Every tool is invoked asynchronously, so a slow make -p never freezes the editor.

lua Copy
mep.opt.runner_tree_depth = 8       -- how deep the dependency tree goes
mep.opt.runner_tree_children = 40   -- how many children to show per node

Three tabs

Tab and Shift-Tab move between them.

TabKeyShows
Targetsrecipes and targets, with the preview above
Workspaces<leader>jwdirectories under the workspace root that have runner files
Variables<leader>jvjust assignments, makefile variables, ninja bindings, CMake cache entries

Workspaces matters in a monorepo: press Enter on a directory to make it this tab's runner root, and the target list becomes that subproject's.

Variables answers "what is this set to, and where" -- Enter jumps to the definition.
