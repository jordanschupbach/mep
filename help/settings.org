* A panel for the settings worth changing

Most of mep is configured by writing Lua in =init.lua=. The Settings panel is
for the preferences you are most likely to want to change, shown with their
current values so you can see what they are without reading source --
and remembered, so you set them once.

| Open it with    | Where                                  |
|-----------------+----------------------------------------|
| =<leader>hS=    | the keyboard                           |
| =:MepSettings=  | the command line                       |
| the gear        | the panel strip, right of the tabs     |
| *Settings* menu | the menu bar (=<leader>um= shows it)   |

Inside, rows are typed. A short list cycles in place with =Ctrl-N= / =Ctrl-P=,
a number steps with =j= / =k= once you are in it, a text field just takes
typing, and a long list opens as a dropdown you can type into:

| Key               | Does                                |
|-------------------+-------------------------------------|
| =j= =k=           | move between rows                   |
| =Enter= =i=       | edit the focused row                |
| =Ctrl-N= =Ctrl-P= | change the focused row's value      |
| =d=               | clear it, back to mep's own default |
| =Enter= =Esc=     | done editing, keeping what is there |
| =q=               | close                               |

** The dropdown rows

Two rows have too many values to step through one at a time -- the colour
scheme has 63 -- so they open a list instead. The field shows =v= rather
than =< >= to say so. =Enter= opens it:

| Key               | Does                                      |
|-------------------+-------------------------------------------|
| =Ctrl-N= =Ctrl-P= | move the highlight                        |
| arrows            | the same                                  |
| typing            | narrows the list                          |
| =Enter=           | choose what is highlighted                |
| =Esc=             | *cancel*, keeping the value you came with |

Typing filters rather than moving, so =j= and =k= are letters here -- which
is why the highlight moves with =Ctrl-N= / =Ctrl-P= and the arrows, the same
keys the file picker uses. A =✓= marks the value the row actually holds, as
opposed to the one you are looking at.

=Esc= cancelling is the one place in this panel where it does not keep what
you did, and the colour scheme is why: the list re-tints the whole interface
as the highlight moves over it, so backing out has to put the old one back.
Choose with =Enter=; leave with =Esc=.

*OpenAI model* additionally takes a name its list does not have. Type one and
=Enter= uses it as typed -- which is how a local OpenAI-compatible server
behind *OpenAI base URL* is reachable, since no list here could know what it
calls its models.

** The prompt box

*PDF K prompt* and *Buffer K prompt* under *Quick ask* are paragraphs, not words, so each is drawn
as a box across the panel with its label above it rather than squeezed into
the value column. =Enter= puts a cursor in it; the arrows, =Home= and =End=
move within the text and =Esc= is done. =d= puts mep's own wording back.

The line under the list explains whatever row you are on. A value shown as
=--= is one you have not set, so mep's own default applies.

* What it does not do

*It never writes =init.lua=.* Your config is a Lua program -- it can check
whether a file exists and set an option only then -- so a panel that rewrote
it would sooner or later mangle something that mattered. Instead the panel
writes its own file:

| Path                                | Holds                            |
|-------------------------------------+----------------------------------|
| =~/.config/mep/init.lua=            | your configuration, hand-written |
| =$XDG_DATA_HOME/mep/settings.json=  | what you last picked in the panel |

So the two can disagree about the same option, and the rule is: *the panel
wins.* Its values are applied after =init.lua= has run, because a setting
you just clicked has to take effect. Where =init.lua= also sets an option,
that row says so:

#+begin_example
[also set in init.lua; this wins]
#+end_example

That is a note, not a problem -- but if you want =init.lua= to be the
authority for an option, clear the row with =d= and the stored value goes
away.

Secrets are deliberately not stored, and nothing about your API key is in
this panel at all. The key lives in your environment, or behind
=mep.ai_api_key_cmd= in =init.lua= -- a command that prints it, so it stays
wherever you already keep secrets. See [[file:ai-commands.html][Ask the model]].

=<leader>ak= (=:MepAiKey=) changes that command for the current session,
prefilled with what is in force, and clears the key mep had cached -- without
that, the old key would keep being used and the change would look like it had
silently failed. It is deliberately *not* remembered: =init.lua= is where a
key command belongs.

* The settings

** AI

*Use the API at all* is the master switch, and it is the first row because
it governs every other AI row. Turn it off and nothing in mep makes a paid
call, or even runs your key command.

Rather than simply refusing, most routes then *fall back to Claude Code* --
the =K= popup, the =:MepAiSend= family, the AI Agent prompt -- sending the
same passage to a pane instead, and saying so each time. Claude Code needs
no key and keeps its own history, which is why one route stays open.

Two exceptions refuse instead: =:MepAiReplaceSelection=, whose reply has to
land back in the buffer (it checks *before* deleting your selection), and
speech-to-text, which transcribes rather than chats.

=<leader>ax= toggles it without opening this panel.

The two things under it used to sit in one flat list and were easy to
confuse, so they are now two sections.

** Quick ask (=K=)

=K= over a passage in a PDF asks the model about it and shows the answer in a
popup -- a short lookup that answers and gets out of the way, over HTTP, on
your own key. Everything that shapes it is here.

*API provider* is =anthropic= or =openai=, and it decides which of the two
model rows below applies. An OpenAI-compatible server (a local model, say) is
=openai= plus its own base URL.

*Anthropic model* and *OpenAI model* are dropdowns rather than text fields,
because a mistyped model name does not look like a mis-set option -- it
arrives as a 404 from a request you never see. Neither list is exhaustive;
the OpenAI one takes a typed name for exactly that reason.

*PDF K prompt* is what mep actually asks about a PDF passage:

#+begin_example
Keep this short and concise. Explain this concept in simpler terms, or
define it. Answer in at most 6 short lines of plain prose: no preamble,
no restating the question, no headings and no bullet lists.
#+end_example

Your passage is quoted underneath it. Rewrite it for the kind of reading you
do -- ask for notation expanded, or an answer in your field's terms, or more
than six lines -- and =d= puts mep's wording back.

*Buffer K prompt* is its counterpart for =K= on a Visual selection in an
ordinary buffer. There the answer is written into the file after the
selection rather than shown in a popup, and a highlight is as often a
request (a comment describing code to write) as a term to explain, so its
wording asks for just the code or text when that is what was asked. See
[[file:ai-commands.html][AI commands]].

*Context sent with a passage* is what goes alongside the passage:

| Mode                            | Sends                                      |
|---------------------------------+--------------------------------------------|
| highlight only                  | just your passage                          |
| add page for short selections   | the page too, but only for a bare term     |
| always add the page             | the page every time                        |

The middle one is the default. Sending the page is useful for a lone symbol
and counterproductive for a sentence: with a short quote and a whole page
behind it, the model tends to summarise the page instead of answering about
the quote. See [[file:pdf.html][PDF]].

*Longest answer* caps the reply in tokens, which for a popup meant to be
short is also the ceiling on what one costs. *Wrap the answer at* is the
column the reply is wrapped to -- the popup box does not wrap on its own, so
this is what keeps an answer inside it.

** Agent in a pane

*Agent command* is what =:aiterminal= runs -- =claude= or =codex=. A separate
section because it is a separate thing: a CLI agent in a terminal pane,
bringing its own credentials, unaffected by the API switch above. This is the
only way to use Codex, which has no HTTP API in mep.

See [[file:ai-commands.html][Ask the model]] and [[file:ai-terminal.html][Claude Code in a pane]].

** Project layout

*Reopen a project with its saved layout* decides what you get when you open a
project with =--project=: its saved panes and splits, or the default file
tree + readme + terminal layout. Off is the default. The layout is saved
either way -- this only controls whether it is applied -- and it has no
effect on a bare =mep=, which never restores a layout at all. See
[[file:sessions.html][Sessions]].

** Appearance

The colour scheme, the interface font size, line numbers, cursor line, soft
wrap and text width.

*Colour scheme* is the dropdown row described above: it re-tints the whole
interface as you move through the 63 palettes, so you are choosing by looking
rather than by name. =:colorscheme= alone lasts the session; set here it is
remembered.

*Interface font size* is the global zoom =Ctrl+Shift+== / =Ctrl+Shift+-= also
changes -- the size everything else is measured in. It was already remembered
between runs; this is the row that shows you what it is.

** Completion

*GitHub Copilot suggestions* is off by default and needs =:CopilotLogin= once
before it can do anything. Equivalent to =:Copilot on= / =:Copilot off=, but
remembered. See [[file:copilot.html][Copilot]].
