* Run this file's tests

=gt= (=:MepLangTest=) works out how to test the file you are looking at and
runs it in this tab's terminal.

It saves the buffer first when it is modified -- a test run against a stale
copy on disk is worse than useless -- and reports the command it chose on
the status line (and in the Notifications history), which is the only
feedback when the terminal is off screen.

| Filetype        | Runs                             |
|-----------------+----------------------------------|
| =.go=           | Go's test runner                 |
| =.py=           | the configured Python test runner |
| =.r=, =.R=      | R's test tooling                 |
| =.c=, =.cpp=, headers | the project's build-directory test target |
| =.rs=           | Cargo's test runner              |

#+begin_src lua
mep.opt.lang_test_python = {'pytest', '-q'}
mep.opt.lang_test_build_dirs = {'build', 'build/native'}
#+end_src

If mep cannot work out a runner for the filetype, it says so in one line
rather than guessing.

* The Tests panel

=<leader>tT= (=:MepActivityTestPanel=) opens the test sidebar. In a CMake
project it lists every test ctest knows about, one row each, with a mark
for where it stands:

| Mark | Means                                       |
|------+---------------------------------------------|
| ○    | not run yet                                 |
| …    | queued in the current run                   |
| ●    | running now                                 |
| ✓    | passed (with how long it took)              |
| ✗    | failed, timed out, or its build failed      |

Press Enter on a test to build its CMake target and run just that test.
Enter on the summary row at the top (the build directory and the
pass/fail/not-run counts) runs them all. The marks update live as ctest
reports each test.

| Key   | Does                                                     |
|-------+----------------------------------------------------------|
| Enter | build and run the test under the cursor (summary: all)   |
| =a=   | run every test                                           |
| =f=   | re-run only the tests that failed                        |
| =o=   | show the output of the test under the cursor             |
| =x=   | stop the run                                             |
| =R=   | reload the test list (after adding a test and re-configuring) |

=o= on a failed test shows what it printed. For a test whose build failed, it
shows the build log, compiler error included. On the summary row it shows the
whole last run. The popout (=mod1+m=) shows the same output beside the list
as you move through it.

The build directory is the first entry of =mep.opt.lang_test_build_dirs=
that holds a configured ctest tree. Set =mep.activity_test_build_dir= to pick
one yourself, and =mep.opt.activity_test_jobs= to run tests in parallel:

#+begin_src lua
mep.activity_test_build_dir = 'build/native-dev'
mep.opt.activity_test_jobs = 8
#+end_src

Tests come from ordinary CMake: =enable_testing()= and one =add_test()=
per test. Before running a test, mep builds the target its executable comes
from. For a target nobody has built yet, it builds the target named after the
test. mep's own windowless test binaries are registered this way, so
=ctest --test-dir build/native= runs the same suite.

Outside a CMake project, =:MepActivityTestRun= runs the whole suite once
(=mep.activity_test_cmd=, or =npm test= when there is a =package.json=)
and lists its failure lines; =mep.activity_test_failure_lines()= exposes
them to Lua.
