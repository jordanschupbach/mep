Colorschemes

Changing it

<leader>ut opens the theme picker, which previews live: every change of the highlighted row re-tints the whole interface immediately, before you commit. Enter keeps the theme; Esc restores the one you started with. Browsing sixty-two themes is therefore just holding a cursor key.

:colorscheme everforest-dark
:colo nord

From Lua:

lua Copy
mep.colorscheme('kanagawa')          -- set it
print(mep.current_theme())           -- what is active
for _, n in ipairs(mep.theme_names()) do print(n) end

To make it stick, put the mep.colorscheme call in init.lua.

A theme is eleven colours

Each one defines a name and eleven colours:

ColourUsed for
bgthe canvas
fgordinary text
rederrors, deletions
greenstrings, additions
yellowwarnings, changes
bluefunctions, links
purplekeywords
cyannumbers, constants, types
orangetypes, parameters
borderpane and panel edges
accentthe active element

Every other colour in the interface -- the status line, sidebars, the picker, the cursor line, tab labels, float borders, about forty groups in all -- is derived from those eleven, by mixing and tinting. That is why adding a theme means writing eleven colours rather than a stylesheet, and why a new UI element picks up sensible colours in all sixty-two themes without anyone revisiting them.

Light and dark

mep does not track a light/dark flag. Where it needs to know -- picking which mep logo to draw on the start screen, for instance -- it computes the perceptual luminance of the resolved background and decides from that.

So a custom theme gets the right treatment automatically, with no flag to set and nothing to keep in sync.

Rendered documents

The HTML, PDF and image viewers re-tint what they show to the active theme by default, rather than rendering a white page inside a dark editor. The pane header shows [theme, Ctrl-R] when it is doing this; Ctrl-R toggles back to the document's own colours, and the header then reads [page colors, Ctrl-R] or [original, Ctrl-R].
