* Changing it

=<leader>ut= opens the theme picker, which *previews live*: every change of
the highlighted row re-tints the whole interface immediately, before you
commit. =Enter= keeps the theme; =Esc= restores the one you started with.
Browsing sixty-two themes is therefore just holding a cursor key.

#+begin_example
:colorscheme everforest-dark
:colo nord
#+end_example

From Lua:

#+begin_src lua
mep.colorscheme('kanagawa')          -- set it
print(mep.current_theme())           -- what is active
for _, n in ipairs(mep.theme_names()) do print(n) end
#+end_src

To make it stick, put the =mep.colorscheme= call in =init.lua=.

* A theme is eleven colours

Each one defines a name and eleven colours:

| Colour   | Used for                                  |
|----------+-------------------------------------------|
| =bg=     | the canvas                                |
| =fg=     | ordinary text                             |
| =red=    | errors, deletions                         |
| =green=  | strings, additions                        |
| =yellow= | warnings, changes                         |
| =blue=   | functions, links                          |
| =purple= | keywords                                  |
| =cyan=   | numbers, constants, types                 |
| =orange= | types, parameters                         |
| =border= | pane and panel edges                      |
| =accent= | the active element                        |

Every other colour in the interface -- the status line, sidebars, the
picker, the cursor line, tab labels, float borders, about forty groups in
all -- is *derived* from those eleven, by mixing and tinting. That is why
adding a theme means writing eleven colours rather than a stylesheet, and
why a new UI element picks up sensible colours in all sixty-two themes
without anyone revisiting them.

* Dim text keeps a contrast floor

The muted text groups -- =Comment=, =LineNr=, =MutedFg=, =Debug= -- are *not*
=border=. They fade =fg= toward =bg=, but stop fading as soon as they reach a
3:1 contrast ratio against the resolved background, so a palette with a
low-contrast =fg= gets a less-faded comment rather than an unreadable one.

That floor is also what keeps glyph antialiasing intact. Text is drawn as
coverage blended between the background and the text colour, so every
antialiased edge pixel lands on a ramp whose length *is* the distance
between those two colours. Dim text to within a handful of levels of the
background and the ramp has nowhere to land: the edges stair-step and the
text looks pixelated, as though rendered at a lower resolution, rather than
simply faint. =border= sits that close to =bg= in most palettes -- which is
right for a pane edge and wrong for a comment.

So a custom theme picks =border= purely for its edges. Comment colour
follows from =fg= and =bg=, and stays legible without being tuned.

* Light and dark

mep does not track a light/dark flag. Where it needs to know -- picking
which mep logo to draw on the start screen, for instance -- it computes the
perceptual luminance of the resolved background and decides from that.

So a custom theme gets the right treatment automatically, with no flag to
set and nothing to keep in sync.

* Rendered documents

The HTML, PDF and image viewers re-tint what they show to the active theme
by default, rather than rendering a white page inside a dark editor. The
pane header shows =[theme, Ctrl-R]= when it is doing this; =Ctrl-R= toggles
back to the document's own colours, and the header then reads
=[page colors, Ctrl-R]= or =[original, Ctrl-R]=.
