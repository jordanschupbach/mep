Measuring the engine

Twelve self-checking sites

"How much of a browser is it?" is a question mep answers with a test rather than a claim. examples/web/ is a ladder of twelve self-checking JavaScript sites, from a static page up to a bundled React application -- all of which pass in real Chromium, so the ladder measures mep against a real browser rather than against itself.

CommandDoes
:WebLadderserve the ladder and open it
:WebLadderRunscore every level

Headlessly:

build/native/mep-web-ladder-test
build/native/mep-web-ladder-test --strict
build/native/mep-web-ladder-test --eval file.js

The levels

Static page, DOM, events, timers, external resources, language features, fetch, a todo app, a router, ES modules, React via UMD, and a bundled React application.

All twelve currently pass, which is why --strict works as a regression gate: it fails the build if any level stops passing.

Reading a failure

A failing level names the browser feature it needed. That is the point of the ladder -- it turns "the page does not work" into a specific missing capability, which is a thing you can go and implement.

--eval file.js runs one script and reports what the engine makes of it, which is the quickest way to check whether a particular construct is supported.
