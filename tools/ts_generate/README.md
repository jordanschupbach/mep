# tools/ts_generate

mep's replacement for the tree-sitter CLI's two dev-time jobs, so changing
one of mep's grammars (`grammars/tree-sitter-<name>`) needs neither the
tree-sitter CLI nor Node (`plans/TREESITTER_GRAMMAR_PLAN.md` Phase 9).

| Program | Replaces | Built from |
| --- | --- | --- |
| `mep-ts-generate` | `tree-sitter generate` 0.25.10 | everything here except `corpus_test.cpp`, plus mep's JS engine (`src/js_engine.cpp` and what it links) |
| `mep-ts-corpus-test` | `tree-sitter test` | `corpus_test.cpp`, linked against the compiled-in grammars (`ts_<name>`) |

```sh
just <name>-grammar          # regenerate grammars/tree-sitter-<name>/src and run its corpus
just grammar-generate <name> # the same
just grammar-generate-check  # regenerate every grammar to a scratch dir; fail unless byte-identical
```

## mep-ts-generate

```
mep-ts-generate [--abi N] [--out DIR] [--json FILE] GRAMMAR_DIR
```

Writes `src/grammar.json`, `src/parser.c`, `src/node-types.json` and
`src/tree_sitter/{alloc,array,parser}.h`, exactly what tree-sitter 0.25.10
writes. The contract is **byte-identical output**: `just
grammar-generate-check` holds it on all 12 grammars. A difference there is
a bug here, not a change to accept. Each grammar's `parser.c` header still
says `@generated by tree-sitter v0.25.10`, because the output is identical.

1. **grammar.js -> grammar.json** (`grammar_js.cpp`, `dsl.js`). The CLI
   runs `grammar.js` on Node with its `dsl.js`. Here it runs on mep's JS
   engine with an in-house `dsl.js` that builds the same object, key for
   key. `require()` takes literal relative paths (`./common.js`,
   `../tree-sitter-c/grammar.js`, `.json` files), which is all the grammars
   use. `--json FILE` skips this step and reads that grammar.json instead.
2. **grammar.json -> tables -> C**: a port of the CLI's
   `cli/generate/src` (Rust), one file per module: `parse_grammar.cpp`,
   `prepare_grammar.cpp`, `node_types.cpp`, `build_tables.cpp` +
   `build_lex_table.cpp` + `build_parse_table.cpp`, `render.cpp`. The port
   keeps the incidental behaviour that decides the output's bytes:
   - `core.h`: Rust's derived orderings.
   - `rust_sort.h`: Rust's unstable sort, whose order for equal elements
     numbers the parse states.
   - `regex.cpp`: regex-syntax 0.8.5's IR for patterns.
   - `unicode_tables.h`: its Unicode 16 tables, generated by
     `gen_unicode_tables.py`.
   - `json.cpp`: serde_json's pretty printer.
3. The `tree_sitter/*.h` headers are `templates/`, copied verbatim.
   CMake embeds them and `dsl.js` into `ts_generate_embedded.h`.

The ABI is 15 by default. It needs the grammar's version from the nearest
`tree-sitter.json`, as the CLI does, and falls back to ABI 14 without one.

### JavaScript limits

`grammar.js` runs on mep's engine, not V8. Every grammar runs on it
unchanged except one: Org's `caseInsensitive` ran a `/\p{L}/u` regex
inside `grammar.js`. mep's regex engine is ASCII-only, so that now throws
instead of silently matching nothing; Org's keywords are ASCII and use
`[a-zA-Z]`. A `\p{...}` regex used only as a token pattern is fine: the
DSL reads its `.source`, and the generator's own `regex.cpp` handles
Unicode classes. When a new grammar needs something the engine lacks,
evaluation stops with the script's error message.

### Moving to a newer tree-sitter

The port follows 0.25.10. To follow a newer CLI:

1. Port its `cli/generate` changes.
2. Regenerate every grammar with the real CLI.
3. Get `just grammar-generate-check` byte-identical again before
   committing.

## mep-ts-corpus-test

```
mep-ts-corpus-test [NAME...]
```

Runs `grammars/tree-sitter-<name>/test/corpus/*.txt` for the named
grammars, or all of them, the way `tree-sitter test` does:

- A case is a `===` header, its input, a dashed divider (the longest dash
  line, so inputs may contain shorter ones), then the expected
  S-expression.
- Whitespace is collapsed.
- Field names are dropped from the actual tree when the expected one has
  none.

It tests the grammar compiled into mep. `just <name>-grammar` rebuilds
that after regenerating, so it always tests the new `src/`. It is part of
`just test`.
